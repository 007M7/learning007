## 九月的模型为什么像换了一个人

续费模型在八月测试中表现不错。九月，产品团队把到期提醒从账户首页移到新的会员中心，同时把银行卡更新入口提前到了合同到期前二十一天。活跃用户更容易找到新入口，支付失败的用户也比以前更早修复问题。

数据团队最初只检查模型输入。登录次数、套餐类型、付款状态和客服记录仍然存在，字段类型也没有改变。他们于是怀疑九月用户更难预测，准备增加模型复杂度。

运营同事却发现了另一件事。以前每天上午九点的一万多份合同几乎都还没有接受过续费提醒。新流程里，一部分用户在模型作答以前已经收到提醒并更新了银行卡。模型仍然把“付款状态正常”当作用户原有特征，实际读到的却混入了新流程提前产生的结果。

问题发生在整段流程。模型面对的对象已经被产品流程重新安排。想知道数据为什么变化，除了比较训练表里的均值，还要追问一行记录来到表格以前经历了什么。

## 跟着合同 1042 再走一次产品流程

合同 1042 不会天然出现在续费训练表中。它先要属于当前产品，再满足模型任务定义，随后经过一连串系统与人的处理。

```text
用户购买产品
      │
      ▼
形成一份有效合同
      │  仍在服务地区内，套餐允许自动续费
      ▼
进入到期前十四天候选池
      │  账户没有关闭，数据同步按时完成
      ▼
上午九点获得风险分数
      │  是否进入两千个人工名额
      ▼
收到提醒、人工检查或不处理
      │
      ▼
到期后七天确认续费结果
      │  付款系统与合同系统成功对账
      ▼
成为训练表中的一行
```

每个箭头都在选择数据。

没有进入服务地区的人不会形成这类合同。提前关闭账户的合同不会进入候选池。数据同步失败的合同可能错过当天评分。风险较高的合同更容易进入人工名单，随后也更容易获得支付提醒。付款完成但对账失败的合同，在标签成熟日仍可能被记成未续费。

因此，训练表只保留了产品流程筛选后的结果。流水线允许谁进入，给谁安排了额外处理，又能为谁确认结果，共同决定我们最终看见什么。

专业上把这整套机制称作数据生成过程。这里的“生成”并不意味着凭空制造数据，它强调观测记录由现实规律、产品规则、人工行动、采集系统和时间共同形成。

## 先说清模型准备服务哪个总体

团队希望模型以后服务的对象集合叫作目标总体。当前任务把它限定为每天上午九点真正可能进入续费工作流的有效合同。所有注册用户与历史数据库里的全部合同都超出了这个范围。

这个范围需要写得足够具体。

| 边界 | 当前任务的约定 | 可能被遗漏的对象 |
|---|---|---|
| 产品 | 支持自动续费的订阅产品 | 线下合同与一次性购买 |
| 地区 | 已接入统一支付系统的地区 | 仍使用本地支付渠道的地区 |
| 时间 | 到期前十四天的上午九点 | 临时延期或人工改期合同 |
| 状态 | 当时有效且账户可联系 | 已关闭账户、通知被拒收的用户 |
| 结果可见性 | 到期后七天能完成付款对账 | 跨系统付款或延迟入账合同 |

训练数据覆盖的是历史流程下能够走完整条链的那部分对象。目标总体是系统准备在未来处理的对象。两者大幅重合时，历史实验才有外推的起点；新增地区、新支付渠道或新的准入规则都会改变重合范围。

“样本很多”不能替代这项检查。数据库可以有数百万行，若它们都来自容易触达、容易对账的老用户，模型面对新渠道时仍然缺少经验。判断代表性需要比较样本怎样进入与未来对象怎样出现，单看数量得不出答案。

## 一次曝光会改变后面所有统计

假设产品首页有一张续费提醒卡。用户必须先登录，再进入首页，卡片成功加载以后才有机会点击。数据库里没有点击的人至少分成三类。

- 看见卡片但没有点击。
- 登录了，卡片却没有成功加载。
- 从未进入能够展示卡片的页面。

三类记录都可能写成 `clicked = 0`，含义却完全不同。第一类表达一次可观察的选择，后两类没有获得同样的选择机会。

获得看见某个页面、商品或动作的机会，称作曝光。推荐、广告、搜索和人工审核任务尤其依赖曝光记录。只在发生点击或购买以后留日志，模型会把“从未看见”误解成“看见后拒绝”。

续费任务也有类似问题。人工只检查高风险名单，便只有这些合同留下完整的支付失败原因和沟通结果。低风险合同即使存在同类问题，也可能直到最终失败才被系统发现。某个字段与未续费高度相关，可能是风险规律，也可能只是它决定了谁会接受更仔细的检查。

画数据过程时，凡是某个对象必须先通过一道门才会产生后续记录，都要把这道门单独画出来，并留下通过与未通过的数量。只保存门后的数据，团队将来很难区分行为差异和机会差异。

## 结果没有出现，不一定等于结果为零

合同到期后七天仍然没有付款，当前任务把它标为未续费。这个标签成立有一个隐含条件，团队能够持续观察合同直到窗口结束。

如果用户在到期前把账户迁移到另一个系统，原平台再也看不到后续付款。此时观察提前中断，团队无法确认结果。统计上常把这种情况称作截尾。窗口尚未走完，或者对象离开可观察范围，都不能直接当成一个普通的负例。

截尾还可能有方向。频繁投诉的用户更容易关闭账户，企业客户更可能通过线下转账完成续费。若这些对象也更容易失去后续记录，删掉它们会让剩余数据显得更稳定；把它们全部记为未续费，又会把数据系统的不可见性混进业务结果。

团队需要为每种结果保留至少三种状态。

| 状态 | 记录含义 | 能否直接进入二分类训练 |
|---|---|---|
| 已确认续费 | 观察窗内出现可核对的成功付款 | 可以 |
| 已确认未续费 | 观察窗完整结束且没有成功付款 | 可以 |
| 结果不可确认 | 观察提前中断、跨系统迁移或对账未完成 | 不能直接当作负例 |

第六章会专门处理标签与缺失。此处先抓住生成过程中的位置。结果可见性同样是一道选择门，它决定哪些对象最终拥有可用于监督学习的标签。

## 模型上线以后会参与制造下一批数据

最初几个月，模型从历史数据学习谁容易未续费。上线以后，高风险合同更容易进入人工名单，也更容易收到提醒、优惠和支付修复。模型的预测由此改变了结果。

下一次训练时，团队看到高风险合同的续费率上升，可能得出“这些特征已经不危险”的结论。可这批合同表现改善，恰好因为旧模型把它们选了出来。数据没有记录入选、人工决定和实际动作，新模型就会把系统干预后的结果当成自然规律。

这种从模型输出返回未来训练数据的路径叫作反馈回路。

```text
历史合同与结果
      │
      ▼
训练风险模型
      │
      ▼
决定谁接受人工检查
      │
      ▼
改变部分合同的续费结果
      │
      └────────── 进入下一轮训练数据
```

反馈并不一定有害。模型本来就是为了改变结果。危险在于团队忘记变化来自系统行动，继续把新数据当作无人干预的观察样本。

最基本的修复是把预测、入选规则、人工决定、实际动作和结果一起记录。若要回答某个动作究竟带来多少增益，还需要随机实验或因果方法。当前风险模型至少要知道一条标签是在怎样的政策下产生，不能把政策隐藏在表外。

## 用一张图固定数据从哪里来

现在可以为续费任务建立数据生成过程图。它不需要还原公司所有系统，只要覆盖会改变样本进入、信息出现和标签确认的关键环节。

| 环节 | 进入条件 | 产生的记录 | 可能改变它的机制 | 必须保留的计数 |
|---|---|---|---|---|
| 合同形成 | 购买支持续费的产品 | 合同、套餐、地区 | 产品与准入政策 | 各渠道合同数与拒绝数 |
| 候选池 | 到期前十四天且仍有效 | 当日候选合同 | 关闭账户、改期、同步故障 | 应进入与实际进入数量 |
| 特征快照 | 九点前数据已经可用 | 登录、付款、客服特征 | 延迟、补录、版本变化 | 字段缺失率与延迟分布 |
| 名单分配 | 风险排序与人工容量 | 入选、未入选 | 阈值、硬规则、人员排班 | 每种规则覆盖人数 |
| 后续行动 | 人工查看后作出决定 | 提醒、优惠、升级服务 | 人工判断与用户响应 | 动作率、拒绝率与成本 |
| 结果确认 | 观察窗结束且完成对账 | 续费、未续费、不可确认 | 迁移、退款、延迟付款 | 三类结果的数量与比例 |

这张图有三个用法。

第一次建模时，它告诉团队训练表需要哪些日志。模型异常时，它提供调查顺序，先看准入与曝光，再看记录和标签。产品或政策变更时，它帮助判断变化落在哪个环节，哪些历史比较不再公平。

九月案例中的改版同时改变了曝光与行动时点。历史测试模拟的是“模型作答前多数合同尚未收到提醒”的流程，新流程却让一部分合同提前接受处理。即使输入列名完全相同，数据的条件含义也已经变化。这类训练环境与目标环境的差异属于数据集偏移。发现偏移以后，不能只问哪列均值变了，还要问生成它的机制是否换了。

## 把生成过程变成项目门禁

一张图只有进入变更流程才有价值。团队可以给每个关键环节指定负责人和触发条件。

- 产品调整准入、页面曝光或提醒时点时，必须标记影响的数据环节。
- 数据管道变更同步频率、字段来源或对账规则时，重新核对可用时间与结果可见性。
- 运营修改名单容量、阈值或人工动作时，保存新政策版本并检查反馈回路。
- 新地区、新渠道或新用户群进入目标总体时，先报告覆盖与缺口，再决定是否沿用旧模型。

团队无需为每次变化都重新训练，但必须先判断历史实验是否仍代表当前流程。若变化只影响页面样式，生成路径不变，可以继续观察。若它提前产生了付款状态或改变谁能留下标签，原实验的适用边界已经移动。

你可以拿自己的项目做一次短练习。任选训练表中的一行，从对象进入产品开始，画到标签确认结束。每一步都写下谁能进入、谁会被挡住、系统留下什么、模型或人工是否会改变后续结果。若某个关键箭头只能回答“数据库里就是这样”，那里就是下一次数据调查的起点。
