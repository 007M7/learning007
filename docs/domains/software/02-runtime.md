## 本章可观察目标

你能根据读写模式选择基本数据结构；能解释进程、内存、文件和线程的关系；能识别阻塞、竞态、死锁和重复执行，并给 AI 明确的并发约束。

## SW04 · 数据结构与复杂度

数据结构不是面试谜题，而是“我们经常做什么操作”的选择。

| 需求 | 常见结构 | 关键代价 |
|---|---|---|
| 按顺序遍历 | 数组/列表 | 中间插入与删除可能搬移元素 |
| 按键快速定位 | 哈希表/Map | 额外内存；无天然顺序 |
| 先来先处理 | 队列 | 需要明确重试与积压 |
| 最高优先级先处理 | 堆/优先队列 | 更新优先级更复杂 |
| 表达层级 | 树 | 遍历、深度和一致性 |

复杂度描述输入规模增长时成本怎样增长。`O(n)` 不是一定慢，`O(1)` 也不是免费；先看真实数据量、I/O 和常数。分页不要先把全部记录读进内存再切片。缓存也不是“加速开关”，它引入过期、失效和一致性问题。

## SW05 · 进程、内存与文件

进程是正在运行的程序实例，拥有虚拟地址空间和操作系统资源。线程共享进程内存，因此通信方便，也更容易产生竞态。文件描述符、端口、环境变量和工作目录都是运行时事实；“本机能跑”经常只是这些事实恰好不同。

```text
程序文件 ─启动→ 进程
              ├─ 虚拟内存：代码 / 堆 / 栈
              ├─ 线程：共享堆，各有调用栈
              ├─ 文件与网络句柄
              └─ 环境变量、用户、权限、工作目录
```

内存泄漏意味着对象不再有用却仍被引用；内存溢出是最终结果之一。文件写成功也不必然代表数据已经安全落盘。作为应用开发者，先掌握生命周期、资源上限和关闭清理，不必现在深入 CPU 指令集。

## SW06 · 并发、异步与任务队列

并发是多个任务在时间上交叠；并行是它们真的同时执行。`async` 适合等待网络/磁盘时让出执行权，不会自动加速 CPU 密集计算。

竞态来自“结果依赖不可控的执行顺序”。例如两个请求都读到库存 1，再各自扣 1。修复必须把不变量放在真正能原子保证的位置：数据库条件更新、唯一约束、事务或锁，而不是只在应用里先查一次。

任务队列默认应按“至少一次”思考：消息可能重复投递，消费者必须幂等；失败要区分可重试与永久失败；重试要有上限、退避和死信去向。

## 练习：找出并发不变量

为“每个用户每天只能领取一次优惠券”写出：业务不变量、数据库唯一约束、重复请求的稳定返回、并发测试，以及 worker 崩溃后重试的行为。

常见误区：认为单线程就没有竞态（多进程/多实例仍存在）；把内存变量当跨实例锁；无限重试；队列确认早于业务提交；用缓存作为唯一事实来源。
