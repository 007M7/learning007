# 05 · 工作流、Agent Runtime 与记忆

<div class="lesson-meta"><span>AI12—AI14</span><span>必修核心</span><span>预计 3 × 60 分钟</span><span>前置：AI09—AI11、SW13</span></div>

## 本章可观察目标

你能选择确定工作流而非滥用 Agent；设计 Task/Run/Step/Artifact 持久模型；让运行可暂停、取消、恢复，并区分会话状态、业务记忆与检索知识。

## AI12 · 工作流还是 Agent

如果步骤与分支可预先列出，用普通工作流/状态机：更可预测、更便宜、更易测试。只有当环境开放、下一步依赖新观察、工具很多且路径无法穷举时，才让模型在受限集合中决策。

```text
确定工作流：A → 条件 B/C → D
Agent 循环：观察 → 提议动作 → 策略/授权 → 执行 → 更新状态 → 终止？
```

即使使用 Agent，外围仍应确定：最大步数、预算、截止时间、允许工具、确认点、终止条件和输出合同。

## AI13 · Runtime 是持久状态机

推荐实体：Task 表达用户意图；Run 是一次执行；Step 是模型/工具/人工步骤；Artifact 是文件或结果；Event 是不可变审计事件。每步先持久化意图/状态，再执行副作用，并记录关联 ID。

暂停不是让进程睡眠：保存检查点和等待原因，释放资源；收到人工输入后用版本/租约防止两个 worker 同时恢复。取消是意图传播：短步骤间检查，长工具若支持则传取消信号；已发生副作用用补偿，不伪装成“从未执行”。

终止条件至少包括：任务完成、明确失败、用户取消、最大步骤、Token/金额预算、总截止时间、重复动作检测和等待人工。

## AI14 · 状态、记忆与压缩

| 类型 | 示例 | 保存原则 |
|---|---|---|
| 运行状态 | 当前 step、工具结果、预算 | 精确、版本化、可恢复 |
| 会话上下文 | 最近消息、未决问题 | 可压缩，但保留来源 |
| 用户偏好 | 语言、输出格式 | 明确同意、可查看删除 |
| 业务事实 | 订单、权限、余额 | 回到权威系统读取 |
| 知识库 | 文档切块 | 版本、ACL、时效与引用 |

“长期记忆”不是把所有对话塞入向量库。写入前先判断目的、合法性、敏感性、保留期、纠正与删除方式。摘要可能丢细节，高风险决策要重读原始记录。

## 练习：可恢复的审批 Agent

实现 `queued → planning → awaiting_approval → executing → succeeded/failed/cancelled`。模拟在工具完成后、状态写入前崩溃；证明恢复不会重复发消息。再模拟审批到达两次和两个 worker 抢同一 Run。

常见误区：Agent 只有 while loop；状态只在内存；工具副作用与 step 状态无幂等关系；摘要覆盖原始审计；记忆没有删除；没有最大步骤和预算。

## 本章完成标准

能解释为何当前功能需要/不需要 Agent；运行中任意杀进程后可从数据库恢复；暂停不占 worker；重复事件不产生重复副作用；所有终止原因可查询。
