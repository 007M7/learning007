# AI 应用与 Agent · 三阶段学习路线

> 学习顺序不是从“最热门能力”排到“最复杂能力”，而是从最小可验证接口，逐步增加外部知识、真实副作用和长时自治。后一阶段必须继承前一阶段的产物。

## 路线总图

```mermaid
flowchart LR
  A1[01 模型行为剖面] --> A2[02 调用与上下文合同]
  A2 --> R1[阶段一迁移]
  R1 --> B1[03 证据链与 RAG]
  B1 --> B2[04 工具与执行边界]
  B2 --> R2[阶段二迁移]
  R2 --> C1[05 可恢复 Runtime 与记忆]
  C1 --> C2[06 Trace、评测与生产指标]
  C2 --> C3[07 安全验证与治理]
  C3 --> R3[阶段三迁移]
  R3 --> S[核心学习总结]
```

路线中间没有“看完即可解锁”。进入下一阶段需要一份真实产物、一条失败证据和一次不看正文的复述。Quiz 只检查局部理解，不代表掌握。

图中的正文节点沿同一条 `调用 → 证据 → 行动 → 运行 → 发布` 控制链累积；`R1/R2/R3` 是换业务对象的迁移门，不是把陌生案例改成新的主项目。迁移通过后，只把密封任务、预期和失败收据加入平行回归。尤其是第一阶段的供应商准入样本，它负责证明合同方法能离开年假问题，不能替换后续正文的身份、版本或指标口径。

## 开始前准备一个很小的场景

选择一个你能判断对错、权限可控、不会伤害真实用户的任务。推荐 10～30 份版本化文档、10～30 个代表问题，以及一个可撤销的草稿工具。不要一开始接邮件群发、付款、生产部署或管理员数据库。

准备下面四项即可开始：

- 能发送 HTTP 请求或使用一个模型 SDK；
- 能读写 JSON，并为字段写简单断言；
- 能保存每次输入、版本、输出和错误；
- 能把测试外部系统重置到已知状态。

如果这些准备本身很困难，先完成软件学习中的 API、状态机、权限和测试内容。AI 路线不会绕过软件工程边界。

## 用同一把尺子核算学习成本

本路线只用 45 分钟标准回合，不混用“几次”“半天”和模糊小时范围。66 回合等于 49.5 小时，分配如下；每章标注的回合已经包含本章局部环境调整、运行与报告。

| 阶段 | 正文章节 | 阶段迁移 | 环境与延时复测 | 合计 |
|---|---:|---:|---:|---:|
| 一 | 13 | 8 | 首次环境 2 ＋ 延时复测 1 | 24 |
| 二 | 12 | 7 | 延时复测 1 | 20 |
| 三 | 14 | 7 | 延时复测 1 | 22 |
| **全路线** | **39** | **22** | **5** | **66 回合 / 49.5 小时** |

延时复测安排在阶段完成至少 7 天后，必须换输入并在不看正文的情况下重建关键判断。它不是阶段总结里的即时重放，因此单独计费且不重复计入迁移回合。

## 阶段一 · 从模型行为到可靠调用

**学习范围：** [01 · 模型行为](/domains/ai/01-models) → [02 · 调用与上下文合同](/domains/ai/02-context) → [阶段一总结](/domains/ai/stage-1-review)

第一章不急着解释全部 Transformer 数学。它用同一批输入重复调用，观察采样、上下文位置、服务版本和结束原因怎样改变结果，并把失败分成可定位的类别。第二章把这些观察写入一个真正的调用合同：输入信任、消息结构、上下文预算、输出 Schema、语义验证、错误处理和回归样本。

阶段一固定投入 24 个标准回合：两章 13 回合、迁移 8 回合、首次环境搭建 2 回合、延时复测 1 回合。

| 必须留下 | 最小验收 |
|---|---|
| 任务卡和 30 条代表输入 | 典型、边界、对抗输入都有存在理由 |
| 三次重复的行为剖面 | 能区分结构错、语义错、证据错和服务失败 |
| 版本化调用合同 | 模型、Prompt、参数、输入来源和失败状态可定位 |
| Schema 与语义验证器 | 形状正确但值错误的反例会被拒绝 |
| 回归集 | 改模型或 Prompt 后能逐样本比较，不只看平均 |

阶段总结中的供应商准入任务单独保存 `scenario_id`、数据来源、规则版本和预期状态。它与正文回归同时运行，但分别报告分母；供应商结果不能被并入员工制度通过率，也不能因为迁移样本表现好就宣布主线已经解决外部知识或行动权限。

**晋级判断：** 你能在陌生场景写出一次调用的输入、输出和失败边界，并说明 temperature=0、结构化输出和更长上下文为什么都不是正确性保证。做不到时，不进入 RAG；先缩小任务和输出。

## 阶段二 · 让答案有证据，让动作有权限

**学习范围：** [03 · RAG 与证据范围](/domains/ai/03-rag) → [04 · Tool Calling、权限与 MCP](/domains/ai/04-tools-mcp) → [阶段二总结](/domains/ai/stage-2-review)

第三章让原文经过版本、解析、切块、ACL、召回和重排成为可引用证据，并分别测量 Recall@k、排序、引用支持和拒答。第四章只接窄工具，把身份、资源、业务状态、批准、幂等和最终结果留在确定程序中。MCP 用于互操作，不替系统承担业务授权。

阶段二固定投入 20 个标准回合：两章 12 回合、迁移 7 回合、延时复测 1 回合。若没有写需求，先保留只读 RAG；若证据链仍不稳定，不要让它获得副作用。

| 必须留下 | 最小验收 |
|---|---|
| Corpus manifest | 原文、版本、生效范围、ACL、解析与索引可重建 |
| Golden evidence set | 每个问题保存必要证据，而非只存参考答案 |
| 检索/回答分层报告 | 找不到、排错、答错和产品展示错误能够分开 |
| 一读一写工具合同 | 输入/输出、错误、副作用和权限边界明确 |
| 绑定批准与幂等测试 | 参数改变后旧批准失效，超时恢复只产生一次写入 |

**晋级判断：** 换到采购、报销或工单场景，你能证明不可信文档不能改变控制流，跨权限内容不会进入上下文，写工具在执行点重新裁决，未知结果不会被误报为失败。关键边界缺一项，就把能力降为草稿或只读。

## 阶段三 · 让长任务可恢复，让系统可停止

**学习范围：** [05 · Agent Runtime 与记忆](/domains/ai/05-agent-runtime) → [06 · Trace、评测与生产指标](/domains/ai/06-evals-safety) → [07 · 安全验证、治理与事故响应](/domains/ai/07-safety-governance) → [阶段三总结](/domains/ai/stage-3-review)

第五章把任务变成显式状态机。Run、Step、Checkpoint、Event 和 Artifact 承载等待与恢复；lease/fencing 处理并发接管；取消与补偿面对不可逆副作用；记忆按来源、范围、权限、有效期和删除治理。第六章从系统主张建立 Trace、分层评测与 Judge 校准，并用每成功任务成本、shadow/canary 和独立回滚审理候选版本。第七章再沿资产、入口、能力与最终后果做安全验证，把红线连接到具名 owner、kill switch、事故响应和用户纠正。

阶段三固定投入 22 个标准回合：三章 14 回合、迁移 7 回合、延时复测 1 回合；其中第六章 5 回合、第七章 3 回合，原有 8 回合只是按评测与治理的知识依赖重新分开。至少一半回合用于故障注入、逐样本审阅和恢复演练。

| 必须留下 | 最小验收 |
|---|---|
| 状态机与不变量 | 等待、结果未知、取消和终态不会混成一个布尔值 |
| 三类恢复证据 | 崩溃、并发接管和取消后不重复副作用、不复活旧状态 |
| 记忆策略 | 权威事实、任务产物、经验和偏好不会互相冒充 |
| Claim cards 与版本化评测 | 每项发布主张都有对象、分母、环境和阻断条件 |
| 发布与事故演练 | shadow/canary 能停止，模型/索引/工具可独立回滚或关闭 |

**毕业判断：** 选择新场景，完成从状态、记忆、Trace 到发布决定的迁移。一次 no-go 只要证据充分，同样是合格结果。若系统只能展示成功路径、无法从终态回放，或安全红线要靠总分补偿，就还没有完成核心路线。

## 每周三次怎样安排

第一次读机制与案例：先写自己的失败预测，再读正文，用普通话复述核心判断。第二次做最小实现：固定一个变量，运行正常与反例，保存逐样本证据。第三次做迁移和评审：换输入、注入故障，让另一位人或 AI 按明确 rubric 找漏洞。

每阶段结束后安排 7 天后复测。关掉正文，重新画关键链，随机抽一个历史失败解释它属于哪一层，再对新场景写一项退出条件。如果只能认出术语却无法产出判断，退回对应案例而不是继续堆阅读量。

## 卡住时怎样缩小，而不是放弃

- 模型调用不稳定：先将任务缩成分类或抽取，保存十条逐样本结果。
- 文档太多：只用一个制度的两个版本，重点验证生效时间与引用。
- 工具难接：使用可复位的本地假服务，先证明授权与幂等。
- Runtime 太复杂：只做三状态、一个等待点和一个外部写入，再注入崩溃。
- 评测成本太高：缩小样本数，但保留典型、边界、历史失败和安全四类。
- 没有人审阅：先写评分锚点，让 AI 提出问题；最终风险接受仍由真实 owner 决定。

缩小项目规模不会降低学习价值。删除反例、版本、权限或验收才会。

## 完成后的三条去向

完成 [核心学习总结](/domains/ai/summary) 后再选择：

- 模型表示、微调、自托管或高级检索成为真实瓶颈：进入 [AI 进阶](/advanced/ai/)；
- 已有稳定系统，需要追踪规划、记忆、computer use、coding agent、评测与安全的最新研究：进入 [Agent 前沿](/frontier/agents/)；
- 状态、权限、测试、部署和事故响应仍薄弱：回补 [软件与系统工程](/domains/software/) 与 [质量与生产交付](/domains/quality/)。

技术路线由瓶颈选择，不由热度选择。保留当前基线和证据包，任何进阶方案都要在同一任务、预算和安全条件下比较。
