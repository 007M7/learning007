# 01 · 模型、Token、Context 与不确定性

<div class="lesson-meta"><span>AI01—AI02</span><span>必修核心</span><span>预计 2 × 55 分钟</span><span>前置：SW02、SW07</span></div>

## 本章可观察目标

你能用系统而非拟人方式解释模型调用；区分模型知识、输入上下文和外部事实；为延迟、成本、限流、超时和不确定输出设计应用边界。

## AI01 · 最小大模型心智模型

大模型把输入切成 Token，根据上下文预测后续 Token 的概率分布。它生成“统计上合适的序列”，不是在数据库中查唯一答案，也不会因为语气自信就更真实。

```text
消息/文本 → Token 化 → 模型在上下文窗口中推理 → 逐 Token 生成
                  ↑                         ↓
             参数化知识              非确定输出/停止原因
```

必须区分：

- **参数知识**：训练后固化，可能陈旧且无法直接列出处；
- **上下文**：本次请求提供的指令、历史、检索片段和工具结果；
- **外部事实**：数据库、文件、API 中可更新、可授权的数据；
- **应用规则**：价格、权限、状态转换等确定性逻辑，不应交给模型猜。

温度/采样控制输出分布，不是“事实准确度旋钮”。上下文窗口有容量限制；塞得更多可能增加成本、延迟和干扰。Embedding 把内容映射到向量空间，用于相似性，不等于模型“理解事实为真”。

## AI02 · 可靠调用模型 API

模型调用是昂贵、不稳定的外部依赖。应用至少记录供应商/模型标识、Prompt 版本、输入/输出 Token、延迟、停止原因、错误类别和 trace ID；涉及隐私时只记录脱敏或摘要信息。

错误分类决定策略：认证/Schema 错误不重试；限流和短暂 5xx 可在总截止时间内退避重试；内容拒绝进入显式业务分支；超时结果未知时不能假设未执行工具副作用。

流式输出改善首字体验，但未结束前内容可能不完整；结构化 JSON、工具参数或审核结果通常应在完整校验后再落库/执行。成本预算按“单次 × 并发 × 重试 × 上下文增长”估算，而不是只看每百万 Token 单价。

## 练习：调用预算与失败表

为“生成一份带引用的报告”列出：最大输入/输出、单次和每日预算、首字节/总超时、限流并发、可重试错误、最大尝试次数、取消传播、降级结果和必须人工确认的条件。

常见误区：把模型当事实库；上下文越多越好；记录完整敏感 Prompt；重试不设截止时间；流式半截 JSON 直接执行；模型名字升级后不重新评测。
