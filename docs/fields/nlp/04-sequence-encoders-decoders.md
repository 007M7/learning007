# 04 · 序列、编码器与解码器

> 分类、序列标注与生成不是换一个 prompt 就相同；信息能从哪里流向哪里、输出是否需全局一致，决定架构与评价器。

## 先别问谁最好，先问你在优化什么

> 为什么分类、抽取和生成需要不同的信息流约束？

合同实体抽取若用自由生成，可能改写公司名、漏字符或产生不存在实体；token 分类能保留偏移却可能生成非法 IOB 序列。需要对照 BiLSTM-CRF、encoder token classifier 与受约束生成，并在相同标注和延迟下选型。

## 把选择拆成三条判断轴

| 知识节点 | 先用一句话说清 | 什么时候值得选择它 | 先排除的误解 |
|---|---|---|---|
| NLPF10 · 序列结构 | 标签和输出之间存在顺序、边界与依赖 | 需要独立预测还是结构化解码 | decoder LLM 总能替代 encoder |
| NLPF11 · 编码/解码信息流 | 双向理解、因果生成和条件生成使用不同 mask | 模型架构是否匹配输出约束 | CRF 已完全过时 |
| NLPF12 · 高效编码器 | 现代长序列编码器联合改善吞吐、位置与训练配方 | 何时小型专用模型胜过通用生成模型 | 参数大等于长文本利用好 |

读表时不要横向背三行。任选一行，把“定义—决定—反例”连成一句因果解释；然后把本章案例中的一个输入替换掉，检查原判断是否仍成立。

## 判断树：双向编码、因果解码与结构化约束

BiLSTM 汇聚左右上下文，CRF 对整条标签序列归一化并学习转移；BERT 通过 masked LM 获得双向表示；decoder 只能看前缀，适合自回归生成；T5 把任务统一为条件文本生成。ModernBERT 重新设计长上下文 encoder 的位置、注意力和训练配方，说明理解型架构仍有独立价值。

~~~~mermaid
flowchart TD
 X[输入序列] --> E{任务信息流}
 E -->|双向理解| EN[Encoder]
 E -->|前缀生成| DE[Decoder]
 E -->|输入到输出| ED[Encoder-Decoder]
 EN --> C[分类/Span/CRF]
 DE --> G[受约束生成]
 ED --> G
 C --> V[结构与偏移校验]
 G --> V
~~~~

## 不要让一个分数替你做决定

线性链 CRF 的 $p(y|x)=\frac{e^{s(x,y)}}{\sum_{y'}e^{s(x,y')}}$，$s$ 包含发射与标签转移；因果注意力令 $M_{ij}=-\infty$ 当 $j>i$。选择应比较结构合法率、exact/span F1、校准、吞吐与内存，而非只看参数量。

把每个符号放回真实系统。下面任何一项说不清，计算正确也不能保证结论正确：

- 输出是否依赖未来 token
- 标签之间有哪些硬约束
- 生成文本能否无损映射回原文 offset
- 最大长度与批量吞吐是否符合业务

## 做到什么，才算结果可信

| 观察维度 | 要留下的记录 | 它防止你误判什么 |
|---|---|---|
| 任务质量 · 序列结构 | 主指标、分层指标、置信区间和失败类型 | 平均分不能说明关键场景是否可用；本章还要据此判断：需要独立预测还是结构化解码 |
| 系统表现 · 编码/解码信息流 | 端到端时延、成功率、降级/拒绝和人工介入 | 局部模型分数不是用户任务结果；本章还要据此判断：模型架构是否匹配输出约束 |
| 资源经济 · 高效编码器 | 训练/推理/标注成本、吞吐、容量与能耗 | 确认改进在真实预算下仍成立；本章还要据此判断：何时小型专用模型胜过通用生成模型 |
| 风险运维 · 序列结构 | 漂移、越权、事故、恢复时间和残余风险 | 把一次实验转化成可持续服务；本章还要据此判断：需要独立预测还是结构化解码 |

## 不要只看宣传：两份可核验依据

公开结果可以帮助设置基线，却不能替代你自己的数据、预算和失败代价。

### BiLSTM-CRF for Sequence Tagging（2016-08-09）

**它追问什么：**端到端神经表示怎样与标签序列约束结合？

**方法和结果：**双向 LSTM 产生上下文发射分数，CRF 联合解码完整标签序列。 在多项序列标注任务上取得当时强结果，并避免手工特征依赖。

**它改变的判断：**明确区分 token 表示与结构解码两层。

> **不要越过这条边界：**长依赖、预训练和现代硬件效率不是其优势，今天主要作为可解释基线。

### ModernBERT（2024-12-18）

**它追问什么：**encoder-only 模型能否用现代配方在长文本和效率上重新竞争？

**方法和结果：**工作结合长上下文、旋转位置、局部/全局注意力和现代训练数据/工程。 作者在多种检索、分类和代码任务报告质量—速度优势。

**它改变的判断：**提醒 NLP 选型不应默认所有任务都用 decoder LLM。

> **不要越过这条边界：**技术报告结果与特定硬件实现需在目标环境复验。

## 一次有约束的选择：合同实体与关系抽取

同一数据上训练字典+规则、encoder+CRF 和 schema 约束生成。按实体精确边界、嵌套实体、关系方向、非法输出、P95 与人工修订时间评测；法律实体要求保留原文字符偏移和证据句。

### 读案例时做三次停顿

1. 到 序列结构 时停一次：需要独立预测还是结构化解码？
2. 到 编码/解码信息流 时再停一次：哪条数据流、状态变化或约束能证明机制真的发生？
3. 到 高效编码器 时最后停一次：如果出现“把生成流畅误当精确抽取”，系统应继续、拒绝还是交给人？

## 做一次公平对照：同任务三架构对照

### 第 1 步：按实体/模板来源分组切分

- **这一步在验证：**序列结构能否支持“需要独立预测还是结构化解码”这项判断。
- **至少留下：**主指标、分层指标、置信区间和失败类型。
- **先停下来而不是继续调参的信号：**把生成流畅误当精确抽取。

### 第 2 步：实现字典、序列标注和生成三层基线

- **这一步在验证：**编码/解码信息流能否支持“模型架构是否匹配输出约束”这项判断。
- **至少留下：**端到端时延、成功率、降级/拒绝和人工介入。
- **先停下来而不是继续调参的信号：**token 与字符 offset 错位。

### 第 3 步：验证 IOB/schema/offset 并记录无法解析输出

- **这一步在验证：**高效编码器能否支持“何时小型专用模型胜过通用生成模型”这项判断。
- **至少留下：**训练/推理/标注成本、吞吐、容量与能耗。
- **先停下来而不是继续调参的信号：**随机拆分文档模板。

### 第 4 步：对长文、嵌套、否定和跨句关系单独压力测试

- **这一步在验证：**序列结构能否支持“需要独立预测还是结构化解码”这项判断。
- **至少留下：**漂移、越权、事故、恢复时间和残余风险。
- **先停下来而不是继续调参的信号：**忽略非法标签序列。

## 什么信号会推翻当前选择

先排除这些误解：decoder LLM 总能替代 encoder；CRF 已完全过时；参数大等于长文本利用好；结构化输出等于 JSON 可解析；token F1 等于实体可用。

### 把生成流畅误当精确抽取

- **先看什么：**主指标、分层指标、置信区间和失败类型
- **回到哪项控制：**高频稳定抽取优先专用 encoder
- **怎样留下证据：**保存触发条件、原始输入、系统响应和人工处置；修复后把同一样本加入“同任务三架构对照”的回归记录。

### token 与字符 offset 错位

- **先看什么：**端到端时延、成功率、降级/拒绝和人工介入

- **怎样留下证据：**保存触发条件、原始输入、系统响应和人工处置；修复后把同一样本加入“同任务三架构对照”的回归记录。

## 证据改变时怎样重选

### 1. 高频稳定抽取优先专用 encoder

验收时查看 **任务质量**，至少保存主指标、分层指标、置信区间和失败类型。如果观察到“把生成流畅误当精确抽取”，这项决定必须重新评审，不能因为已经实现就默认保留。

### 2. 开放 schema 生成必须有语法约束和校验

验收时查看 **系统表现**，至少保存端到端时延、成功率、降级/拒绝和人工介入。如果观察到“token 与字符 offset 错位”，这项决定必须重新评审，不能因为已经实现就默认保留。

### 3. 保存原文 offset 与规范化值双表示

验收时查看 **资源经济**，至少保存训练/推理/标注成本、吞吐、容量与能耗。如果观察到“随机拆分文档模板”，这项决定必须重新评审，不能因为已经实现就默认保留。

### 4. 架构升级以端到端修订成本决策

验收时查看 **风险运维**，至少保存漂移、越权、事故、恢复时间和残余风险。如果观察到“忽略非法标签序列”，这项决定必须重新评审，不能因为已经实现就默认保留。

## 本章小结

- 信息流约束决定架构
- 结构解码保证全局合法性
- 专用 encoder 仍有质量成本优势
- 端到端可用性包含偏移与校验
