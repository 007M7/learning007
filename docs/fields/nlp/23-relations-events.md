## 为什么现在要学“关系与事件抽取”

你看到的是输出变化，真正需要追的是状态、信息和约束怎样传递。发票抽取返回合法 JSON，却把含税总额当未税金额、把供应商与购买方对调。

**本章核心判断：** 关系和事件把实体连接成带角色、时间和跨句依赖的结构，局部分类不足以保证一致。

本章只追一个判断：**局部实体如何组合成跨句、带角色的结构？** 最后必须用“Schema、约束与图一致性检查”来回答；如果产物不能暴露失败样本，就还不能算学会。

## 沿着一条完整推理链走到底

### 第一步：固定要解释或改变的对象

不要用“整体效果更好”代替对象。把“局部实体如何组合成跨句、带角色的结构？”改写为：在明确输入、时间点和约束下，观察什么量，比较什么基线，最后据此采取什么动作。

### 第二步：写出中间机制

上一主题“实体边界、嵌套与匹配协议”提供前置条件，本章用 **错误本体** 解释关键机制，并把结果留在“Schema、约束与图一致性检查”中。下一主题“约束生成与输出校验器”只在这些证据成立后继续。 只要中间任一环只能凭主观解释，结论就应降级为假设。

### 第三步：主动寻找反例

先尝试制造“训练集缺少完整记录级难例”。如果当前方法仍给出看似正常的平均分，说明评价没有覆盖真正风险，需要补切片、过程指标或拒绝条件。

### 第四步：把结论写成可撤回决定

当前决定是“业务 invariant 进入发布门禁”。同时写下适用条件、责任人和重新评审信号；这样新证据出现时能更新，而不是把旧结论当永久规则。

这条推理链最终必须落到 **Schema、约束与图一致性检查**。只有定义、机制、观察和决定互相对得上，文章内容才真正进入工作系统。

## 在“发票到财务记录”中定位关键判断

定义供应商、购买方、币种、未税额、税额、总额和日期；每字段保存原文 span、规范化值与置信。验证总额≈未税额+税额、币种一致和主体不互换。评测 exact field、record exact、金额绝对误差、自动通过率与错误入账率。

| 检查点 | 应留下的证据 | 不能接受的替代品 |
|---|---|---|
| 结构化理解 | 主指标、分层指标、置信区间和失败类型，并写入Schema、约束与图一致性检查 | 平均分不能说明关键场景是否可用 |
| 约束生成 | 端到端时延、成功率、降级/拒绝和人工介入，并写入Schema、约束与图一致性检查 | 局部模型分数不是用户任务结果 |
| 错误本体 | 训练/推理/标注成本、吞吐、容量与能耗，并写入Schema、约束与图一致性检查 | 确认改进在真实预算下仍成立 |

案例不是为了模仿结论，而是为了练习定位：如果“规范化后丢失原文位置”发生，先查哪条数据或控制链，再决定继续、拒绝或交给人。

## 两份证据把“关系与事件抽取”的边界画在哪里

### CoNLL-2003 Shared Task（2003-01-01）

本章用它校准“关系与事件抽取”的边界：建立精确边界与实体类型的共同语言。。**不要越过的边界：**新闻英语/德语和窄类型无法代表嵌套、领域实体与真实系统成本。

### Universal Dependencies v2（2020-01-01）

这项工作追问：多语言句法结构能否使用统一标注框架？

UD 统一词性、形态特征与依存关系，同时允许语言特定扩展。 项目持续覆盖大量语言并维护指南、树库与验证工具。

本章据此采用的判断是：**展示 schema、社区治理和自动验证怎样共同支持跨语言资源。** 但不能外推到：统一标签仍会压平语言特性，树库质量和覆盖差异必须保留。

两份来源若结论看似冲突，先比较任务定义、数据分布、资源预算和评价方法；不能只用发布日期或排行榜高低裁决。

## 当 错误本体 失效，先查哪里

先排除这些看似合理的误解：可解析等于可用；字段 F1 高则整单可靠；生成模型不需要 offset；修复器越强越好；schema 一经定义不会演化。

### 规范化后丢失原文位置

先查看 **资源经济**：训练/推理/标注成本、吞吐、容量与能耗。如果证据确认失败，回到“业务 invariant 进入发布门禁”，保存触发输入、系统响应和人工处置，再把样本加入回归集。

### 训练集缺少完整记录级难例

先查看 **任务质量**：主指标、分层指标、置信区间和失败类型。如果证据确认失败，回到“高风险字段不允许无证据自动填充”，保存触发输入、系统响应和人工处置，再把样本加入回归集。

本章的边界不是一句“视情况而定”，而是能写进测试、监测或人工审核条件的触发器。

## “Schema、约束与图一致性检查”怎样进入真实系统

| 决定 | 验收依据 | 重新评审的信号 |
|---|---|---|
| 业务 invariant 进入发布门禁 | 训练/推理/标注成本、吞吐、容量与能耗 | 规范化后丢失原文位置 |
| 人工修订成为标注回流而非覆盖日志 | 漂移、越权、事故、恢复时间和残余风险 | 自动修复偷偷改事实 |

这些不是永久最佳实践，而是当前证据下的可逆决定。把决定、理由、适用范围和退出信号一起写进“Schema、约束与图一致性检查”，否则下一次改动只能重新争论。

## 把“关系与事件抽取”迁移到新条件

围绕“关系与事件抽取”完成如下变式：选一种票据/合同，写 schema、语法校验、两个业务 invariant 和证据对齐；用 20 条难例报告每层拦截量与仍遗漏的高风险错误。

提交“Schema、约束与图一致性检查”时同时附上：

1. 一个成功样本和一个失败样本；
2. 失败推翻了哪条假设，而不只是报错信息；
3. 哪项结论来自公开来源，哪项只来自你的本地实验；
4. 如果换数据、人群、环境或本体，最先需要重测什么；
5. 当前仍无法消除的残余风险。
