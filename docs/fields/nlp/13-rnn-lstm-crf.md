## 为什么现在要学“RNN、LSTM 与 CRF 的序列约束”

你看到的是输出变化，真正需要追的是状态、信息和约束怎样传递。合同实体抽取若用自由生成，可能改写公司名、漏字符或产生不存在实体；token 分类能保留偏移却可能生成非法 IOB 序列。

**本章核心判断：** RNN 建模上下文，CRF 对标签序列做联合归一化，从而把结构约束放进解码。

本章只追一个判断：**局部标签为什么需要联合解码？** 最后必须用“BiLSTM-CRF 基线与边界错误”来回答；如果产物不能暴露失败样本，就还不能算学会。

## 两份证据把“RNN、LSTM 与 CRF 的序列约束”的边界画在哪里

### BiLSTM-CRF for Sequence Tagging（2016-08-09）

这项工作追问：端到端神经表示怎样与标签序列约束结合？

双向 LSTM 产生上下文发射分数，CRF 联合解码完整标签序列。 在多项序列标注任务上取得当时强结果，并避免手工特征依赖。

本章据此采用的判断是：**明确区分 token 表示与结构解码两层。** 但不能外推到：长依赖、预训练和现代硬件效率不是其优势，今天主要作为可解释基线。

### ModernBERT（2024-12-18）

本章用它校准“RNN、LSTM 与 CRF 的序列约束”的边界：提醒 NLP 选型不应默认所有任务都用 decoder LLM。。**不要越过的边界：**技术报告结果与特定硬件实现需在目标环境复验。

两份来源若结论看似冲突，先比较任务定义、数据分布、资源预算和评价方法；不能只用发布日期或排行榜高低裁决。

## 当 序列结构 失效，先查哪里

先排除这些看似合理的误解：decoder LLM 总能替代 encoder；CRF 已完全过时；参数大等于长文本利用好；结构化输出等于 JSON 可解析；token F1 等于实体可用。
