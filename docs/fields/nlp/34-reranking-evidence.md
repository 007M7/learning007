## 为什么现在要学“重排与证据覆盖”

你看到的是输出变化，真正需要追的是状态、信息和约束怎样传递。位置编码允许外推不代表训练分布覆盖；大量干扰文档会争夺注意力。RAG 将问题映射到候选块，瓶颈可分为 corpus、chunk、retrieval、rerank、context assembly 与 answer utilization。Oracle evidence 能把检索误差从利用误差中分离。

**本章核心判断：** 重排优化候选顺序，证据覆盖关注回答所需事实是否齐全；Top-k 相似不等于充分。

本章只追一个判断：**Top-k 相似文段为何会遗漏完整证据链？** 最后必须用“难负例、重排与覆盖率”来回答；如果产物不能暴露失败样本，就还不能算学会。

## 给“重排与证据覆盖”一个可操作定义

重排优化候选顺序，证据覆盖关注回答所需事实是否齐全；Top-k 相似不等于充分。

可操作定义必须允许你回答三件事：输入或条件是什么，发生了哪条机制，最后观察什么才算支持结论。本章的观察出口是 **难负例、重排与覆盖率**。

### 三个支撑概念，而不是本章的替代标题

| 位置 | 概念 | 在本章中的作用 | 一旦误用会怎样 |
|---|---|---|---|
| 前置 | 上下文容量 | 接口可接收的 token 数不等于可可靠利用的信息量 | 只做 needle 单点检索 |
| 当前支点 | 检索增强 | 召回与利用哪个是瓶颈 | RAG 只要召回率高即可 |
| 下游 | 长文诊断 | 位置、密度、顺序、语言和干扰共同影响利用 | 答案对但引用错仍算成功 |

## 用公式审查“重排与证据覆盖”

端到端正确率可分解近似 $P(correct)=P(recall)P(use\ correct|recalled)P(generate\ faithful|used)$。MLRBench 的思路是测有效利用而非声明窗口；实验矩阵令 $Y=f(position,length,language,density,distractor,model)$ 并报告交互效应。

逐个把符号放回真实任务，并检查：

- 证据是否完整落在一个 chunk
- 关键条件是单点还是跨段组合
- 输入长度用各语言真实 token 计量
- Judge 是否也会随长度失效

推导完成不代表结论成立。至少改变一次关键条件，观察 **检索增强** 的结论是否保持；若不保持，把条件写入“难负例、重排与覆盖率”而不是藏在代码默认值里。

## 沿着一条完整推理链走到底

### 第一步：固定要解释或改变的对象

不要用“整体效果更好”代替对象。把“Top-k 相似文段为何会遗漏完整证据链？”改写为：在明确输入、时间点和约束下，观察什么量，比较什么基线，最后据此采取什么动作。

### 第二步：写出中间机制

上一主题“检索流水线：切分、索引与召回”提供前置条件，本章用 **检索增强** 解释关键机制，并把结果留在“难负例、重排与覆盖率”中。下一主题“能放进去不等于能用：长上下文利用”只在这些证据成立后继续。 只要中间任一环只能凭主观解释，结论就应降级为假设。

### 第三步：主动寻找反例

先尝试制造“忽略语言 token 差异”。如果当前方法仍给出看似正常的平均分，说明评价没有覆盖真正风险，需要补切片、过程指标或拒绝条件。

### 第四步：把结论写成可撤回决定

当前决定是“标称窗口不进入能力宣传”。同时写下适用条件、责任人和重新评审信号；这样新证据出现时能更新，而不是把旧结论当永久规则。

这条推理链最终必须落到 **难负例、重排与覆盖率**。只有定义、机制、观察和决定互相对得上，文章内容才真正进入工作系统。

## 把“重排与证据覆盖”做成可重放实验

实验标题：**难负例、重排与覆盖率**。不要同时追求完整系统，只要求输入可重放、判断可观测、失败可解释。

### 1. 冻结问题和验收

把“Top-k 相似文段为何会遗漏完整证据链？”写成输入、条件、基线和通过阈值，禁止实验后改题。

- **必须保存：** 问题卡、数据/环境版本和预期失败。
- **停止信号：** 答案对但引用错仍算成功。

### 2. 执行本章关键动作

建立 no-context 与 oracle-evidence 上下界

- **必须保存：** 端到端时延、成功率、降级/拒绝和人工介入。
- **停止信号：** 把 oracle 结果当真实 RAG。

### 3. 主动注入反例

构造“答案对但引用错仍算成功”，验证评价或安全控制是否真的能发现。

- **必须保存：** 触发输入、完整过程和系统响应。
- **停止信号：** 忽略语言 token 差异。

### 4. 比较并做决定

把结果与两份来源的任务和边界对齐，决定继续、降级、拒绝或补证据。

- **必须保存：** 难负例、重排与覆盖率及其适用范围。
- **停止信号：** Judge 与被测模型同样读不完。

## 当 检索增强 失效，先查哪里

先排除这些看似合理的误解：窗口大小等于阅读能力；RAG 只要召回率高即可；needle 测试代表复杂推理；更多上下文不会伤害；引用存在就算有依据。

### 答案对但引用错仍算成功

先查看 **系统表现**：端到端时延、成功率、降级/拒绝和人工介入。如果证据确认失败，回到“标称窗口不进入能力宣传”，保存触发输入、系统响应和人工处置，再把样本加入回归集。

### 忽略语言 token 差异

先查看 **风险运维**：漂移、越权、事故、恢复时间和残余风险。如果证据确认失败，回到“按失败层决定改 chunk、检索还是模型”，保存触发输入、系统响应和人工处置，再把样本加入回归集。

本章的边界不是一句“视情况而定”，而是能写进测试、监测或人工审核条件的触发器。

## “难负例、重排与覆盖率”怎样进入真实系统

| 决定 | 验收依据 | 重新评审的信号 |
|---|---|---|
| 标称窗口不进入能力宣传 | 端到端时延、成功率、降级/拒绝和人工介入 | 答案对但引用错仍算成功 |
| 上下文组装保留章节/页码/版本 | 训练/推理/标注成本、吞吐、容量与能耗 | 把 oracle 结果当真实 RAG |

这些不是永久最佳实践，而是当前证据下的可逆决定。把决定、理由、适用范围和退出信号一起写进“难负例、重排与覆盖率”，否则下一次改动只能重新争论。

## 把“重排与证据覆盖”迁移到新条件

围绕“重排与证据覆盖”完成如下变式：用一份长文构造 24 个控制样本，移动相同证据并加入干扰；画准确率/支持率随位置与长度变化，给出选全文还是 RAG 的决策。

提交“难负例、重排与覆盖率”时同时附上：

1. 一个成功样本和一个失败样本；
2. 失败推翻了哪条假设，而不只是报错信息；
3. 哪项结论来自公开来源，哪项只来自你的本地实验；
4. 如果换数据、人群、环境或本体，最先需要重测什么；
5. 当前仍无法消除的残余风险。

## 本章小结

- **问题：** Top-k 相似文段为何会遗漏完整证据链？
- **机制：** 长上下文是资源上限，不是能力保证；只有控制证据位置、长度、语言、密度和干扰，才能分辨找不到、没读懂与生成没遵循。
- **产物：** 难负例、重排与覆盖率
- **边界：** 标称窗口不能支持的能力声明
