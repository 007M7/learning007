## 两份证据把“能放进去不等于能用：长上下文利用”的边界画在哪里

本章用它校准“能放进去不等于能用：长上下文利用”的边界：建立长上下文位置压力测试范式。。**不要越过的边界：**模型代际已变化，具体曲线必须在当前模型和真实任务复测。

### MLRBench（2026-03-31）

这项工作追问：现代模型在多语言长上下文中实际利用多少？

覆盖 7 种语言，通过可控长度、位置和任务测有效阅读而非 API 容量。 研究报告多种模型的有效能力常低于标称上下文的 30%，并存在语言差异。

本章据此采用的判断是：**提供截至 2026 的多语言长上下文反证。** 但不能外推到：基准任务与模型列表有限；30% 是实验结果而非所有系统常数。

两份来源若结论看似冲突，先比较任务定义、数据分布、资源预算和评价方法；不能只用发布日期或排行榜高低裁决。

## 当 长文诊断 失效，先查哪里

先排除这些看似合理的误解：窗口大小等于阅读能力；RAG 只要召回率高即可；needle 测试代表复杂推理；更多上下文不会伤害；引用存在就算有依据。

### 把 oracle 结果当真实 RAG

先查看 **资源经济**：训练/推理/标注成本、吞吐、容量与能耗。如果证据确认失败，回到“上下文组装保留章节/页码/版本”，保存触发输入、系统响应和人工处置，再把样本加入回归集。

### Judge 与被测模型同样读不完

先查看 **任务质量**：主指标、分层指标、置信区间和失败类型。如果证据确认失败，回到“长文默认分层导航加检索”，保存触发输入、系统响应和人工处置，再把样本加入回归集。

本章的边界不是一句“视情况而定”，而是能写进测试、监测或人工审核条件的触发器。
