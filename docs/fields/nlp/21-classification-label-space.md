## 为什么现在要学“分类首先是标签空间设计”

先暂时忘掉模型名称。发票抽取返回合法 JSON，却把含税总额当未税金额、把供应商与购买方对调。字段级准确看似高，财务入账却错误。需要 schema + cross-field invariant + 原文 span + 任务级 exact record。

**本章核心判断：** 分类性能上限由标签本体决定；互斥、层级、开放集和拒绝类必须先于模型设计。

本章只追一个判断：**类别互斥、层级和开放集假设怎样改变评价？** 最后必须用“标签本体与拒绝类”来回答；如果产物不能暴露失败样本，就还不能算学会。

## 沿着一条完整推理链走到底

### 第一步：固定要解释或改变的对象

不要用“整体效果更好”代替对象。把“类别互斥、层级和开放集假设怎样改变评价？”改写为：在明确输入、时间点和约束下，观察什么量，比较什么基线，最后据此采取什么动作。

### 第二步：写出中间机制

上一主题“偏好优化与语言行为边界”提供前置条件，本章用 **结构化理解** 解释关键机制，并把结果留在“标签本体与拒绝类”中。下一主题“实体边界、嵌套与匹配协议”只在这些证据成立后继续。 只要中间任一环只能凭主观解释，结论就应降级为假设。

### 第三步：主动寻找反例

先尝试制造“规范化后丢失原文位置”。如果当前方法仍给出看似正常的平均分，说明评价没有覆盖真正风险，需要补切片、过程指标或拒绝条件。

### 第四步：把结论写成可撤回决定

当前决定是“高风险字段不允许无证据自动填充”。同时写下适用条件、责任人和重新评审信号；这样新证据出现时能更新，而不是把旧结论当永久规则。

这条推理链最终必须落到 **标签本体与拒绝类**。只有定义、机制、观察和决定互相对得上，文章内容才真正进入工作系统。

| 4 | 部分正确能否安全进入下游；在“分类首先是标签空间设计”中必须显式核对 | 人工修订成为标注回流而非覆盖日志 |

## 两份证据把“分类首先是标签空间设计”的边界画在哪里

### CoNLL-2003 Shared Task（2003-01-01）

这项工作追问：如何形成可比较的命名实体识别任务？

共享任务固定语料、PER/ORG/LOC/MISC 类型和 exact-span F1。 它成为长期 NER 基准与序列标注教学入口。

本章据此采用的判断是：**建立精确边界与实体类型的共同语言。** 但不能外推到：新闻英语/德语和窄类型无法代表嵌套、领域实体与真实系统成本。

### Universal Dependencies v2（2020-01-01）

本章用它校准“分类首先是标签空间设计”的边界：展示 schema、社区治理和自动验证怎样共同支持跨语言资源。。**不要越过的边界：**统一标签仍会压平语言特性，树库质量和覆盖差异必须保留。

两份来源若结论看似冲突，先比较任务定义、数据分布、资源预算和评价方法；不能只用发布日期或排行榜高低裁决。

## 当 结构化理解 失效，先查哪里

先排除这些看似合理的误解：可解析等于可用；字段 F1 高则整单可靠；生成模型不需要 offset；修复器越强越好；schema 一经定义不会演化。

### JSON 合法即认为正确

先查看 **任务质量**：主指标、分层指标、置信区间和失败类型。如果证据确认失败，回到“高风险字段不允许无证据自动填充”，保存触发输入、系统响应和人工处置，再把样本加入回归集。

### 规范化后丢失原文位置

先查看 **资源经济**：训练/推理/标注成本、吞吐、容量与能耗。如果证据确认失败，回到“业务 invariant 进入发布门禁”，保存触发输入、系统响应和人工处置，再把样本加入回归集。

本章的边界不是一句“视情况而定”，而是能写进测试、监测或人工审核条件的触发器。
