## 沿着一条完整推理链走到底

### 第一步：固定要解释或改变的对象

不要用“整体效果更好”代替对象。把“预测含义正确但 Span 差一个字符时应怎样计分？”改写为：在明确输入、时间点和约束下，观察什么量，比较什么基线，最后据此采取什么动作。

### 第二步：写出中间机制

上一主题“分类首先是标签空间设计”提供前置条件，本章用 **约束生成** 解释关键机制，并把结果留在“边界错误本体与 Span 评测”中。下一主题“关系与事件抽取”只在这些证据成立后继续。 只要中间任一环只能凭主观解释，结论就应降级为假设。

### 第三步：主动寻找反例

先尝试制造“自动修复偷偷改事实”。如果当前方法仍给出看似正常的平均分，说明评价没有覆盖真正风险，需要补切片、过程指标或拒绝条件。

### 第四步：把结论写成可撤回决定

当前决定是“schema 与 prompt/model 独立版本化”。同时写下适用条件、责任人和重新评审信号；这样新证据出现时能更新，而不是把旧结论当永久规则。

这条推理链最终必须落到 **边界错误本体与 Span 评测**。只有定义、机制、观察和决定互相对得上，文章内容才真正进入工作系统。

## 结构化理解 怎样经过 约束生成 影响结果

序列标注定位连续 span，span classifier 支持嵌套，生成模型适合开放 schema。JSON grammar 可在 token 选择时屏蔽非法前缀；Pydantic/JSON Schema 验类型；业务 invariant 检查金额关系和枚举；证据对齐器把每个值绑定原文偏移。修复只处理可机械确定的格式，不让模型静默猜事实。

~~~~mermaid
flowchart LR
 T[原文+版面] --> X[Span/生成候选]
 X --> G[语法/schema]
 G --> I[跨字段 invariant]
 I --> E[原文证据对齐]
 E --> C{置信与风险}
 C -->|通过| API[结构化接口]
 C -->|不足| H[人工修订]
~~~~

读图时从结果逆向追问：哪一步能够观察，哪一步只是假设，哪一步失效后必须让系统拒绝或降级。

## 用公式审查“实体边界、嵌套与匹配协议”

实体边界 F1 基于 exact span；record exact match 要求一整条记录全部正确。若字段正确率均为 $p$, $k$ 个必要字段的独立近似成功仅 $p^k$。业务损失为 $\sum_e C_{type(e)}N_e$，高成本角色互换应单独门禁。

逐个把符号放回真实任务，并检查：

- 是否允许嵌套、重叠和不连续 span
- 规范化值与原文值如何双向追溯
- schema 合法是否仍可能语义冲突
- 部分正确能否安全进入下游

推导完成不代表结论成立。至少改变一次关键条件，观察 **约束生成** 的结论是否保持；若不保持，把条件写入“边界错误本体与 Span 评测”而不是藏在代码默认值里。

## “边界错误本体与 Span 评测”怎样进入真实系统

| 决定 | 验收依据 | 重新评审的信号 |
|---|---|---|

## 当 约束生成 失效，先查哪里

先排除这些看似合理的误解：可解析等于可用；字段 F1 高则整单可靠；生成模型不需要 offset；修复器越强越好；schema 一经定义不会演化。

### 只算字段 micro-F1

先查看 **系统表现**：端到端时延、成功率、降级/拒绝和人工介入。如果证据确认失败，回到“schema 与 prompt/model 独立版本化”，保存触发输入、系统响应和人工处置，再把样本加入回归集。

### 自动修复偷偷改事实

先查看 **风险运维**：漂移、越权、事故、恢复时间和残余风险。如果证据确认失败，回到“人工修订成为标注回流而非覆盖日志”，保存触发输入、系统响应和人工处置，再把样本加入回归集。

本章的边界不是一句“视情况而定”，而是能写进测试、监测或人工审核条件的触发器。

## 把“实体边界、嵌套与匹配协议”迁移到新条件

围绕“实体边界、嵌套与匹配协议”完成如下变式：选一种票据/合同，写 schema、语法校验、两个业务 invariant 和证据对齐；用 20 条难例报告每层拦截量与仍遗漏的高风险错误。

提交“边界错误本体与 Span 评测”时同时附上：

1. 一个成功样本和一个失败样本；
2. 失败推翻了哪条假设，而不只是报错信息；
3. 哪项结论来自公开来源，哪项只来自你的本地实验；
4. 如果换数据、人群、环境或本体，最先需要重测什么；
5. 当前仍无法消除的残余风险。
