## 为什么现在要学“自动指标与人评分别看见什么”

先别问“谁最好”。BLEU、ROUGE、模型裁判和专家人评如何组合？ 只有把约束、失败代价和退出条件放在同一张表里，选择才有意义。

**本章核心判断：** 自动指标擅长规模与一致性，人评擅长情境与价值判断；两者的不一致本身也是证据。

本章只追一个判断：**BLEU、ROUGE、模型裁判和专家人评如何组合？** 最后必须用“多方法评价协议与不一致分析”来回答；如果产物不能暴露失败样本，就还不能算学会。

## 给“自动指标与人评分别看见什么”一个可操作定义

自动指标擅长规模与一致性，人评擅长情境与价值判断；两者的不一致本身也是证据。

可操作定义必须允许你回答三件事：输入或条件是什么，发生了哪条机制，最后观察什么才算支持结论。本章的观察出口是 **多方法评价协议与不一致分析**。

## 用公式审查“自动指标与人评分别看见什么”

事实精确率 $FP=|supported|/|verifiable\ claims|$，覆盖率衡量必要事实；Judge 的敏感度/特异度与 Cohen $\kappa$ 必须按切片报告。若严重错误成本 $C_s$ 远高于普通错误，应最小化 $R=\sum_kC_kP(e_k)$ 而不是单一平均得分。

逐个把符号放回真实任务，并检查：

- 来源权威性、发布日期与适用范围
- claim 分解器遗漏是否独立抽查
- Judge 是否盲于模型身份和答案顺序
- 回归集是否冻结且有污染审计

推导完成不代表结论成立。至少改变一次关键条件，观察 **评价器校准** 的结论是否保持；若不保持，把条件写入“多方法评价协议与不一致分析”而不是藏在代码默认值里。

## 沿着一条完整推理链走到底

### 第一步：固定要解释或改变的对象

不要用“整体效果更好”代替对象。把“BLEU、ROUGE、模型裁判和专家人评如何组合？”改写为：在明确输入、时间点和约束下，观察什么量，比较什么基线，最后据此采取什么动作。

### 第二步：写出中间机制

上一主题“把回答拆成 Claim–Evidence”提供前置条件，本章用 **评价器校准** 解释关键机制，并把结果留在“多方法评价协议与不一致分析”中。下一主题“LLM Judge 的偏差与校准”只在这些证据成立后继续。 只要中间任一环只能凭主观解释，结论就应降级为假设。

### 第三步：主动寻找反例

先尝试制造“不断调评价 prompt 污染回归集”。如果当前方法仍给出看似正常的平均分，说明评价没有覆盖真正风险，需要补切片、过程指标或拒绝条件。

### 第四步：把结论写成可撤回决定

当前决定是“严重错误采用零/低容忍独立门禁”。同时写下适用条件、责任人和重新评审信号；这样新证据出现时能更新，而不是把旧结论当永久规则。

这条推理链最终必须落到 **多方法评价协议与不一致分析**。只有定义、机制、观察和决定互相对得上，文章内容才真正进入工作系统。

## 当 评价器校准 失效，先查哪里

先排除这些看似合理的误解：引用等于事实；更强 Judge 就无偏；事实性是一个总分；模型自检能独立验证；离线通过后无需持续回归。

### 来源存在但不支持 claim

先查看 **系统表现**：端到端时延、成功率、降级/拒绝和人工介入。如果证据确认失败，回到“严重错误采用零/低容忍独立门禁”，保存触发输入、系统响应和人工处置，再把样本加入回归集。

### 不断调评价 prompt 污染回归集

先查看 **风险运维**：漂移、越权、事故、恢复时间和残余风险。如果证据确认失败，回到“能力声明写明语种、领域、时效和拒答边界”，保存触发输入、系统响应和人工处置，再把样本加入回归集。

本章的边界不是一句“视情况而定”，而是能写进测试、监测或人工审核条件的触发器。

## 事实性 怎样经过 评价器校准 影响结果

先将回答原子化为可核验 claims，再检索/读取权威来源，判断 entail/contradict/insufficient 和时间有效性。Judge 只承担 rubric 可观察项；与盲人评计算混淆矩阵和校准。线上反馈分无害格式、可恢复任务失败、高风险错误和安全事故，分别进入修复与门禁。

~~~~mermaid
flowchart LR
 O[输出] --> C[原子 claims]
 C --> E[权威证据+时间]
 E --> V[支持/矛盾/不足]
 V --> J[Judge rubric]
 J --> H[盲人评校准]
 H --> R[风险加权门禁]
 R -->|失败| I[事故/回归样本]
 I --> C
~~~~

读图时从结果逆向追问：哪一步能够观察，哪一步只是假设，哪一步失效后必须让系统拒绝或降级。

## 把“自动指标与人评分别看见什么”迁移到新条件

围绕“自动指标与人评分别看见什么”完成如下变式：准备 30 个输出，其中刻意加入否定、旧版本、主体错配和引用不支持；让自动 Judge 与两位盲评者判断，计算混淆矩阵并写发布门禁。

提交“多方法评价协议与不一致分析”时同时附上：

1. 一个成功样本和一个失败样本；
2. 失败推翻了哪条假设，而不只是报错信息；
3. 哪项结论来自公开来源，哪项只来自你的本地实验；
4. 如果换数据、人群、环境或本体，最先需要重测什么；
5. 当前仍无法消除的残余风险。
