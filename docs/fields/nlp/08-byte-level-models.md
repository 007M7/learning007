## 为什么现在要学“字节级模型与开放词汇边界”

前沿方法通常是在旧边界上交换了新的成本。我们要分清稳定机制、近期证据和仍未解决的问题。

**本章核心判断：** 字节级建模消除未知词但延长序列并把分词负担交给网络，质量和效率需共同比较。

本章只追一个判断：**绕开固定词表能解决什么，又把难度移到哪里？** 最后必须用“Token/byte 质量—延迟对照”来回答；如果产物不能暴露失败样本，就还不能算学会。

## 两份证据把“字节级模型与开放词汇边界”的边界画在哪里

### SentencePiece（2018-08-21）

本章用它校准“字节级模型与开放词汇边界”的边界：建立了现代多语言 tokenizer 的可复现基础。。**不要越过的边界：**语言无关实现不等于语言公平；训练混合和词表容量仍决定分配。

### Byte Latent Transformer（2024-12-13）

本章用它校准“字节级模型与开放词汇边界”的边界：提供按信息复杂度而非固定词表分配计算的路线。。**不要越过的边界：**结果来自特定规模与训练配方；推理栈、缓存和真实多语言成本仍需独立测量。

| 3 | 长度比较使用字符、字节还是语义对齐段落；在“字节级模型与开放词汇边界”中必须显式核对 | 费用/延迟看每项任务而非每 token 单价 |

## 当 切分单位 失效，先查哪里

先排除这些看似合理的误解：Tokenizer 只是工程预处理；词表越大越好；无 OOV 等于跨语言公平；更少 token 必然更强；换 tokenizer 不影响模型接口。

### 忽略 offset 对抽取高亮的影响

先查看 **风险运维**：漂移、越权、事故、恢复时间和残余风险。如果证据确认失败，回到“Tokenizer 更新视为数据接口破坏性变更”，保存触发输入、系统响应和人工处置，再把样本加入回归集。

### 只报告平均 token 长度

先查看 **任务质量**：主指标、分层指标、置信区间和失败类型。如果证据确认失败，回到“上下文窗口按最差语言预算”，保存触发输入、系统响应和人工处置，再把样本加入回归集。

本章的边界不是一句“视情况而定”，而是能写进测试、监测或人工审核条件的触发器。
