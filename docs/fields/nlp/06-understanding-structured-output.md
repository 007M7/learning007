# 06 · 分类、抽取与结构化语言

> ‘输出 JSON’只是句法层；可生产的结构化 NLP 还要保证原文证据、类型约束、实体同一性、关系方向和业务完整性。

## 这次只练一件事：实现四层校验器

发票抽取返回合法 JSON，却把含税总额当未税金额、把供应商与购买方对调。字段级准确看似高，财务入账却错误。需要 schema + cross-field invariant + 原文 span + 任务级 exact record。

不要急着把整套系统做完。本章先用一个可重放的小任务回答：**怎样让模型输出可校验实体、关系、事件和标签，而非漂亮段落？**

## 示范任务：发票到财务记录

定义供应商、购买方、币种、未税额、税额、总额和日期；每字段保存原文 span、规范化值与置信。验证总额≈未税额+税额、币种一致和主体不互换。评测 exact field、record exact、金额绝对误差、自动通过率与错误入账率。

### 读案例时做三次停顿

1. 到 结构化理解 时停一次：输出本体能否支持下游系统？
2. 到 约束生成 时再停一次：哪条数据流、状态变化或约束能证明机制真的发生？
3. 到 错误本体 时最后停一次：如果出现“JSON 合法即认为正确”，系统应继续、拒绝还是交给人？

## Span、语法约束与语义验证

序列标注定位连续 span，span classifier 支持嵌套，生成模型适合开放 schema。JSON grammar 可在 token 选择时屏蔽非法前缀；Pydantic/JSON Schema 验类型；业务 invariant 检查金额关系和枚举；证据对齐器把每个值绑定原文偏移。修复只处理可机械确定的格式，不让模型静默猜事实。

## 做到什么，才算结果可信

| 观察维度 | 要留下的记录 | 它防止你误判什么 |
|---|---|---|
| 任务质量 · 结构化理解 | 主指标、分层指标、置信区间和失败类型 | 平均分不能说明关键场景是否可用；本章还要据此判断：输出本体能否支持下游系统 |
| 系统表现 · 约束生成 | 端到端时延、成功率、降级/拒绝和人工介入 | 局部模型分数不是用户任务结果；本章还要据此判断：哪些错误应在解码时阻止 |
| 资源经济 · 错误本体 | 训练/推理/标注成本、吞吐、容量与能耗 | 确认改进在真实预算下仍成立；本章还要据此判断：迭代数据、模型还是规则 |
| 风险运维 · 结构化理解 | 漂移、越权、事故、恢复时间和残余风险 | 把一次实验转化成可持续服务；本章还要据此判断：输出本体能否支持下游系统 |

## 为什么这些步骤能够解释结果

实体边界 F1 基于 exact span；record exact match 要求一整条记录全部正确。若字段正确率均为 $p$, $k$ 个必要字段的独立近似成功仅 $p^k$。业务损失为 $\sum_e C_{type(e)}N_e$，高成本角色互换应单独门禁。

把每个符号放回真实系统。下面任何一项说不清，计算正确也不能保证结论正确：

- 是否允许嵌套、重叠和不连续 span
- 规范化值与原文值如何双向追溯
- schema 合法是否仍可能语义冲突
- 部分正确能否安全进入下游

## 拿公开证据校准你的实验

不必复述整篇论文，但要检查自己的任务单位、基线、预算和运行边界是否与来源一致。

### CoNLL-2003 Shared Task（2003-01-01）

**它追问什么：**如何形成可比较的命名实体识别任务？

**方法和结果：**共享任务固定语料、PER/ORG/LOC/MISC 类型和 exact-span F1。 它成为长期 NER 基准与序列标注教学入口。

**它改变的判断：**建立精确边界与实体类型的共同语言。

> **不要越过这条边界：**新闻英语/德语和窄类型无法代表嵌套、领域实体与真实系统成本。

### Universal Dependencies v2（2020-01-01）

**它追问什么：**多语言句法结构能否使用统一标注框架？

**方法和结果：**UD 统一词性、形态特征与依存关系，同时允许语言特定扩展。 项目持续覆盖大量语言并维护指南、树库与验证工具。

**它改变的判断：**展示 schema、社区治理和自动验证怎样共同支持跨语言资源。

> **不要越过这条边界：**统一标签仍会压平语言特性，树库质量和覆盖差异必须保留。

## 轮到你：换一组条件再做：实现四层校验器

选一种票据/合同，写 schema、语法校验、两个业务 invariant 和证据对齐；用 20 条难例报告每层拦截量与仍遗漏的高风险错误。

提交时一并回答：

- 你能否不看正文解释span、schema 与 invariant 的层次；
- 产物是否真的包含一个带证据的四层校验器；
- 哪个失败样本暴露了无法安全自动修复的结构错误；
- 如果换一个数据、人群、环境或本体，最先需要重测哪项指标。

提交物不能只有成功截图。附上一个失败样本，并说明它推翻了什么假设、哪些残余风险还不能消除。

## 验证通过后，项目要改变什么

### 1. 高风险字段不允许无证据自动填充

验收时查看 **任务质量**，至少保存主指标、分层指标、置信区间和失败类型。如果观察到“JSON 合法即认为正确”，这项决定必须重新评审，不能因为已经实现就默认保留。

### 2. schema 与 prompt/model 独立版本化

验收时查看 **系统表现**，至少保存端到端时延、成功率、降级/拒绝和人工介入。如果观察到“只算字段 micro-F1”，这项决定必须重新评审，不能因为已经实现就默认保留。

### 3. 业务 invariant 进入发布门禁

验收时查看 **资源经济**，至少保存训练/推理/标注成本、吞吐、容量与能耗。如果观察到“规范化后丢失原文位置”，这项决定必须重新评审，不能因为已经实现就默认保留。

### 4. 人工修订成为标注回流而非覆盖日志

验收时查看 **风险运维**，至少保存漂移、越权、事故、恢复时间和残余风险。如果观察到“自动修复偷偷改事实”，这项决定必须重新评审，不能因为已经实现就默认保留。

## 卡住时先查这几处

先排除这些误解：可解析等于可用；字段 F1 高则整单可靠；生成模型不需要 offset；修复器越强越好；schema 一经定义不会演化。

### JSON 合法即认为正确

- **先看什么：**主指标、分层指标、置信区间和失败类型
- **回到哪项控制：**高风险字段不允许无证据自动填充
- **怎样留下证据：**保存触发条件、原始输入、系统响应和人工处置；修复后把同一样本加入“实现四层校验器”的回归记录。

### 只算字段 micro-F1

- **先看什么：**端到端时延、成功率、降级/拒绝和人工介入
- **回到哪项控制：**schema 与 prompt/model 独立版本化
- **怎样留下证据：**保存触发条件、原始输入、系统响应和人工处置；修复后把同一样本加入“实现四层校验器”的回归记录。

### 规范化后丢失原文位置

- **先看什么：**训练/推理/标注成本、吞吐、容量与能耗

- **怎样留下证据：**保存触发条件、原始输入、系统响应和人工处置；修复后把同一样本加入“实现四层校验器”的回归记录。

## 本章小结

- 结构化输出含语法、类型、语义与证据四层
- record 指标比字段平均更接近任务
- 高风险缺失应拒绝或人工升级
- 错误本体驱动数据与架构选择
