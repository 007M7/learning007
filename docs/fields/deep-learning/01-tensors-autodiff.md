## 这次只练一件事：独立写出并验证反向传播

一个模型 loss 下降缓慢，可能来自错误标签、broadcast 造成的形状错位、detach、混合精度下溢、梯度累积未清零或真正的优化困难。只会调用 `backward()` 无法区分这些原因。自动微分给出代码所定义函数的导数，不保证代码表达了你想要的数学目标。

不要急着把整套系统做完。本章先用一个可重放的小任务回答：**神经网络训练究竟在计算什么，梯度为什么会错？**

## 示范任务：一个悄悄广播的回归损失

预测形状为 `[B,1]`、标签为 `[B]`，框架可能广播成 `[B,B]` 而不报错。loss 仍会下降，却在比较每个预测与所有标签。修复方式是先写 shape contract 和最小手算样本，再对少量参数做 central difference；训练日志同时记录梯度范数、非有限值和每层激活统计。

### 读案例时做三次停顿

1. 到 张量与算子 时停一次：一次计算的语义和资源边界？
2. 到 计算图 时再停一次：哪条数据流、状态变化或约束能证明机制真的发生？
3. 到 自动微分 时最后停一次：如果出现“相信能运行就维度正确”，系统应继续、拒绝还是交给人？

## 反向模式自动微分

前向执行把输入沿算子图变成损失，并保存反向所需的局部信息；反向从标量损失的伴随 1 出发，对每个算子应用向量—Jacobian 乘积，将来自多条路径的梯度相加。神经网络参数很多、损失很少，因此反向模式比逐参数前向模式高效。checkpointing 用重算换激活内存，`no_grad` 与 detach 改变图的边界。

~~~~mermaid
flowchart LR
  X[输入张量] --> O1[算子/形状/dtype]
  O1 --> H[中间激活]
  H --> L[标量损失]
  L --> V[VJP 反向]
  V --> G[参数梯度累积]
  G --> C[梯度检查/裁剪]
  C --> U[优化器更新]
~~~~

## 做到什么，才算结果可信

| 观察维度 | 要留下的记录 | 它防止你误判什么 |
|---|---|---|
| 任务质量 · 张量与算子 | 主指标、切片、置信区间与失败样本 | 确认改进是否稳定且可解释；本章还要据此判断：一次计算的语义和资源边界 |
| 训练 · 计算图 | loss、梯度/激活、吞吐、显存、数据量、FLOPs | 区分算法收益和更多计算；本章还要据此判断：哪些值需保留、重算或停止梯度 |
| 推理 · 自动微分 | 首 Token、每 Token、P50/P95、吞吐、峰值内存 | 模型参数量不等于用户体验；本章还要据此判断：前向/反向模式与验证方式 |
| 风险 · 张量与算子 | 校准、偏移、攻击、记忆/污染与能耗 | 把能力放入真实部署边界；本章还要据此判断：一次计算的语义和资源边界 |

## 为什么这些步骤能够解释结果

若 $z=f(x,y)$、$L=g(z)$，链式法则给出

$$
\frac{\partial L}{\partial x}=\frac{\partial L}{\partial z}\frac{\partial z}{\partial x}.
$$

多层网络 $h_l=\phi(W_lh_{l-1}+b_l)$ 的伴随递推为

$$
\bar h_{l-1}=W_l^T\left(\bar h_l\odot\phi'(a_l)\right),
\quad \frac{\partial L}{\partial W_l}=(\bar h_l\odot\phi'(a_l))h_{l-1}^T.
$$

把每个符号放回真实系统。下面任何一项说不清，计算正确也不能保证结论正确：

- 广播维度在反向时需沿扩展轴求和
- 非标量输出反向本质是 VJP，需要上游向量
- in-place 修改可能破坏保存的中间量
- 数值梯度只适合小规模、双精度和避开不可微点

## 拿公开证据校准你的实验

不必复述整篇论文，但要检查自己的任务单位、基线、预算和运行边界是否与来源一致。

### Automatic Differentiation in Machine Learning: a Survey（2018-10-17）

先看这份来源时，要带着一个具体问题：自动微分与符号微分、数值差分的区别是什么？

论文以计算图和基本算子分解前向/反向模式，说明 AD 在机器精度下应用链式法则，不需要展开巨大符号表达式。 综述建立了 JVP、VJP、复杂度和实现的统一语言。 因此，本章采用它来支持这样的判断：贡献是让反传被理解为通用程序变换而非神经网络特例。

但它没有替我们回答所有问题。综述不替代具体框架在随机、控制流、复数和分布式算子上的实现文档。

### PyTorch: An Imperative Style, High-Performance Deep Learning Library（2019-12-05）

最后看这份来源时，要带着一个具体问题：动态图如何兼顾 Python 交互式表达与高性能张量/自动微分？

PyTorch 以 define-by-run 构建动态图，autograd 记录运行时操作；后端张量库、设备抽象和分布式组件承载性能。 论文描述其设计与规模应用，解释易调试体验来自运行时图而不是牺牲全部性能。 因此，本章采用它来支持这样的判断：贡献是建立现代研究代码的执行模型。

但它没有替我们回答所有问题。框架持续演进，论文中的编译与分布式能力已非 2026 完整状态；必须查当前官方文档。

## 验证通过后，项目要改变什么

### 1. 模型入口和损失建立 shape/dtype/device 合同

验收时查看 **任务质量**，至少保存主指标、切片、置信区间与失败样本。如果观察到“相信能运行就维度正确”，这项决定必须重新评审，不能因为已经实现就默认保留。

### 2. 训练循环显式区分 forward、backward、step、zero_grad

验收时查看 **训练**，至少保存loss、梯度/激活、吞吐、显存、数据量、FLOPs。如果观察到“把数值差分误差当 AD 错误”，这项决定必须重新评审，不能因为已经实现就默认保留。

### 3. 关键自定义算子附 gradcheck

验收时查看 **推理**，至少保存首 Token、每 Token、P50/P95、吞吐、峰值内存。如果观察到“跨 batch 意外累积梯度”，这项决定必须重新评审，不能因为已经实现就默认保留。

### 4. 混合精度与 checkpointing 单独做数值/性能回归

验收时查看 **风险**，至少保存校准、偏移、攻击、记忆/污染与能耗。如果观察到“在需要梯度的路径 detach”，这项决定必须重新评审，不能因为已经实现就默认保留。

## 卡住时先查这几处

先排除这些误解：自动微分等于符号推导；梯度存在说明目标正确；反向传播只能用于神经网络；detach 只节省内存；loss 下降能排除实现错误。

### 相信能运行就维度正确

- **先看什么：** 主指标、切片、置信区间与失败样本
- **回到哪项控制：** 模型入口和损失建立 shape/dtype/device 合同
- **怎样留下证据：** 保存触发条件、原始输入、系统响应和人工处置；修复后把同一样本加入“独立写出并验证反向传播”的回归记录。

### 把数值差分误差当 AD 错误

- **先看什么：** loss、梯度/激活、吞吐、显存、数据量、FLOPs
- **回到哪项控制：** 训练循环显式区分 forward、backward、step、zero_grad
- **怎样留下证据：** 保存触发条件、原始输入、系统响应和人工处置；修复后把同一样本加入“独立写出并验证反向传播”的回归记录。

### 跨 batch 意外累积梯度

- **先看什么：** 首 Token、每 Token、P50/P95、吞吐、峰值内存
- **回到哪项控制：** 关键自定义算子附 gradcheck
- **怎样留下证据：** 保存触发条件、原始输入、系统响应和人工处置；修复后把同一样本加入“独立写出并验证反向传播”的回归记录。

### 在需要梯度的路径 detach

- **先看什么：** 校准、偏移、攻击、记忆/污染与能耗
- **回到哪项控制：** 混合精度与 checkpointing 单独做数值/性能回归
- **怎样留下证据：** 保存触发条件、原始输入、系统响应和人工处置；修复后把同一样本加入“独立写出并验证反向传播”的回归记录。

### 只监测 loss 不监测梯度和激活

- **先看什么：** 主指标、切片、置信区间与失败样本
- **回到哪项控制：** 模型入口和损失建立 shape/dtype/device 合同
- **怎样留下证据：** 保存触发条件、原始输入、系统响应和人工处置；修复后把同一样本加入“独立写出并验证反向传播”的回归记录。
