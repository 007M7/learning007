## 为什么现在要学“数据、张量与流水并行”

你看到的是输出变化，真正需要追的是状态、信息和约束怎样传递。参数量、训练 Token 和 FLOPs 经常被混为“规模”。

**本章核心判断：** 分布式训练把显存问题转成通信与同步问题，效率取决于计算通信重叠和负载平衡。

本章只追一个判断：**模型放不进一张卡时，通信从哪里成为瓶颈？** 最后必须用“显存—通信—吞吐剖析”来回答；如果产物不能暴露失败样本，就还不能算学会。

## “模型放不进一张卡时，通信从哪里成为瓶颈？”依赖哪些前提

| 顺序 | 必须成立的前提 | 对应控制 |

## 沿着一条完整推理链走到底

### 第一步：固定要解释或改变的对象

不要用“整体效果更好”代替对象。把“模型放不进一张卡时，通信从哪里成为瓶颈？”改写为：在明确输入、时间点和约束下，观察什么量，比较什么基线，最后据此采取什么动作。

### 第二步：写出中间机制

上一主题“缩放定律与算力最优分配”提供前置条件，本章用 **缩放律** 解释关键机制，并把结果留在“显存—通信—吞吐剖析”中。下一主题“SFT：用示范重塑条件行为”只在这些证据成立后继续。 只要中间任一环只能凭主观解释，结论就应降级为假设。

### 第三步：主动寻找反例

先尝试制造“跨 tokenizer 直接比较 token 数”。如果当前方法仍给出看似正常的平均分，说明评价没有覆盖真正风险，需要补切片、过程指标或拒绝条件。

### 第四步：把结论写成可撤回决定

当前决定是“训练成本和下游/安全收益同表决策”。同时写下适用条件、责任人和重新评审信号；这样新证据出现时能更新，而不是把旧结论当永久规则。

这条推理链最终必须落到 **显存—通信—吞吐剖析**。只有定义、机制、观察和决定互相对得上，文章内容才真正进入工作系统。

## 当 缩放律 失效，先查哪里

先排除这些看似合理的误解：参数越多必然更强；Chinchilla 比例是永久常数；token 是统一信息单位；GPU 小时可跨硬件直接比；更多数据不需要权利和重复审计。

### 重复数据制造表面 loss 收益

先查看 **风险**：校准、偏移、攻击、记忆/污染与能耗。如果证据确认失败，回到“训练成本和下游/安全收益同表决策”，保存触发输入、系统响应和人工处置，再把样本加入回归集。

### 跨 tokenizer 直接比较 token 数

先查看 **任务质量**：主指标、切片、置信区间与失败样本。如果证据确认失败，回到“扩展前必须用 pilot 预测并设停止阈值”，保存触发输入、系统响应和人工处置，再把样本加入回归集。

本章的边界不是一句“视情况而定”，而是能写进测试、监测或人工审核条件的触发器。

## 把“数据、张量与流水并行”迁移到新条件

围绕“数据、张量与流水并行”完成如下变式：用小规模运行拟合幂律，再故意在最大点改变数据质量或架构，观察外推残差；解释制度变化为何使旧曲线失效。

提交“显存—通信—吞吐剖析”时同时附上：

1. 一个成功样本和一个失败样本；
2. 失败推翻了哪条假设，而不只是报错信息；
3. 哪项结论来自公开来源，哪项只来自你的本地实验；
4. 如果换数据、人群、环境或本体，最先需要重测什么；
5. 当前仍无法消除的残余风险。
