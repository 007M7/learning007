## 为什么现在要学“缩放定律与算力最优分配”

公式不是装饰。它的价值是迫使我们写清对象、假设和优化目标，再检查现实是否满足。

**本章核心判断：** 缩放定律是在特定数据与架构上的经验关系，算力最优要求参数和有效 Token 协同增长。

本章只追一个判断：**固定算力下参数和 Token 应怎样共同增长？** 最后必须用“小规模 Scaling 拟合与预算表”来回答；如果产物不能暴露失败样本，就还不能算学会。

## 用公式审查“缩放定律与算力最优分配”

常见经验形式：

$$
L(N,D)\approx L_\infty + A N^{-\alpha}+B D^{-\beta},
\qquad C\approx 6ND
$$

（常数与指数依实现和定义）。计算最优选择是在约束 $C$ 下最小化估计损失，而不是单独最大化 $N$。

逐个把符号放回真实任务，并检查：

- 幂律只在观测尺度和固定数据/架构制度内可信
- token 不是跨 tokenizer 完全可比的数据单位
- $6ND$ 是粗略 dense Transformer 训练估计
- 下游能力、安全和涌现不能由预训练 loss 唯一决定

推导完成不代表结论成立。至少改变一次关键条件，观察 **训练系统** 的结论是否保持；若不保持，把条件写入“小规模 Scaling 拟合与预算表”而不是藏在代码默认值里。

## 在“训练一个 1B 中文领域模型”中定位关键判断

预算不是先定 1B 参数再塞数据，而是用 50M/100M/300M 小模型在多个 token 配比做 pilot，拟合 loss 与下游任务；对领域数据去重并保留文档级时间切分。报告 tokenizer 后 token、有效样本、FLOPs、GPU 利用率和碳/费用。若领域 SFT/RAG 已达到目标，不因缩放曲线漂亮就启动全量预训练。

| 检查点 | 应留下的证据 | 不能接受的替代品 |
|---|---|---|
| 缩放律 | 主指标、切片、置信区间与失败样本，并写入小规模 Scaling 拟合与预算表 | 确认改进是否稳定且可解释 |
| 数据混合 | loss、梯度/激活、吞吐、显存、数据量、FLOPs，并写入小规模 Scaling 拟合与预算表 | 区分算法收益和更多计算 |
| 训练系统 | 首 Token、每 Token、P50/P95、吞吐、峰值内存，并写入小规模 Scaling 拟合与预算表 | 模型参数量不等于用户体验 |

案例不是为了模仿结论，而是为了练习定位：如果“在少量尺度上过度外推”发生，先查哪条数据或控制链，再决定继续、拒绝或交给人。

## 当 训练系统 失效，先查哪里

先排除这些看似合理的误解：参数越多必然更强；Chinchilla 比例是永久常数；token 是统一信息单位；GPU 小时可跨硬件直接比；更多数据不需要权利和重复审计。

### 在少量尺度上过度外推

先查看 **推理**：首 Token、每 Token、P50/P95、吞吐、峰值内存。如果证据确认失败，回到“benchmark 污染检查在评测前冻结”，保存触发输入、系统响应和人工处置，再把样本加入回归集。

### 把预训练 loss 当所有能力代理

先查看 **任务质量**：主指标、切片、置信区间与失败样本。如果证据确认失败，回到“扩展前必须用 pilot 预测并设停止阈值”，保存触发输入、系统响应和人工处置，再把样本加入回归集。

本章的边界不是一句“视情况而定”，而是能写进测试、监测或人工审核条件的触发器。
