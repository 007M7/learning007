## 先分清尖峰、发散和 NaN

字符分类器使用第七章确认的初始化、归一化与残差配置，已经稳定训练八千多步。第 8119 步的各项指标仍在历史范围内，第 8120 步总 loss 突然升高，随后两步继续扩大，第 8123 步出现 NaN。

这是本章用于学习诊断的模拟现场。先看三种经常混在一起的表现。

一次 Loss Spike 是某一步损失明显偏离附近范围，下一步可能自行恢复。它可能来自一批更难的数据、动态损失项切换，也可能是数值或优化失稳的开端。

持续发散表现为损失、梯度或参数更新连续离开健康范围。学习率过大、反馈正向放大、初始化与结构不匹配都可能造成这种轨迹。

NaN 或 inf 属于非有限值。除零、非法对数、低精度溢出、先出现的梯度爆炸和一次错误通信都可能把它带进图。NaN 会沿后续算子快速传播，最终出现的位置往往晚于最初故障。

三种现象需要不同证据。只截一张第 8123 步 loss 为 NaN 的图，无法知道第一个异常值在第 8120 步的输入、某层激活、某个梯度还是优化器状态中出现。

## 第一动作是保全现场

看到尖峰以后，先暂停新的参数更新，保留最后一个健康 checkpoint、故障前后的日志和触发数据。若继续训练几十步再回来看，参数与优化器状态已经离开故障起点。

一份能够调查的现场至少包含下面这些对象。

| 对象 | 需要保存的内容 | 缺失后的困难 |
|---|---|---|
| 数据 batch | 稳定样本 ID、原始或可重建输入、标签、采样来源、增强参数 | 无法确认同一输入能否再次触发 |
| 模型状态 | 参数、缓冲区与具体代码版本 | 无法恢复故障前函数 |
| 优化器与日程 | 矩估计、动量、step、学习率和参数组 | 恢复轨迹已经改变 |
| 精度状态 | autocast 配置、scaler、overflow 与跳步记录 | 无法复现低精度行为 |
| 随机状态 | CPU、各设备、采样器和数据增强随机状态 | 重放得到另一条执行 |
| 运行环境 | 库版本、硬件、编译配置和关键环境选项 | 无法区分代码与运行差异 |
| 分布式现场 | 各 rank 的 batch 摘要、梯度有限值、通信与错误日志 | 平均以后会掩盖单个 worker 异常 |

保存 batch 时要遵守数据许可与隐私规则。不能长期保存原始输入，就保存稳定引用、哈希、生成配方和能复现问题的脱敏最小样本。目标是重建输入，不是为了调试绕过数据治理。

还要定义最近健康点。第 8119 步 loss 正常并不自动证明所有内部状态正常。查看故障前一段时间的激活分位数、梯度范数、更新参数比和 scaler 变化，找到最早离开基线的信号。最近健康 checkpoint 应当位于这个变化以前。

## 同一 batch 能否重复触发，先把故障分成两半

从第 8119 步 checkpoint 恢复，固定随机状态，只运行第 8120 步 batch。暂时不执行参数更新，先观察前向 loss 与反向梯度。

若同一 batch 稳定触发异常，调查重点落在数据内容、前向数值、损失和当前参数组合。若换普通 batch 就恢复，触发条件很可能与这批数据有关，但仍要查是合法难样本还是管道错误。

若同一 batch 无法复现，检查随机增强、dropout、异步数据加载、编译计划与设备非确定操作。故障也可能依赖前几步积累的优化器状态，恢复位置过晚或 checkpoint 不完整都会让它消失。

若单卡能跑、多卡才失败，重点转向各 rank 数据、归约、通信、参数同步与负载差异。本阶段不展开数据并行算法，仍然要求保存最小的 rank 级证据。第三阶段讲分布式训练时，会把这些路径展开。

重放的第一轮不急着修。它只回答故障能否由同一状态与输入再次产生。能够重复以后，每次只改变一个条件，根因才不会被多个“优化”一起盖住。

## 从数据入口查到第一次非有限值

第 8120 步 batch 比普通 batch 多出一组异常长记录。进入模型以前，先核对第一章张量契约。

- shape 是否仍在允许范围，padding 与 mask 是否对应。
- dtype 与 device 是否符合精度策略。
- 输入、标签和样本权重是否全为有限值。
- 归一化前的数据范围是否突然变化。
- 标签是否越界，空序列或全 mask 样本是否有明确定义。

“异常长”不等于“错误”。模型本来就需要处理允许范围内的长样本。若长度超出数据合同，修采样或截断；若仍在合同内，模型数值路径应当承担它，不能直接删除困难样本让曲线好看。

接着在前向图插入有限值与范围检查。不要为每个张量永久打印完整内容，先记录每个模块输出的最小值、最大值、均值、RMS、关键分位数和非有限数量。找到第一个从有限变成 inf 或 NaN 的节点。

常见位置包括指数、对数、除法、softmax 前 logits、归一化的极小方差和自定义归约。数值稳定实现通常会在 softmax 前减去最大值，在对数前约束合法范围，使用 log-sum-exp 避免先指数再求和。发现第一处异常以后，要回到该算子的输入范围和数学定义，不能只在输出上调用 `nan_to_num`。

总 loss 还可能由多项相加。分类损失、正则项、辅助损失与蒸馏损失要分开记录。总量尖峰时，先找到哪一项改变；动态权重或掩码分母为零，会让某一小项瞬间支配全部梯度。

## 前向正常以后再看反向与更新

若第 8120 步前向 loss 有限，异常可能在反向或参数更新出现。此时从输出层向输入层记录梯度。

梯度总范数是一个入口，不能作为唯一信号。全局范数正常时，某一小层仍可能异常；全局范数变大也可能是合法困难样本。按层记录梯度 RMS、最大绝对值、零比例与非有限数量，再和第七章的健康范围比较。

更新参数比能补充梯度尺度。

$$
r_l=\frac{\lVert\Delta\theta_l\rVert}
{\lVert\theta_l\rVert+\epsilon}.
$$

某层梯度看起来不大，经 Adam 的逐坐标缩放和学习率作用以后，更新仍可能相对参数过大。参数接近零时，这个比值也会放大，所以要同时查看分子、分母与坐标分布。

学习率日程是另一条线索。尖峰是否正好发生在 warmup 结束、重启或阶段切换位置；恢复 checkpoint 后，调度器 step 是否正确；梯度累积改变以后，有效更新次数是否与日程一致。第六章保存的优化器与日程状态能直接回答。

梯度裁剪可以限制单次更新，适合作为护栏。它不能说明梯度为什么变大。开启裁剪以后训练继续，事故仍要保留裁剪前范数、触发比例和对应 batch。若大部分步骤都被裁剪，实际更新规则已经长期改变，团队应当重新检查尺度、数据与学习率。

## 混合精度要记录溢出发生在哪一步

低精度格式提供更高吞吐和更少显存，也缩小或改变可安全表达的数值范围。混合精度通常让部分运算使用低精度，关键归约或参数更新保留更高精度。loss scaling 会先放大损失，避免很小的梯度在低精度中下溢，反向以后再把梯度缩回。

动态 scaler 发现 inf 或 NaN 时，可能跳过当前优化器更新并降低 scale。若日志只记录 loss，看不到这一步实际上没有更新。连续跳步会让训练停在原地，scale 反复下降又可能指向持续数值问题。

故障记录需要回答这些问题。

1. 第一个非有限值出现在前向、缩放后的反向、取消缩放还是优化器更新。
2. 哪些算子在低精度执行，哪些量用高精度累积。
3. scaler 在故障前后取什么值，多少步被跳过。
4. 把同一小图切到 float32 或 float64 后，异常是否消失。

高精度对照能够定位数值范围，不能直接成为最终修复。全程切到 float32 能跑，只说明低精度路径有问题；生产训练若需要低精度效率，还要缩小到具体算子、输入范围或缩放策略。

## 多卡平均会遮住单个 rank 的异常

分布式数据并行会在不同 rank 上处理不同小批量，再归约梯度。若只有一个 rank 收到坏样本或产生非有限梯度，归约以后所有副本都可能被污染。只保存全局平均日志，很难知道故障从哪里进入。

假设四个 rank 中只有 rank 2 收到一个异常长样本。它的前向 loss 仍是有限值，某层梯度却在低精度下上溢并变成 Inf。梯度归约把四份局部梯度相加，更新以前每个副本都会拿到被污染的结果。此时“所有 rank 同时出现 Inf”只说明污染已经传播，不能证明四份数据都有问题。需要在归约以前分别记录梯度有限性和首个异常层，再把 rank 2 的 batch 放到单卡复现。

最低限度的运行日志应为每个 rank 保存 batch 标识、loss 分项、梯度是否有限、数据耗时与通信错误。发现差异后，用相同 checkpoint 把可疑 rank 的 batch 放到单卡重放。

还要检查参数和优化器状态是否在所有 rank 一致。某个进程跳过更新、scaler 状态不同或恢复 checkpoint 不完整，都可能让副本逐步分离。可以定期比较参数摘要或哈希，异常时再扩大检查。

通信超时、硬件错误和 worker 重启属于系统故障。它们也会投影到训练曲线，却不能由调学习率解决。调查记录要保留应用日志与系统日志的共同时间线。第三阶段会学习通信拓扑和并行策略，本章只建立这条责任边界。

## 故障树应当跟着证据分叉

把排查顺序写成一棵树，比列出几十条“可能原因”更有用。

```text
Loss Spike 或 NaN
        │
        ├─ 从健康 checkpoint 重放同一 batch
        │       ├─ 能复现
        │       │    ├─ 前向先异常 → 数据合同、算子范围、loss 分项
        │       │    └─ 反向或更新先异常 → 梯度、精度、优化器、日程
        │       └─ 不能复现 → 随机状态、checkpoint 完整性、异步与非确定执行
        │
        └─ 单卡正常，多卡异常
                └─ rank 数据差异、归约、状态同步、通信与硬件
```

每次分叉都要有一个观察或对照支持。看到长样本以后直接判定“数据问题”，会错过 softmax 的数值实现；看到梯度爆炸以后直接判定“学习率过大”，也会错过标签权重突然扩大。

最小对照每次只改一个因素。可以先保持其余状态不变，只替换 batch；随后回到原 batch，仅切换数值精度。若还需检查某个 loss 分项或多卡通信，也各自建立独立实验。多个修改一起让异常消失，只能证明组合有效，不能指出根因。

## 修复以后还要证明正常样本没有被伤害

假设最终发现某个全 mask 样本让损失除以有效 token 数零。修复可以为这类输入定义拒绝规则，也可以在数据管道保证至少一个有效位置。选择哪种办法取决于任务是否允许空样本。

修复验证要包括三组样本。

- 原故障样本能够稳定触发新规则，并得到明确处理。
- 正常边界样本继续产生与旧版本一致的有效结果。
- 相邻变式，如一个有效位置、最大允许长度和不同 batch 组合，也能通过。

随后从健康 checkpoint 重新运行故障前后的一小段训练，确认 loss、梯度、更新参数比和 scaler 回到允许范围。只验证“程序不再 NaN”还不够，粗暴裁剪或跳过可能让模型停止学习。

回归门禁应放到最早能发现问题的位置。数据合同能拒绝的输入，不必等完整训练；自定义算子数值问题进入第四章的梯度与不变量套件；训练中才出现的状态组合，则保留短程重放测试和运行告警。

## 第一阶段最终留下可重放训练包

本次事故调用了前七章的全部产物。

训练面板负责在事故发生时留下第一批定位证据。最低配置可以从下面五类信号开始，具体阈值要由健康基线和模型尺度确定。

| 信号 | 记录粒度 | 异常触发 | 第一项动作 |
|---|---|---|---|
| 总 loss 与各分项 | 每步，并保留短窗口 | 非有限、突变或分项比例异常 | 冻结当前 batch 与状态 |
| 激活分位数与非有限值 | 关键层定期记录，异常时逐层扩大 | 首次越过健康范围 | 在前向图定位第一个异常层 |
| 梯度 RMS、最大值与有限性 | 更新前按层或参数组 | Inf、NaN 或层间比例突变 | 检查 loss 缩放、反向路径与裁剪前数值 |
| 更新参数比 | 每个参数组 | 更新量相对参数突然放大或归零 | 核对学习率、优化器状态和跳步 |
| scaler、rank 与系统事件 | 每步状态加共同时间戳 | 连续跳步、rank 差异或通信错误 | 切换高精度小图或单卡重放 |

- 张量契约确定输入、mask、loss 和参数的轴、类型与设备。
- 计算图指出值从哪里进入，又通过哪条路径影响 loss。
- 手算反传提供局部梯度与路径汇合的参照。
- 梯度验证区分导数实现、断图、语义和低精度问题。
- 初始化报告给出训练开始时的健康信号范围。
- 优化器对照记录状态、日程、更新尺度与续训条件。
- 归一化和残差消融说明深层模型的统计与短路径。
- 事故包保存触发输入、完整状态、故障树、修复与回归门禁。

八份材料组成一套可重放训练包。它无法保证模型在新数据上有用，也还没有说明图像为何适合卷积。它能支持一项更早的结论，这段程序确实按约定计算，梯度能穿过网络，参数更新可解释，出现异常时也能回到具体状态调查。
