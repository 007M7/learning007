## 缩放律 怎样经过 数据混合 影响结果

经验缩放律在固定范式下拟合 loss 随参数 $N$、数据 $D$ 或计算 $C$ 的幂律；Chinchilla 结论强调给定计算下模型与数据应共同扩展。数据管道进行语言/领域配比、质量过滤、去重、污染检测和权利治理。系统用数据/张量/流水线/专家并行与低精度提高利用率，但通信、负载不均和故障会改变有效计算。

~~~~mermaid
flowchart LR
  B[能力/预算目标] --> S[小规模 scaling runs]
  S --> N[参数/数据/计算分配]
  N --> D[数据混合/去重/权利]
  N --> Y[并行/精度/容错]
  D --> T[预训练]
  Y --> T
  T --> E[loss+下游+污染评测]
  E --> R[是否扩展/调整制度]
~~~~

读图时从结果逆向追问：哪一步能够观察，哪一步只是假设，哪一步失效后必须让系统拒绝或降级。

## 用公式审查“训练数据的清洗、去重与配比”

常见经验形式：

$$
L(N,D)\approx L_\infty + A N^{-\alpha}+B D^{-\beta},
\qquad C\approx 6ND
$$

（常数与指数依实现和定义）。计算最优选择是在约束 $C$ 下最小化估计损失，而不是单独最大化 $N$。

逐个把符号放回真实任务，并检查：

- 幂律只在观测尺度和固定数据/架构制度内可信
- token 不是跨 tokenizer 完全可比的数据单位
- $6ND$ 是粗略 dense Transformer 训练估计
- 下游能力、安全和涌现不能由预训练 loss 唯一决定

推导完成不代表结论成立。至少改变一次关键条件，观察 **数据混合** 的结论是否保持；若不保持，把条件写入“数据混合卡与去重审计”而不是藏在代码默认值里。

## “数据混合卡与去重审计”怎样进入真实系统

| 决定 | 验收依据 | 重新评审的信号 |
|---|---|---|
| 数据账本记录来源、许可、语言/领域和去重 | loss、梯度/激活、吞吐、显存、数据量、FLOPs | 用 GPU 小时代替 FLOPs/费用 |
| benchmark 污染检查在评测前冻结 | 首 Token、每 Token、P50/P95、吞吐、峰值内存 | 在少量尺度上过度外推 |

这些不是永久最佳实践，而是当前证据下的可逆决定。把决定、理由、适用范围和退出信号一起写进“数据混合卡与去重审计”，否则下一次改动只能重新争论。

## 当 数据混合 失效，先查哪里

先排除这些看似合理的误解：参数越多必然更强；Chinchilla 比例是永久常数；token 是统一信息单位；GPU 小时可跨硬件直接比；更多数据不需要权利和重复审计。

### 用 GPU 小时代替 FLOPs/费用

先查看 **训练**：loss、梯度/激活、吞吐、显存、数据量、FLOPs。如果证据确认失败，回到“数据账本记录来源、许可、语言/领域和去重”，保存触发输入、系统响应和人工处置，再把样本加入回归集。

### 重复数据制造表面 loss 收益

先查看 **风险**：校准、偏移、攻击、记忆/污染与能耗。如果证据确认失败，回到“训练成本和下游/安全收益同表决策”，保存触发输入、系统响应和人工处置，再把样本加入回归集。

本章的边界不是一句“视情况而定”，而是能写进测试、监测或人工审核条件的触发器。

## 把“训练数据的清洗、去重与配比”迁移到新条件

围绕“训练数据的清洗、去重与配比”完成如下变式：用小规模运行拟合幂律，再故意在最大点改变数据质量或架构，观察外推残差；解释制度变化为何使旧曲线失效。

提交“数据混合卡与去重审计”时同时附上：

1. 一个成功样本和一个失败样本；
2. 失败推翻了哪条假设，而不只是报错信息；
3. 哪项结论来自公开来源，哪项只来自你的本地实验；
4. 如果换数据、人群、环境或本体，最先需要重测什么；
5. 当前仍无法消除的残余风险。
