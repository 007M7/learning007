## 为什么现在要学“DPO 与 RLHF 的目标函数”

公式不是装饰。它的价值是迫使我们写清对象、假设和优化目标，再检查现实是否满足。

**本章核心判断：** DPO 从偏好对直接估计相对策略，RLHF 在线更新策略；二者都依赖参考分布和偏好质量。

本章只追一个判断：**直接偏好优化和在线策略优化在分布上有何不同？** 最后必须用“目标推导与 KL/胜率曲线”来回答；如果产物不能暴露失败样本，就还不能算学会。

## 用公式审查“DPO 与 RLHF 的目标函数”

DPO 常见目标为

$$
-\mathbb E\log\sigma\left(\beta\left[
\log\frac{\pi_\theta(y_w|x)}{\pi_{ref}(y_w|x)}-
\log\frac{\pi_\theta(y_l|x)}{\pi_{ref}(y_l|x)}
\right]\right).
$$

受 KL 约束的策略目标可概括为

$$
\max_\pi\mathbb E[r(x,y)]-\beta D_{KL}(\pi\|\pi_{ref}).
$$

逐个把符号放回真实任务，并检查：

- 偏好对不等于绝对正确答案
- $\beta$ 控制偏好强度和参考约束
- 奖励可验证只证明判定器覆盖的结果
- 训练采样分布与部署提示分布可能不同

推导完成不代表结论成立。至少改变一次关键条件，观察 **可验证 RL** 的结论是否保持；若不保持，把条件写入“目标推导与 KL/胜率曲线”而不是藏在代码默认值里。

## 给“DPO 与 RLHF 的目标函数”一个可操作定义

DPO 从偏好对直接估计相对策略，RLHF 在线更新策略；二者都依赖参考分布和偏好质量。

可操作定义必须允许你回答三件事：输入或条件是什么，发生了哪条机制，最后观察什么才算支持结论。本章的观察出口是 **目标推导与 KL/胜率曲线**。

## 沿着一条完整推理链走到底

### 第一步：固定要解释或改变的对象

不要用“整体效果更好”代替对象。把“直接偏好优化和在线策略优化在分布上有何不同？”改写为：在明确输入、时间点和约束下，观察什么量，比较什么基线，最后据此采取什么动作。

### 第二步：写出中间机制

上一主题“偏好数据与奖励模型”提供前置条件，本章用 **可验证 RL** 解释关键机制，并把结果留在“目标推导与 KL/胜率曲线”中。下一主题“推理后训练：过程、结果与验证器”只在这些证据成立后继续。 只要中间任一环只能凭主观解释，结论就应降级为假设。

### 第三步：主动寻找反例

先尝试制造“把推理文本当忠实内部机制”。如果当前方法仍给出看似正常的平均分，说明评价没有覆盖真正风险，需要补切片、过程指标或拒绝条件。

### 第四步：把结论写成可撤回决定

当前决定是“奖励与 Judge 需红队并保留确定验证器”。同时写下适用条件、责任人和重新评审信号；这样新证据出现时能更新，而不是把旧结论当永久规则。

这条推理链最终必须落到 **目标推导与 KL/胜率曲线**。只有定义、机制、观察和决定互相对得上，文章内容才真正进入工作系统。

## 在“领域分析助手的后训练”中定位关键判断

先用 2,000 个经专家审阅的示范教报告结构和引用格式；用偏好对训练是否承认不确定、是否引用充分。计算题和可执行查询才进入可验证 RL。每阶段在冻结集比较事实、任务完成、拒绝、长度、引用支持率和领域外安全；若奖励升高但长答案/套模板增加，判为 reward proxy 过优化。

| 检查点 | 应留下的证据 | 不能接受的替代品 |
|---|---|---|
| 监督指令微调 | 主指标、切片、置信区间与失败样本，并写入目标推导与 KL/胜率曲线 | 确认改进是否稳定且可解释 |
| 偏好优化 | loss、梯度/激活、吞吐、显存、数据量、FLOPs，并写入目标推导与 KL/胜率曲线 | 区分算法收益和更多计算 |
| 可验证 RL | 首 Token、每 Token、P50/P95、吞吐、峰值内存，并写入目标推导与 KL/胜率曲线 | 模型参数量不等于用户体验 |

案例不是为了模仿结论，而是为了练习定位：如果“用同一 Judge 生成、训练和验收”发生，先查哪条数据或控制链，再决定继续、拒绝或交给人。

## 两份证据把“DPO 与 RLHF 的目标函数”的边界画在哪里

### Direct Preference Optimization（2023-05-29）

本章用它校准“DPO 与 RLHF 的目标函数”的边界：贡献是降低偏好对齐工程复杂度并形成广泛基线。。**不要越过的边界：**离线偏好覆盖、reference 和超参会限制效果；DPO 不自动解决标签偏差或分布外过优化。

### DeepSeek-R1（2025-01-22）

这项工作追问：大规模可验证 RL 能否在没有初始 SFT 时产生复杂推理行为？

R1-Zero 直接对基础模型做 RL，观察到自我验证、反思与长推理，但出现可读性和语言混合；R1 加入 cold-start、分阶段 RL/SFT，并蒸馏到小模型。 报告称 R1 在多项数学、代码和推理基准接近当时强闭源模型，并开放权重。

本章据此采用的判断是：**贡献是提供可验证奖励驱动 reasoning 的大规模证据与训练配方。** 但不能外推到：厂商自报且依赖具体数据/奖励/预算；基准表现不能证明忠实思维过程或开放任务通用性。

两份来源若结论看似冲突，先比较任务定义、数据分布、资源预算和评价方法；不能只用发布日期或排行榜高低裁决。

## 当 可验证 RL 失效，先查哪里

先排除这些看似合理的误解：SFT 会增加所有知识；DPO 不需要任何奖励假设；RL 奖励上升等于推理更真实；chain-of-thought 是忠实解释；后训练只影响风格。

### 用同一 Judge 生成、训练和验收

先查看 **推理**：首 Token、每 Token、P50/P95、吞吐、峰值内存。如果证据确认失败，回到“奖励与 Judge 需红队并保留确定验证器”，保存触发输入、系统响应和人工处置，再把样本加入回归集。

### 把推理文本当忠实内部机制

先查看 **任务质量**：主指标、切片、置信区间与失败样本。如果证据确认失败，回到“每类后训练数据记录来源、标注政策与版本”，保存触发输入、系统响应和人工处置，再把样本加入回归集。

本章的边界不是一句“视情况而定”，而是能写进测试、监测或人工审核条件的触发器。

## “目标推导与 KL/胜率曲线”怎样进入真实系统

| 决定 | 验收依据 | 重新评审的信号 |
|---|---|---|
| 奖励与 Judge 需红队并保留确定验证器 | 首 Token、每 Token、P50/P95、吞吐、峰值内存 | 用同一 Judge 生成、训练和验收 |
| 能力提升和安全/风格变化分开门禁 | 校准、偏移、攻击、记忆/污染与能耗 | 忽略长度/格式投机 |

这些不是永久最佳实践，而是当前证据下的可逆决定。把决定、理由、适用范围和退出信号一起写进“目标推导与 KL/胜率曲线”，否则下一次改动只能重新争论。

## 把“DPO 与 RLHF 的目标函数”迁移到新条件

围绕“DPO 与 RLHF 的目标函数”完成如下变式：设计一个偏好数据偏爱长答案的实验，观察 DPO 后长度与真实正确率；再通过长度匹配、独立 rubric 或约束修正，解释哪个指标被投机。

提交“目标推导与 KL/胜率曲线”时同时附上：

1. 一个成功样本和一个失败样本；
2. 失败推翻了哪条假设，而不只是报错信息；
3. 哪项结论来自公开来源，哪项只来自你的本地实验；
4. 如果换数据、人群、环境或本体，最先需要重测什么；
5. 当前仍无法消除的残余风险。
