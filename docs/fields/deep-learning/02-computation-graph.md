## 五行模型代码里藏着两条路线

上一章的字符分类器已经有了张量契约。现在把网络缩小到能画在纸上。输入 $x$ 的形状是 `[B, 4]`，先经过一个线性层和 ReLU，再经过第二个线性层得到 logits。训练时还加了一项权重惩罚。

```python
a = x @ w1 + b1
h = relu(a)
logits = h @ w2 + b2
data_loss = cross_entropy(logits, target)
penalty = 0.5 * weight_decay * (w1 ** 2).sum()
loss = data_loss + penalty
```

顺着代码读，我们容易把它看成六行依次执行的命令。顺着值的来路读，`loss` 实际有两条支路。数据损失从 `x` 一路经过 `w1` 和 `w2`，惩罚项直接使用 `w1`。两条支路在最后一次加法汇合。

```text
x ─┐
   ├─ matmul ─ add b1 ─ ReLU ─ matmul ─ add b2 ─ cross entropy ─┐
w1 ┘                              ▲                              │
                                    w2                            ├─ add ─ loss
w1 ─ square ─ sum ─ scale ───────────────────────────────────────┘
```

`w1` 因此收到两部分影响。第一部分来自分类误差，第二部分来自权重惩罚。若手写反向只沿最长的那条线走，惩罚项对 `w1` 的梯度就会漏掉。若程序不小心对 `penalty` 调用了 `detach`，数值仍然会被加进 loss，参数却不会沿这条支路更新。

计算图首先解决这个阅读问题。它按照依赖组织程序，使我们能从最终损失反向追到所有参与计算的值。

## 节点记录一次具体执行

计算图里的算子可以很小。矩阵乘法、加法、ReLU、求和与索引都能成为一个节点。每个节点在前向时接收张量，产生新张量；反向时接收结果一侧传来的梯度，再把对应梯度送给需要求导的输入。

以 $a=xW+b$ 为例。前向要知道 $x$、$W$ 与 $b$。若最终损失记作 $L$，反向会收到 $\partial L/\partial a$，随后计算三份结果。

$$
\frac{\partial L}{\partial x}=\frac{\partial L}{\partial a}W^\mathsf{T},
\qquad
\frac{\partial L}{\partial W}=x^\mathsf{T}\frac{\partial L}{\partial a},
\qquad
\frac{\partial L}{\partial b}=\sum_{i=1}^{B}\frac{\partial L}{\partial a_i}.
$$

偏置在前向时从 `[H]` 广播到 `[B, H]`，反向便沿 batch 轴求和。第一章看到的广播规则，在图里变成了一条明确的梯度归约。

反向并不总要保存节点的全部输入和输出。ReLU 若保存前向输入是否大于零，就能决定梯度在哪里通过；某些实现也可以从输出判断。矩阵乘法为了求 $W$ 的梯度需要 $x$，为了求 $x$ 的梯度需要 $W$。框架会根据算子的反向定义保存所需状态，这些状态通常称为中间激活或 saved tensors。

训练显存因此不只放参数。较深网络还要保存一串中间激活，批量和序列越长，它们占用的空间越大。激活检查点会丢弃一部分中间值，反向走到那里时重新执行前向。它用更多计算换取更少内存。判断这项交换以前，先从图上标出哪些值能重算，哪些算子含随机性或外部状态。

可以先在图卡上做一次很小的估算。一个 `[256,4096]` 的 `float32` 激活约占 4 MiB，连续二十层只计算每层一份输出也接近 80 MiB，尚未计入算子额外保存的状态。若某一段主要由便宜、确定的逐元素算子组成，却产生很大的激活，它更适合用检查点换内存。若重算会重新抽取随机掩码、读取可变外部状态或触发昂贵算子，就要先固定随机性并核算时间。图卡最终应写下“保存哪些值、重算哪一段、预计省多少内存、增加多少计算”，让选择可以被复测。

## 一张图需要标出什么

只画层名还不够。一张能用于调试的计算图至少要留下五类信息。

| 图上对象 | 要写清的内容 | 它能回答的问题 |
|---|---|---|
| 输入与参数 | 轴语义、shape、dtype、device、是否求导 | 进入算子的对象是否符合契约 |
| 算子 | 精确操作与关键配置 | 值在哪一步被变换或归约 |
| 中间激活 | 输出形状与反向所需状态 | 显存被谁占用，反向缺什么 |
| 分支与汇合 | 一个值被几条路径使用 | 梯度应当在哪些位置相加 |
| 梯度边界 | `requires_grad`、`detach`、`no_grad` 的位置 | 哪些参数从损失不可达 |

继续看分类器。`target` 参与交叉熵计算，却不需要梯度。`x` 在一般监督训练中也可以不求梯度，但 `w1`、`b1`、`w2` 和 `b2` 要从 loss 可达。若我们正在生成输入对抗扰动，`x` 又可能需要梯度。同一个张量是否求导取决于当前任务，不能由它叫“输入”还是“参数”永久决定。

没有父节点、又被要求求导的张量常被称为叶子张量。模型参数通常属于这一类。算子产生的 `a`、`h` 和 `logits` 是中间张量。框架默认把梯度累积到叶子参数的 `.grad` 中；中间张量的梯度若要保留，往往需要明确请求。第三章会解释为什么这里使用“累积”这个词。

## 代码的控制流会改变图

在动态图框架中，计算图来自这一次真实执行。下面的模型会根据输入选择一条支路。

```python
if x.abs().max() > threshold:
    h = safe_block(x)
else:
    h = fast_block(x)
```

本批数据只执行其中一条，当前图里也只有这一条。下一批数据走另一条路，图随之变化。这种 define-by-run 方式适合普通编程控制流和交互调试。它也提醒我们，一次成功的图检查没有覆盖从未执行的分支。

循环也会按实际次数展开。循环运行十步，图里就出现十次依赖；参数即使每步共享，产生的中间状态仍然不同。后面的 RNN 章节会沿时间展开这张图，观察一份梯度要穿过多少步。

编译系统可能把若干算子融合、重新排序或生成新的执行计划。面向学习的计算图描述数学依赖，性能剖析还要看编译后的执行图。两张图解决不同问题。前者回答输出由谁决定，后者回答硬件实际运行了什么。

## 分叉后的梯度必须在汇合处相加

假设一个中间量 $h$ 同时走进两条支路。

$$
u=f(h), \qquad v=g(h), \qquad L=u+v.
$$

改变 $h$ 会同时改变 $u$ 和 $v$，所以总梯度是两条路径贡献的和。

$$
\frac{\partial L}{\partial h}
=\frac{\partial L}{\partial u}\frac{\partial u}{\partial h}
+\frac{\partial L}{\partial v}\frac{\partial v}{\partial h}.
$$

这条规则会反复出现。一个共享参数在多个时间步使用，梯度要把各步贡献相加；一个残差块同时保留恒等路径和变换路径，输入梯度也从两条路汇合；同一批样本的平均损失对参数求导，各样本的贡献在归约中合并。

图的价值就在这里。它让“加在哪里”由依赖决定，不靠背诵某种网络的专用公式。

Jacobian 是多维输出对多维输入的局部导数表。真实网络中的 Jacobian 很大，框架通常不显式构造整张表。反向节点接收上游向量，再计算向量与 Jacobian 的乘积。我们会在下一章把这个动作写成 VJP，并解释它为何适合标量损失和大量参数。当前画图时只需标出局部输入、输出和反向规则需要什么。

## 从 loss 逆向做一次可达性审计

一张图画完以后，从标量 loss 开始逆向走。每到一个算子，检查哪几个输入需要梯度，局部反向需要保存什么，分支是否全部计入。最后把应训练参数分成三类。

| 参数状态 | 图上现象 | 下一步 |
|---|---|---|
| 可达且梯度有限 | 存在从 loss 到参数的完整路径 | 进入数值验证 |
| 设计上冻结 | 参数明确不求导，原因有记录 | 确认优化器没有接管它 |
| 意外不可达 | 本应训练，却被条件分支、detach 或无梯度算子截断 | 缩小输入并定位断点 |

还要检查一类“可达却无效”的路径。ReLU 前向输入长期小于零时，图仍然连通，局部导数却为零；饱和激活也可能让导数非常小。计算图能告诉我们路径存在，不能保证梯度大小足以训练。第五章会继续追踪信号尺度。

为本章分类器制作一张计算图卡。先使用批量为 2 的输入完成一次真实前向，随后记录每个算子的输入输出形状。把数据损失与权重惩罚两条支路画全，再从 loss 逆向标出 `w1` 的两份梯度来源。最后故意在惩罚项前插入 `detach`，说明数值和梯度分别发生了什么变化。

产物至少包含下面这些内容。

- 一张按依赖绘制的图，不能只抄模块列表。
- 每个关键节点的张量契约和局部反向所需状态。
- 所有分支汇合与共享参数位置。
- 设计冻结与意外断图的区分。
- 一条从 loss 到每个可训练参数的可达路径。
