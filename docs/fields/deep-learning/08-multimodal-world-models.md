# 08 · 多模态与世界模型

> 多模态表示解决“信息能否相遇”，世界模型还必须回答“动作后世界怎样变化”；视觉逼真不能替代动力学正确。

## 旧办法卡在了哪里

> 对齐文本、图像、视频和动作时，共享表示真正保留了什么？

CLIP 相似可支持开放词汇识别，却可能依赖背景捷径；图文模型能描述物体，不代表知道抓取后的接触变化。视频生成看似真实，仍可能穿透、反重力或跨视角漂移。世界模型用于规划时，微小动力学偏差会被长轨迹放大。

## 现在真正汇合的是哪三件事

### 1. 跨模态对齐

把配对文本、图像、音频等映射到可比较表示。这里真正要支持的判断是：**共享空间能支持哪些检索与迁移**。

- **先排除的误解：** 共享 embedding 等于完整理解
- **用反例检查：** 把 CLIP 相似当空间 grounding
- **理解检查：** 不看定义，用自己的项目举一个例子，再说明哪条观察会让这个例子不成立。

### 2. 多模态融合

以交叉注意或统一 token 交换细粒度信息。这里真正要支持的判断是：**何时早融合、晚融合或工具化**。

- **先排除的误解：** 图文对齐自动产生 3D
- **用反例检查：** 未加入动作却称世界模型
- **理解检查：** 不看定义，用自己的项目举一个例子，再说明哪条观察会让这个例子不成立。

### 3. 世界模型

预测状态/观察在动作条件下如何演化。这里真正要支持的判断是：**用于规划、数据、评测还是想象**。

- **先排除的误解：** 视频逼真就是世界模型
- **用反例检查：** 只测一步预测
- **理解检查：** 不看定义，用自己的项目举一个例子，再说明哪条观察会让这个例子不成立。

## 把变化连起来：对比对齐、交叉融合与动作条件预测

对比学习拉近配对样本并推远 batch 内负例，获得粗粒度共享空间；cross-attention 让一种模态查询另一模态 token，支持细粒度 grounding。世界模型学习 $p(s_{t+1}|s_t,a_t)$ 或未来观察序列，可在潜空间 rollout 供规划/策略训练。机器人场景还需要多视角几何一致、接触和控制条件。

~~~~mermaid
flowchart LR
  I[图像/视频] --> A[对比对齐]
  T[文本/音频] --> A
  A --> F[Cross-attention 融合]
  F --> G[Grounding/状态]
  G --> W[动作条件世界模型]
  W --> R[Rollout/规划/数据]
  R --> E[几何/物理/任务一致性]
~~~~

## 截至当前，证据能说到哪一步

发布日期较新不自动意味着证据等级更高。下面逐项看机制、结果和限制。

### Learning Transferable Visual Models From Natural Language Supervision（2021-02-26）

先看这份来源时，要带着一个具体问题：互联网图文对能否训练可零样本迁移的视觉表示？

CLIP 在 4 亿图文对上用双编码器对比学习，类别文本提示可作为零样本分类权重。 论文跨 30+ 数据集展示强零样本迁移，同时报告分布偏移、OCR 和社会偏差等限制。 因此，本章采用它来支持这样的判断：贡献是把自然语言监督变成开放视觉接口。

但它没有替我们回答所有问题。互联网数据偏差、粗粒度配对和提示敏感性限制 grounding；不是物理世界理解证明。

### World Model for Robot Learning: A Comprehensive Survey（2026-04-30）

接着看这份来源时，要带着一个具体问题：机器人世界模型在规划、策略、仿真、评测和数据生成中分别扮演什么角色？

综述按架构、功能和具身应用整理预测模型，并连接视频世界模型、model-based planning、机器人学习与基准。 作者指出世界模型已从想象式生成走向可控、结构化和基础模型规模，同时保留动力学、评测与耦合难题。 因此，本章采用它来支持这样的判断：贡献是提供 2026 年统一问题地图和持续更新资源。

但它没有替我们回答所有问题。综述不是新算法的独立性能证据，且快速领域中的覆盖会过时。

### PAIWorld（2026-06-16）

最后看这份来源时，要带着一个具体问题：机器人多摄像头世界模型怎样保持跨视角三维一致？

方法在 DiT 中加入几何感知跨视角注意、编码相机射线/外参的旋转位置表示和 3D 表征蒸馏。 作者报告在 WorldArena 等多视角基准领先并支持规划、数据和策略后训练。 因此，本章采用它来支持这样的判断：贡献是把显式几何通信引入多视角世界基础模型。

但它没有替我们回答所有问题。预印本排行榜与生成指标仍需真实策略和跨硬件独立复现。

## 稳定机制与新近结论的分界

对称对比损失的一侧为

$$
\mathcal L_{i\to t}=-\frac1N\sum_i\log\frac{\exp(z_i^Iv_i^T/\tau)}{\sum_j\exp(z_i^Iv_j^T/\tau)}.
$$

动作条件世界模型最大化

$$
\sum_t\log p_\theta(o_{t+1}\mid o_{\le t},a_{\le t}),
$$

但像素似然高不保证任务相关状态和物理约束正确。

把每个符号放回真实系统。下面任何一项说不清，计算正确也不能保证结论正确：

- 负例可能包含语义相同样本
- 对齐空间的相似度不等于可组合推理
- 世界模型需要区分观测随机性与动力学不确定性
- 长 rollout 必须测误差累积和策略利用模型漏洞

## 把前沿能力放回真实约束：仓库机器人多视角预测

顶置、腕部和第一视角摄像头观察同一抓取。共享表示先做物体/指令 grounding，世界模型接收相机外参和动作，预测多视角未来。评测分像素、3D 位置、接触事件、动作响应和下游规划成功；若视频好看但物体在视角间漂移，不能用于安全规划，只能作为有限数据增强。

### 读案例时做三次停顿

1. 到 跨模态对齐 时停一次：共享空间能支持哪些检索与迁移？
2. 到 多模态融合 时再停一次：哪条数据流、状态变化或约束能证明机制真的发生？
3. 到 世界模型 时最后停一次：如果出现“把 CLIP 相似当空间 grounding”，系统应继续、拒绝还是交给人？

## 今天可以采取的动作

### 1. 共享表示、grounding 和动力学分别评测

验收时查看 **任务质量**，至少保存主指标、切片、置信区间与失败样本。如果观察到“把 CLIP 相似当空间 grounding”，这项决定必须重新评审，不能因为已经实现就默认保留。

### 2. 世界模型输入显式包含动作与传感器标定

验收时查看 **训练**，至少保存loss、梯度/激活、吞吐、显存、数据量、FLOPs。如果观察到“未加入动作却称世界模型”，这项决定必须重新评审，不能因为已经实现就默认保留。

### 3. 生成数据标记 synthetic provenance

验收时查看 **推理**，至少保存首 Token、每 Token、P50/P95、吞吐、峰值内存。如果观察到“只测一步预测”，这项决定必须重新评审，不能因为已经实现就默认保留。

### 4. 用于规划前需通过物理/任务闭环而非视觉评分

验收时查看 **风险**，至少保存校准、偏移、攻击、记忆/污染与能耗。如果观察到“多视角拼 token 不编码几何”，这项决定必须重新评审，不能因为已经实现就默认保留。

## 仍然不能这样外推

先排除这些误解：共享 embedding 等于完整理解；图文对齐自动产生 3D；视频逼真就是世界模型；一步误差低就能长程规划；合成数据没有分布风险。

### 把 CLIP 相似当空间 grounding

- **先看什么：** 主指标、切片、置信区间与失败样本
- **回到哪项控制：** 共享表示、grounding 和动力学分别评测
- **怎样留下证据：** 保存触发条件、原始输入、系统响应和人工处置；修复后把同一样本加入“区分看起来对与物理上对”的回归记录。

### 未加入动作却称世界模型

- **先看什么：** loss、梯度/激活、吞吐、显存、数据量、FLOPs
- **回到哪项控制：** 世界模型输入显式包含动作与传感器标定
- **怎样留下证据：** 保存触发条件、原始输入、系统响应和人工处置；修复后把同一样本加入“区分看起来对与物理上对”的回归记录。

### 只测一步预测

- **先看什么：** 首 Token、每 Token、P50/P95、吞吐、峰值内存
- **回到哪项控制：** 生成数据标记 synthetic provenance
- **怎样留下证据：** 保存触发条件、原始输入、系统响应和人工处置；修复后把同一样本加入“区分看起来对与物理上对”的回归记录。

### 多视角拼 token 不编码几何

- **先看什么：** 校准、偏移、攻击、记忆/污染与能耗
- **回到哪项控制：** 用于规划前需通过物理/任务闭环而非视觉评分
- **怎样留下证据：** 保存触发条件、原始输入、系统响应和人工处置；修复后把同一样本加入“区分看起来对与物理上对”的回归记录。

### 策略利用世界模型不真实漏洞

- **先看什么：** 主指标、切片、置信区间与失败样本
- **回到哪项控制：** 共享表示、grounding 和动力学分别评测

## 建立自己的更新实验：区分看起来对与物理上对

### 第 1 步：训练小型图文对比模型并检查 hard negatives

- **这一步在验证：** 跨模态对齐能否支持“共享空间能支持哪些检索与迁移”这项判断。
- **至少留下：** 主指标、切片、置信区间与失败样本。
- **先停下来而不是继续调参的信号：** 把 CLIP 相似当空间 grounding。

### 第 2 步：加入跨注意力做指代 grounding

- **这一步在验证：** 多模态融合能否支持“何时早融合、晚融合或工具化”这项判断。
- **至少留下：** loss、梯度/激活、吞吐、显存、数据量、FLOPs。
- **先停下来而不是继续调参的信号：** 未加入动作却称世界模型。

### 第 3 步：构造动作条件视频/状态预测

- **这一步在验证：** 世界模型能否支持“用于规划、数据、评测还是想象”这项判断。
- **至少留下：** 首 Token、每 Token、P50/P95、吞吐、峰值内存。
- **先停下来而不是继续调参的信号：** 只测一步预测。

### 第 4 步：比较单视角与多视角，并测 rollout 误差和策略成功

- **这一步在验证：** 跨模态对齐能否支持“共享空间能支持哪些检索与迁移”这项判断。
- **至少留下：** 校准、偏移、攻击、记忆/污染与能耗。
- **先停下来而不是继续调参的信号：** 多视角拼 token 不编码几何。

完成示范后再做一次变式：构造三个视觉逼真但物理错误的视频案例（穿透、跨视角漂移、动作无因果响应），为每类定义机器可测指标和下游后果。

## 做到什么，才算结果可信

| 观察维度 | 要留下的记录 | 它防止你误判什么 |
|---|---|---|
| 任务质量 · 跨模态对齐 | 主指标、切片、置信区间与失败样本 | 确认改进是否稳定且可解释；本章还要据此判断：共享空间能支持哪些检索与迁移 |
| 训练 · 多模态融合 | loss、梯度/激活、吞吐、显存、数据量、FLOPs | 区分算法收益和更多计算；本章还要据此判断：何时早融合、晚融合或工具化 |
| 推理 · 世界模型 | 首 Token、每 Token、P50/P95、吞吐、峰值内存 | 模型参数量不等于用户体验；本章还要据此判断：用于规划、数据、评测还是想象 |
| 风险 · 跨模态对齐 | 校准、偏移、攻击、记忆/污染与能耗 | 把能力放入真实部署边界；本章还要据此判断：共享空间能支持哪些检索与迁移 |

## 本章小结

- 对齐、融合、grounding 是不同层
- 世界模型需显式条件化动作
- 几何和物理一致独立于视觉质量
- 规划价值必须由闭环任务验证
