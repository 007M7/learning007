## 第三章的答案交给框架重算

上一章手算了一个只有两个权重的小网络。现在用自动微分执行同一组数字。框架在前向时记录乘法、加法、ReLU 和平方误差，反向时从 loss 的 1 出发调用各算子的反向规则。若代码与手算图完全一致，我们期待得到 $w_2$ 的梯度 6、$w_1$ 的梯度 30。

```python
x = torch.tensor(2.0, dtype=torch.float64)
y = torch.tensor(7.0, dtype=torch.float64)
w1 = torch.tensor(3.0, dtype=torch.float64, requires_grad=True)
b1 = torch.tensor(-4.0, dtype=torch.float64, requires_grad=True)
w2 = torch.tensor(5.0, dtype=torch.float64, requires_grad=True)
b2 = torch.tensor(0.0, dtype=torch.float64, requires_grad=True)

a = w1 * x + b1
h = torch.relu(a)
y_hat = w2 * h + b2
loss = 0.5 * (y_hat - y) ** 2
loss.backward()
```

自动微分得到相同数字，能支持两件事。当前执行路径上的算子反向组合与手算一致，代码也没有在这几个节点之间意外断开。它仍然不能证明字符分类任务定义正确，也不能证明批量版没有错误广播。

把第一章的 `[B,1]` 预测和 `[B]` 标签交给自动微分，框架会先按广播规则生成 `[B,B]` 误差，再准确求出这个错误损失的梯度。数值差分也会对同一个错误函数做扰动，两边很可能高度一致。

因此，梯度通过检查的准确表述应当是“程序导数与独立近似一致”。不能把它扩大成“模型实现正确”。

## 中心差分从参数两侧看斜率

对于一个标量参数 $\theta$，导数可以用很小的扰动近似。前向差分只在一侧取值，误差通常随 $\varepsilon$ 一阶变化。

$$
g_{forward}=\frac{L(\theta+\varepsilon)-L(\theta)}{\varepsilon}.
$$

中心差分同时查看两侧，主要截断误差通常更小。

$$
g_{numeric}=\frac{L(\theta+\varepsilon)-L(\theta-\varepsilon)}{2\varepsilon}.
$$

把上一章的 $w_2=5$ 向两侧各移动 $10^{-5}$，分别重新运行前向，就能得到一个接近 6 的数值梯度。自动微分给出的 6 来自链式法则，数值梯度来自损失值的有限变化，两条计算路线相对独立。

$\varepsilon$ 不能无限缩小。太大时，差分看到的是一段弯曲区间的平均斜率；太小时，两个相近浮点数相减会丢失有效数字。梯度检查通常切到 `float64`，尝试几个数量级，并观察误差是否先下降后受舍入影响。固定一个神奇的 epsilon，换参数尺度以后很容易误判。

比较时不能只看一个相对误差数字。例如两个梯度分别是 $10^{-8}$ 和 $2\times10^{-8}$，相对差达到 0.5，绝对差却只有 $10^{-8}$。若它们对当前参数更新都可以忽略，仅用相对阈值会误报；若业务恰好依赖这个微小梯度，只看绝对阈值又会漏报。更可控的做法是同时写下绝对容差与相对容差。

$$
|g_{auto}-g_{numeric}|
\leq \operatorname{atol}
+\operatorname{rtol}\max(|g_{auto}|,|g_{numeric}|).
$$

`atol` 保护接近零的区域，`rtol` 随梯度尺度调整允许误差。两者都要根据双精度、参数尺度和算子数值条件设定，并保留自动梯度、数值梯度与差值原数。容差通过也只表示局部数值一致，不能替代方向、形状和任务不变量。

## 不可微点会让两种正确答案看起来冲突

ReLU 在零点有折角。若参数扰动让 $a$ 从负数跨到正数，中心差分看见折角两侧的平均变化；自动微分按照框架约定选择一个局部值。两者不同，并不能立刻证明反向实现有错。

最大值、绝对值和裁剪在折点也没有唯一普通导数。正式检查前可以让输入远离折点，或者单独核对框架采用的次梯度约定。排序在数值不相等的局部区域可以表现为固定置换，遇到并列值时映射会突然改变。离散索引与 `argmax` 对选择变量通常没有可供梯度训练的连续导数，不能把它们和折点一起交给次梯度解释。遇到这类算子，要先明确哪些输入应当求导，再为可微部分选择最小子图。

随机性也会污染差分。两次前向若使用不同 dropout 掩码或不同数据增强，损失变化同时包含参数扰动和随机样本变化。检查时要关闭随机层，或者固定随机状态，保证 $L(\theta+\varepsilon)$ 与 $L(\theta-\varepsilon)$ 只差这一项参数。

批归一化的运行统计、状态更新和分布式归约也会改变前向状态。数值检查要明确使用训练还是评估模式，必要时冻结运行统计。这里检验的是一个确定函数，若两次调用本身不是同一个函数，差分没有共同基准。

## 参数很多时检查一个方向

逐个扰动数百万个参数代价太高。可以随机取一个与参数同形的方向 $v$，比较梯度在这个方向上的投影与方向差分。

$$
g_{auto}^{dir}=\nabla_\theta L\cdot v,
$$

$$
g_{numeric}^{dir}=\frac{L(\theta+\varepsilon v)-L(\theta-\varepsilon v)}{2\varepsilon}.
$$

一次方向检查能同时穿过许多参数。它不能定位具体错误，所以常见顺序是先做几次随机方向测试；发现不一致以后，把图缩小到某个模块或某个参数，再逐元素检查。

方向向量需要归一化，避免参数量增大时扰动总长度失控。不同参数组尺度差异很大时，可以按层分别抽方向。嵌入、归一化参数和卷积核承担的计算不同，把全部拼成一个方向可能让大尺度部分遮住小尺度故障。

数值检查适合小模型、小批量和关键自定义算子。它会额外运行许多次前向，不能作为每个生产训练 step 的常规监测。大训练依靠上线前的单元测试、少量抽查和运行时统计共同保护。

## 四类错误需要四种证据

假设梯度异常，先判断哪一层承诺被破坏。

| 故障 | 典型现象 | 更直接的检查 |
|---|---|---|
| 局部反向写错 | 自动梯度与中心差分或方向差分不一致 | 双精度 gradcheck，缩小到自定义算子 |
| 依赖路径断开 | 某个应训练参数从 loss 不可达，或框架返回 `None` | 从 loss 做可达性审计，检查 detach 与条件分支 |
| 张量语义错误 | 自动梯度与数值梯度一致，任务结果却异常 | 轴语义、形状、配对和归约不变量 |
| 数值范围失守 | 低精度出现 inf、NaN 或大量跳步，双精度小图正常 | 精度对照、缩放状态、逐层有限值检查 |

第一类最适合数值差分。第二类要回到计算图。梯度为零本身不能证明断图，ReLU 关闭、路径抵消或刚好位于驻点都可能给出零值，需要结合可达性、钩子与局部激活判断。第三类要回到张量契约和可手算样本。第四类需要记录 dtype、缩放和中间值范围。

原地操作常落在第二和第四类之间。框架能够检测到某个已保存张量被改写时，通常会报版本错误；所有修改都能被自动发现这个假设并不安全。共享视图、自定义算子和不受跟踪的外部状态仍然可能产生复杂问题。调试时先移除原地写法，确认函数式版本正确，再证明性能优化没有改变结果。

`detach` 也没有“好”或“坏”的固定结论。目标网络、停止梯度估计和缓存特征可能有意设置边界。错误发生在意图没有写清，某条应该训练的路径被无声切断。计算图卡要把所有设计断点列出来，测试则要确认断点两侧的梯度状态。

## 语义不变量负责抓住错误目标

广播 bug 能同时通过自动微分和中心差分，需要另一组与任务有关的检查。

字符分类器可以先写下下面这些不变量。

- 交换 batch 中两张图片的顺序，逐样本输出也应按同样顺序交换，总损失保持不变。
- 复制同一个样本两次并取平均损失，参数梯度应与单样本相同。
- 只修改第 $i$ 个标签时，归约以前只有第 $i$ 个样本损失发生变化。
- 样本权重全部乘以同一常数时，求和损失与梯度按相同比例变化；平均口径则按契约判断。
- 在不含随机层的评估模式下，同一输入重复前向得到相同输出。

第一条检查 batch 轴有没有混入特征或类别轴。第二条检查平均与求和。第三条会直接暴露 `[B,1]` 对 `[B]` 造成的两两比较。它们不验证导数公式，却能验证程序是否保持任务要求的关系。

一个完整梯度测试因此分成三圈。

```text
最内圈  能手算的小图
         核对前向值、局部导数和路径汇合

中间圈  独立导数近似
         中心差分、随机方向、双精度与确定执行

最外圈  任务结构不变量
         轴语义、样本独立、归约、对称性与梯度边界
```

三圈得到的证据可以互相定位。手算和差分都错，先查局部实现。两者一致而不变量失败，先查损失与张量语义。只有低精度训练失败，检查数值范围和精度策略。

## 把失败写进梯度故障簿

检查发现问题以后，不能只改一行代码。保存能够稳定复现它的最小输入、参数、随机状态、前向输出、自动梯度、数值梯度和不变量结果。故障簿还要记录根因、修复和新增门禁。

| 字段 | 广播故障示例 |
|---|---|
| 触发条件 | prediction 为 `[3,1]`，target 为 `[3]` |
| 表面现象 | loss 有限且能够下降 |
| 导数检查 | 自动梯度与中心差分一致 |
| 失败证据 | 修改一个标签会改变三行逐元素误差 |
| 根因 | 样本轴与补出的轴广播为 `[3,3]` |
| 修复 | 两者统一为 `[3]`，损失入口增加形状断言 |
| 回归门禁 | 单标签扰动只能影响对应逐样本损失 |

为自己的模型完成一份同样的记录。至少选择一个正常算子和一个自定义或高风险算子，分别运行中心差分或方向差分；再注入一次 detach、一次错误广播和一次低精度溢出，观察三圈检查分别在哪一层发出信号。
