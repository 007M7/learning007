## 先还原现场：领域分析助手的后训练

先用 2,000 个经专家审阅的示范教报告结构和引用格式；用偏好对训练是否承认不确定、是否引用充分。计算题和可执行查询才进入可验证 RL。每阶段在冻结集比较事实、任务完成、拒绝、长度、引用支持率和领域外安全；若奖励升高但长答案/套模板增加，判为 reward proxy 过优化。

先不要急着把结果归因给“模型不够强”。问自己：**SFT、偏好优化与强化学习分别改变了什么分布？**

SFT 可教格式却覆盖有限；偏好数据受标注者和采样策略影响；RL 在数学/代码等可验证任务上有清晰奖励，却可能学会长度、格式或测试漏洞。训练分数提升不等于知识增加，也不等于跨领域安全。需要保留基础模型、SFT、偏好/RL 多个 checkpoint 做同数据消融。

## 从行为克隆到受约束策略优化

先沿数据流或控制流追一次。很多故障的最后一步很醒目，第一步却可能只是一个时间点、单位、权限或责任边界没有写清。

SFT 对专家示范做 teacher forcing。RLHF 训练奖励模型，再以 KL 约束策略不偏离参考；DPO 从 Bradley–Terry 偏好模型推导出直接比较 chosen/rejected 的分类目标，无需显式在线奖励模型。可验证 RL 用执行器/答案判定奖励采样轨迹；课程、采样温度、组相对优势与冷启动数据影响训练稳定和可读性。

## 三个关键判断点

### 1. 监督指令微调

在示范分布上最大化期望回答似然。这里真正要支持的判断是：**格式/任务适配是否已有高质量示范**。

- **先排除的误解：**SFT 会增加所有知识
- **用反例检查：**把偏好等同真理
- **理解检查：**不看定义，用自己的项目举一个例子，再说明哪条观察会让这个例子不成立。

### 2. 偏好优化

用成对/标量反馈改变输出相对偏好。这里真正要支持的判断是：**反馈噪声与 KL 约束是否可控**。

- **先排除的误解：**DPO 不需要任何奖励假设
- **用反例检查：**只测奖励模型分数
- **理解检查：**不看定义，用自己的项目举一个例子，再说明哪条观察会让这个例子不成立。

### 3. 可验证 RL

在可检查结果上通过采样与奖励优化策略。这里真正要支持的判断是：**探索能否带来真实推理而非投机**。

- **先排除的误解：**RL 奖励上升等于推理更真实
- **用反例检查：**用同一 Judge 生成、训练和验收
- **理解检查：**不看定义，用自己的项目举一个例子，再说明哪条观察会让这个例子不成立。

## 用形式化检查隐藏假设

DPO 常见目标为

$$
-\mathbb E\log\sigma\left(\beta\left[
\log\frac{\pi_\theta(y_w|x)}{\pi_{ref}(y_w|x)}-
\log\frac{\pi_\theta(y_l|x)}{\pi_{ref}(y_l|x)}
\right]\right).
$$

受 KL 约束的策略目标可概括为

$$
\max_\pi\mathbb E[r(x,y)]-\beta D_{KL}(\pi\|\pi_{ref}).
$$

把每个符号放回真实系统。下面任何一项说不清，计算正确也不能保证结论正确：

- 偏好对不等于绝对正确答案
- $\beta$ 控制偏好强度和参考约束
- 奖励可验证只证明判定器覆盖的结果
- 训练采样分布与部署提示分布可能不同

## 外部证据能排除哪些误判

案例告诉我们发生了什么，研究与标准帮助判断哪些解释可迁移、哪些控制本应存在。

### Direct Preference Optimization（2023-05-29）

**它追问什么：**能否不用显式奖励模型和在线 RL 直接优化偏好？

**方法和结果：**DPO 从 KL 约束奖励最优策略与 Bradley–Terry 偏好概率关系推导封闭目标，用 chosen/rejected 对训练策略。 论文在摘要、对话等任务报告与 PPO 类方法竞争且训练简单稳定。

**它改变的判断：**贡献是降低偏好对齐工程复杂度并形成广泛基线。

> **不要越过这条边界：**离线偏好覆盖、reference 和超参会限制效果；DPO 不自动解决标签偏差或分布外过优化。

### DeepSeek-R1（2025-01-22）

**它追问什么：**大规模可验证 RL 能否在没有初始 SFT 时产生复杂推理行为？

**方法和结果：**R1-Zero 直接对基础模型做 RL，观察到自我验证、反思与长推理，但出现可读性和语言混合；R1 加入 cold-start、分阶段 RL/SFT，并蒸馏到小模型。 报告称 R1 在多项数学、代码和推理基准接近当时强闭源模型，并开放权重。

**它改变的判断：**贡献是提供可验证奖励驱动 reasoning 的大规模证据与训练配方。

> **不要越过这条边界：**厂商自报且依赖具体数据/奖励/预算；基准表现不能证明忠实思维过程或开放任务通用性。

## 如果由你接手，先做哪四步：让奖励上升而产品变差

### 第 1 步：在小模型上保留 base/SFT/DPO 三个 checkpoint

- **这一步在验证：**监督指令微调能否支持“格式/任务适配是否已有高质量示范”这项判断。
- **至少留下：**主指标、切片、置信区间与失败样本。
- **先停下来而不是继续调参的信号：**把偏好等同真理。

### 第 2 步：同一提示集比较任务、格式、事实与 KL/长度变化

- **这一步在验证：**偏好优化能否支持“反馈噪声与 KL 约束是否可控”这项判断。
- **至少留下：**loss、梯度/激活、吞吐、显存、数据量、FLOPs。
- **先停下来而不是继续调参的信号：**只测奖励模型分数。

### 第 3 步：构造偏好标签噪声和反事实顺序偏差

- **这一步在验证：**可验证 RL能否支持“探索能否带来真实推理而非投机”这项判断。
- **至少留下：**首 Token、每 Token、P50/P95、吞吐、峰值内存。
- **先停下来而不是继续调参的信号：**用同一 Judge 生成、训练和验收。

### 第 4 步：为可验证奖励加入一个漏洞，观察策略是否利用

- **这一步在验证：**监督指令微调能否支持“格式/任务适配是否已有高质量示范”这项判断。
- **至少留下：**校准、偏移、攻击、记忆/污染与能耗。
- **先停下来而不是继续调参的信号：**忽略长度/格式投机。

## 做到什么，才算结果可信

| 观察维度 | 要留下的记录 | 它防止你误判什么 |
|---|---|---|
| 任务质量 · 监督指令微调 | 主指标、切片、置信区间与失败样本 | 确认改进是否稳定且可解释；本章还要据此判断：格式/任务适配是否已有高质量示范 |
| 训练 · 偏好优化 | loss、梯度/激活、吞吐、显存、数据量、FLOPs | 区分算法收益和更多计算；本章还要据此判断：反馈噪声与 KL 约束是否可控 |
| 推理 · 可验证 RL | 首 Token、每 Token、P50/P95、吞吐、峰值内存 | 模型参数量不等于用户体验；本章还要据此判断：探索能否带来真实推理而非投机 |
| 风险 · 监督指令微调 | 校准、偏移、攻击、记忆/污染与能耗 | 把能力放入真实部署边界；本章还要据此判断：格式/任务适配是否已有高质量示范 |

## 防止下一次以同样方式发生

### 1. 每类后训练数据记录来源、标注政策与版本

验收时查看 **任务质量**，至少保存主指标、切片、置信区间与失败样本。如果观察到“把偏好等同真理”，这项决定必须重新评审，不能因为已经实现就默认保留。

### 2. 训练阶段 checkpoint 支持行为回归和回退

验收时查看 **训练**，至少保存loss、梯度/激活、吞吐、显存、数据量、FLOPs。如果观察到“只测奖励模型分数”，这项决定必须重新评审，不能因为已经实现就默认保留。

### 3. 奖励与 Judge 需红队并保留确定验证器

验收时查看 **推理**，至少保存首 Token、每 Token、P50/P95、吞吐、峰值内存。如果观察到“用同一 Judge 生成、训练和验收”，这项决定必须重新评审，不能因为已经实现就默认保留。

### 4. 能力提升和安全/风格变化分开门禁

验收时查看 **风险**，至少保存校准、偏移、攻击、记忆/污染与能耗。如果观察到“忽略长度/格式投机”，这项决定必须重新评审，不能因为已经实现就默认保留。

## 仍需保留的残余风险

先排除这些误解：SFT 会增加所有知识；DPO 不需要任何奖励假设；RL 奖励上升等于推理更真实；chain-of-thought 是忠实解释；后训练只影响风格。

## 把复盘迁移到新场景：让奖励上升而产品变差

设计一个偏好数据偏爱长答案的实验，观察 DPO 后长度与真实正确率；再通过长度匹配、独立 rubric 或约束修正，解释哪个指标被投机。

提交时一并回答：

- 你能否不看正文解释SFT、DPO、可验证 RL 的目标差异；
- 产物是否真的包含一个三 checkpoint 行为消融；
- 哪个失败样本暴露了奖励提升不能证明真实推理的原因；
- 如果换一个数据、人群、环境或本体，最先需要重测哪项指标。

提交物不能只有成功截图。附上一个失败样本，并说明它推翻了什么假设、哪些残余风险还不能消除。

## 本章小结

- SFT、偏好和 RL 改变不同训练信号
- DPO 简化但不消除偏好偏差
- 可验证奖励适合有可靠结果判定的任务
- 每阶段需独立回归和 reward hacking 测试
