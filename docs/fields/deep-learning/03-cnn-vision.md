## 从一个容易答错的问题开始

> 局部性、平移等变与全局注意力之间如何取舍？

小型工业缺陷数据上，ViT 可能因缺乏预训练和错误增强而不如 CNN；大规模预训练后，ViT 又能获得更强迁移。模型参数相近不代表 FLOPs、内存访问和边缘延迟相同。图像分类分数也不代表定位、遮挡和域偏移下可靠。

## 先把三个角色认清

### 1. 卷积偏置

局部感受野和权共享编码平移结构。这里真正要支持的判断是：**局部模式是否稳定可复用**。

- **先排除的误解：** ViT 已淘汰 CNN
- **用反例检查：** 用参数量代替实际延迟
- **理解检查：** 不看定义，用自己的项目举一个例子，再说明哪条观察会让这个例子不成立。

### 2. 残差骨干

恒等捷径让深层网络学习增量变换。这里真正要支持的判断是：**深度是否带来可优化收益**。

- **先排除的误解：** 卷积天然平移不变
- **用反例检查：** patch 大小抹去小目标
- **理解检查：** 不看定义，用自己的项目举一个例子，再说明哪条观察会让这个例子不成立。

### 3. 视觉 Transformer

图像 patch token 通过全局注意力交互。这里真正要支持的判断是：**数据/预训练是否支撑更弱偏置**。

- **先排除的误解：** 参数少一定更快
- **用反例检查：** 训练/测试拍摄批次泄漏
- **理解检查：** 不看定义，用自己的项目举一个例子，再说明哪条观察会让这个例子不成立。

## 局部等变、残差优化与 patch 注意力

卷积核在空间滑动实现平移等变，池化/步幅扩大感受野并降低分辨率。ResNet 让块学习 $F(x)$ 并输出 $x+F(x)$，改善深网络信号传播。ViT 把 patch 投影为 token，加位置编码后用多头自注意力全局混合。ConvNeXt 等反向吸收 Transformer 的训练和宏观设计，说明性能来自一组设计而非单一算子。

~~~~mermaid
flowchart LR
  I[图像/增强] --> C[CNN 局部共享]
  I --> P[Patch+ViT 全局注意]
  C --> R[残差多尺度表示]
  P --> R
  R --> H[分类/检测/分割头]
  H --> E[IID+遮挡+域偏移]
  E --> D[质量/延迟/内存选型]
~~~~

## 公式真正暴露了哪些假设

二维卷积可写为

$$
y_{i,j,c_o}=\sum_{u,v,c_i}K_{u,v,c_i,c_o}x_{i+u,j+v,c_i}.
$$

残差块 $y=x+F(x)$ 的梯度包含恒等路径：

$$
\frac{\partial L}{\partial x}=\frac{\partial L}{\partial y}\left(I+\frac{\partial F}{\partial x}\right).
$$

把每个符号放回真实系统。下面任何一项说不清，计算正确也不能保证结论正确：

- 卷积等变会被边界、步幅和池化改变
- 感受野理论大小不等于有效感受野
- patch 大小决定序列长度和细粒度信息
- 预训练数据与增强可能比骨干名字更影响结果

## 真实研究怎样修正这个直觉

这些来源不是让你记论文名，而是帮助区分哪些判断已有证据，哪些仍只是合理猜测。

### Deep Residual Learning for Image Recognition（2015-12-10）

先看这份来源时，要带着一个具体问题：为什么更深网络出现退化，恒等捷径能否使其可优化？

ResNet 用残差块和 shortcut 让网络学习相对恒等映射的增量，构建 50/101/152 层视觉网络。 论文在 ImageNet 和检测任务取得当时领先，并显示普通深网络训练误差反而更高的退化现象。 因此，本章采用它来支持这样的判断：贡献是提供可扩展深度的优化接口，影响远超视觉。

但它没有替我们回答所有问题。原始结果不能代表今天最优骨干；残差也不保证任意深度/尺度稳定。

### An Image is Worth 16x16 Words（2021-06-03）

接着看这份来源时，要带着一个具体问题：纯 Transformer 在足够预训练数据下能否替代卷积视觉骨干？

ViT 将图像分 patch、线性嵌入并用标准 Transformer encoder；依赖大规模监督预训练后迁移到中等图像任务。 作者报告在大预训练规模下匹配或超过强 CNN，同时训练计算更有竞争力。 因此，本章采用它来支持这样的判断：贡献是证明视觉可统一成 token 序列建模。

但它没有替我们回答所有问题。小数据、边缘延迟和密集预测需要独立对照，不能从 ImageNet 迁移成绩概括。

### A ConvNet for the 2020s（2022-03-02）

最后看这份来源时，要带着一个具体问题：若逐步把现代训练和 Transformer 宏观设计移植到卷积，CNN 能否保持竞争力？

ConvNeXt 从 ResNet 出发，调整 stage 比例、patchify stem、深度可分离卷积、LayerNorm、激活和训练策略。 论文在分类、检测与分割展示与同规模 Transformer 竞争。 因此，本章采用它来支持这样的判断：贡献是用受控现代化削弱“注意力单独带来全部提升”的归因。

但它没有替我们回答所有问题。具体硬件效率与实现相关，架构消融也无法穷尽所有交互。

## 回到：产线表面缺陷检测

只有 8,000 张图、缺陷尺寸小且相机固定。保留轻量 CNN 从头训练、预训练 ConvNeXt 和 ViT 三组；patch 不能大到吞掉细裂纹。按生产批次和相机分组测试，增加亮度、污染和遮挡切片。最终以漏检成本、边缘设备 P95 和校准选择，而非只看 ImageNet 架构声誉。

### 读案例时做三次停顿

1. 到 卷积偏置 时停一次：局部模式是否稳定可复用？
2. 到 残差骨干 时再停一次：哪条数据流、状态变化或约束能证明机制真的发生？
3. 到 视觉 Transformer 时最后停一次：如果出现“用参数量代替实际延迟”，系统应继续、拒绝还是交给人？

## 跟做一遍：测量数据规模如何改变骨干排名

### 第 1 步：固定图像分辨率与训练预算比较 CNN/ViT

- **这一步在验证：** 卷积偏置能否支持“局部模式是否稳定可复用”这项判断。
- **至少留下：** 主指标、切片、置信区间与失败样本。
- **先停下来而不是继续调参的信号：** 用参数量代替实际延迟。

### 第 2 步：从小数据到增加预训练逐级改变数据条件

- **这一步在验证：** 残差骨干能否支持“深度是否带来可优化收益”这项判断。
- **至少留下：** loss、梯度/激活、吞吐、显存、数据量、FLOPs。
- **先停下来而不是继续调参的信号：** patch 大小抹去小目标。

### 第 3 步：用遮挡/平移测试等变和鲁棒性

- **这一步在验证：** 视觉 Transformer能否支持“数据/预训练是否支撑更弱偏置”这项判断。
- **至少留下：** 首 Token、每 Token、P50/P95、吞吐、峰值内存。
- **先停下来而不是继续调参的信号：** 训练/测试拍摄批次泄漏。

### 第 4 步：在目标硬件测预处理、推理和后处理完整延迟

- **这一步在验证：** 卷积偏置能否支持“局部模式是否稳定可复用”这项判断。
- **至少留下：** 校准、偏移、攻击、记忆/污染与能耗。
- **先停下来而不是继续调参的信号：** 使用翻转等不合法增强。

完成示范后再做一次变式：在 10%、30%、100% 数据量下训练小 CNN 和小 ViT，分别加入/不加入预训练；画质量—数据—计算曲线并解释排名翻转。

## 别把“ViT 已淘汰 CNN”当成结论

常见误区还包括：卷积天然平移不变；参数少一定更快；预训练收益等于架构收益；ImageNet 领先等于领域任务领先。

### 用参数量代替实际延迟

- **先看什么：** 主指标、切片、置信区间与失败样本
- **回到哪项控制：** 骨干选型绑定数据规模、任务粒度和硬件
- **怎样留下证据：** 保存触发条件、原始输入、系统响应和人工处置；修复后把同一样本加入“测量数据规模如何改变骨干排名”的回归记录。

### patch 大小抹去小目标

- **先看什么：** loss、梯度/激活、吞吐、显存、数据量、FLOPs
- **回到哪项控制：** 增强变换需验证语义合法
- **怎样留下证据：** 保存触发条件、原始输入、系统响应和人工处置；修复后把同一样本加入“测量数据规模如何改变骨干排名”的回归记录。

### 训练/测试拍摄批次泄漏

- **先看什么：** 首 Token、每 Token、P50/P95、吞吐、峰值内存
- **回到哪项控制：** 分类之外保留定位/区域证据
- **怎样留下证据：** 保存触发条件、原始输入、系统响应和人工处置；修复后把同一样本加入“测量数据规模如何改变骨干排名”的回归记录。

### 使用翻转等不合法增强

- **先看什么：** 校准、偏移、攻击、记忆/污染与能耗
- **回到哪项控制：** 延迟使用目标设备端到端测量
- **怎样留下证据：** 保存触发条件、原始输入、系统响应和人工处置；修复后把同一样本加入“测量数据规模如何改变骨干排名”的回归记录。

### 用分类准确率代表安全漏检

- **先看什么：** 主指标、切片、置信区间与失败样本
- **回到哪项控制：** 骨干选型绑定数据规模、任务粒度和硬件
- **怎样留下证据：** 保存触发条件、原始输入、系统响应和人工处置；修复后把同一样本加入“测量数据规模如何改变骨干排名”的回归记录。
