## 先还原现场：多运营人 BVLOS 走廊

两家平台共享走廊，提交四维意图并接收动态限制。沿高度/位置/运营商实测上行和中断；注入 UTM 延迟、冲突计划和 Remote ID 不一致。失链按持续时间进入继续/返航/备降，服务中断停止新放行。

先不要急着把结果归因给“模型不够强”。问自己：**高密度 BVLOS 运行需要交换哪些意图、身份、约束和冲突信息？**

4G 覆盖图显示信号，却无法保证低时延、上行容量和漫游切换；多家运营平台对同一空域有不同意图视图。必须定义 end-to-end C2 SLO、Remote ID、UOM/USS 一致性和失联降级。

## 链路预算、状态机与协同服务

先沿数据流或控制流追一次。很多故障的最后一步很醒目，第一步却可能只是一个时间点、单位、权限或责任边界没有写清。

C2 从航空器—接入网—核心网—控制站全链路测量 RSRP/SINR、丢包、RTT、抖动和可用性。运行识别提供身份/位置等最小必要信息。UTM/U-space 用服务交换运行计划、空域约束、监视和冲突；机载 DAA 与地面服务是互补防线。

## 三个关键判断点

### 1. C2 通信

遥控/监视链在覆盖、延迟、完整性和安全上满足运行需求。这里真正要支持的判断是：**失链何时触发何种动作**。

- **先排除的误解：** 5G 覆盖即 C2 合格
- **用反例检查：** 信号格数当可靠性
- **理解检查：** 不看定义，用自己的项目举一个例子，再说明哪条观察会让这个例子不成立。

### 2. 运行识别

航空器/运营信息按规则对授权主体可见。这里真正要支持的判断是：**身份、隐私和可信怎样平衡**。

- **先排除的误解：** UTM 等于传统塔台
- **用反例检查：** 下行好等于上行好
- **理解检查：** 不看定义，用自己的项目举一个例子，再说明哪条观察会让这个例子不成立。

### 3. UTM/UOM 服务

航线意图、约束、动态空域和冲突通过服务协同。这里真正要支持的判断是：**服务失效时谁维持安全**。

- **先排除的误解：** Remote ID 无隐私权衡
- **用反例检查：** 把待实施标准写成已实施
- **理解检查：** 不看定义，用自己的项目举一个例子，再说明哪条观察会让这个例子不成立。

## 用形式化检查隐藏假设

链路余量 $M=P_t+G_t+G_r-L_{path}-L_{misc}-Sensitivity$；可靠运行关注 $P(latency<L,availability>A)$ 和连续中断长度。冲突概率/间隔必须考虑意图更新延迟和位置协方差。

把每个符号放回真实系统。下面任何一项说不清，计算正确也不能保证结论正确：

- 覆盖图与目标高度/上行差异
- 运营商/卫星切换与共因
- 身份数据的访问/留存
- UTM 服务不可用时的运行最小能力

## 外部证据能排除哪些误判

案例告诉我们发生了什么，研究与标准帮助判断哪些解释可迁移、哪些控制本应存在。

### GB/T 47575-2026 低空交通管理服务相关国家标准（2026-07-02）

先看这份来源时，要带着一个具体问题：中国低空交通管理服务标准有什么最新节点？

国家标准页面显示 GB/T 47575-2026 于 2026-07-02 发布，2026-09-01 实施。 在 2026-08-30 证据截止日它已发布但尚未实施。 因此，本章采用它来支持这样的判断：必须明确区分发布和生效，提前做接口差距分析。

但它没有替我们回答所有问题。正式适用范围、条文和配套标准需逐项读取；不得写成已实施。

### EASA U-space（2026-08-30）

接着看这份来源时，要带着一个具体问题：欧洲 U-space 如何组织高密度无人机服务？

EASA 官方页面说明 U-space 空域与网络识别、地理感知、飞行授权、交通信息等服务。 提供已运行监管体系的服务分类参考。 因此，本章采用它来支持这样的判断：帮助对照 UTM/UOM 状态和接口。

但它没有替我们回答所有问题。欧盟框架不能替代中国规则，角色和数据要求不同。

### ICAO UTM Guidance（2026-08-30）

最后看这份来源时，要带着一个具体问题：UTM 全球互操作需要哪些共同概念？

ICAO 材料组织 UTM 原则、服务与传统 ATM 协同。 支持跨平台意图/约束交换的共同语义。 因此，本章采用它来支持这样的判断：提供国际比较基线。

但它没有替我们回答所有问题。指导性材料不直接批准某一 BVLOS 运行。

## 如果由你接手，先做哪四步：做一个低空服务失效仿真

### 第 1 步：按任务高度路线实测 C2 分布而非地面覆盖图

- **这一步在验证：** C2 通信能否支持“失链何时触发何种动作”这项判断。
- **至少留下：** 任务成功、航迹/时间/载荷与拒绝率。
- **先停下来而不是继续调参的信号：** 信号格数当可靠性。

### 第 2 步：定义链路/识别/UTM 状态机和时间预算

- **这一步在验证：** 运行识别能否支持“身份、隐私和可信怎样平衡”这项判断。
- **至少留下：** 最小间隔、能量/控制余度、告警与失效覆盖。
- **先停下来而不是继续调参的信号：** 下行好等于上行好。

### 第 3 步：多运营人仿真冲突、迟到和不一致

- **这一步在验证：** UTM/UOM 服务能否支持“服务失效时谁维持安全”这项判断。
- **至少留下：** 定位/感知/C2 延迟、P95/P99、可用性。
- **先停下来而不是继续调参的信号：** 把待实施标准写成已实施。

### 第 4 步：演练服务不可用与机载独立保持间隔

- **这一步在验证：** C2 通信能否支持“失链何时触发何种动作”这项判断。
- **至少留下：** 每航次成本、机队利用、人工、维护与事故暴露。
- **先停下来而不是继续调参的信号：** 服务延迟不进冲突预测。

## 仍需保留的残余风险

先排除这些误解：5G 覆盖即 C2 合格；UTM 等于传统塔台；Remote ID 无隐私权衡；计划去冲突即可无需 DAA；发布标准即已实施。

### 信号格数当可靠性

- **先看什么：** 任务成功、航迹/时间/载荷与拒绝率
- **回到哪项控制：** GB/T 47575 标注 2026-09-01 才实施
- **怎样留下证据：** 保存触发条件、原始输入、系统响应和人工处置；修复后把同一样本加入“做一个低空服务失效仿真”的回归记录。

- **怎样留下证据：** 保存触发条件、原始输入、系统响应和人工处置；修复后把同一样本加入“做一个低空服务失效仿真”的回归记录。

## 把复盘迁移到新场景：做一个低空服务失效仿真

模拟 20 架航空器四维意图，注入 2—10 秒网络延迟和服务中断；报告冲突告警、最小间隔、停止放行和恢复条件。

提交时一并回答：

- 你能否不看正文解释C2、Remote ID 与 UTM 的分工；
- 产物是否真的包含一份失链/服务状态机；
- 哪个失败样本暴露了地面服务不可用时不得继续的运行；
- 如果换一个数据、人群、环境或本体，最先需要重测哪项指标。

提交物不能只有成功截图。附上一个失败样本，并说明它推翻了什么假设、哪些残余风险还不能消除。
