## 为什么现在要学“运行识别：身份、位置与隐私”

很多误判并非算错，而是把两个相近词当成同一件事。围绕 **运行识别**，本章先建立可反驳的定义。

**本章核心判断：** Remote ID 在空域透明与隐私安全间取舍，身份、位置和访问角色需分别设计。

本章只追一个判断：**谁需要识别谁，广播和网络方式各承担什么？** 最后必须用“Remote ID 数据与威胁模型”来回答；如果产物不能暴露失败样本，就还不能算学会。

## 用公式审查“运行识别：身份、位置与隐私”

链路余量 $M=P_t+G_t+G_r-L_{path}-L_{misc}-Sensitivity$；可靠运行关注 $P(latency<L,availability>A)$ 和连续中断长度。冲突概率/间隔必须考虑意图更新延迟和位置协方差。

逐个把符号放回真实任务，并检查：

- 覆盖图与目标高度/上行差异
- 运营商/卫星切换与共因
- 身份数据的访问/留存
- UTM 服务不可用时的运行最小能力

推导完成不代表结论成立。至少改变一次关键条件，观察 **运行识别** 的结论是否保持；若不保持，把条件写入“Remote ID 数据与威胁模型”而不是藏在代码默认值里。

## 沿着一条完整推理链走到底

### 第一步：固定要解释或改变的对象

不要用“整体效果更好”代替对象。把“谁需要识别谁，广播和网络方式各承担什么？”改写为：在明确输入、时间点和约束下，观察什么量，比较什么基线，最后据此采取什么动作。

### 第二步：写出中间机制

上一主题“C2 链路预算、时延与连续性”提供前置条件，本章用 **运行识别** 解释关键机制，并把结果留在“Remote ID 数据与威胁模型”中。下一主题“UTM 如何交换意图与冲突”只在这些证据成立后继续。 只要中间任一环只能凭主观解释，结论就应降级为假设。

### 第三步：主动寻找反例

先尝试制造“服务延迟不进冲突预测”。如果当前方法仍给出看似正常的平均分，说明评价没有覆盖真正风险，需要补切片、过程指标或拒绝条件。

### 第四步：把结论写成可撤回决定

当前决定是“C2 SLO 绑定失链动作”。同时写下适用条件、责任人和重新评审信号；这样新证据出现时能更新，而不是把旧结论当永久规则。

这条推理链最终必须落到 **Remote ID 数据与威胁模型**。只有定义、机制、观察和决定互相对得上，文章内容才真正进入工作系统。

## C2 通信 怎样经过 运行识别 影响结果

C2 从航空器—接入网—核心网—控制站全链路测量 RSRP/SINR、丢包、RTT、抖动和可用性。运行识别提供身份/位置等最小必要信息。UTM/U-space 用服务交换运行计划、空域约束、监视和冲突；机载 DAA 与地面服务是互补防线。

~~~~mermaid

 G --> U[UTM/UOM/USS]
 U --> X[空域约束/意图/冲突]
 X --> G

 H -->|降级| S[机载安全模式]
~~~~

读图时从结果逆向追问：哪一步能够观察，哪一步只是假设，哪一步失效后必须让系统拒绝或降级。

## 当 运行识别 失效，先查哪里

先排除这些看似合理的误解：5G 覆盖即 C2 合格；UTM 等于传统塔台；Remote ID 无隐私权衡；计划去冲突即可无需 DAA；发布标准即已实施。

### 下行好等于上行好

先查看 **安全裕度**：最小间隔、能量/控制余度、告警与失效覆盖。如果证据确认失败，回到“C2 SLO 绑定失链动作”，保存触发输入、系统响应和人工处置，再把样本加入回归集。

### 服务延迟不进冲突预测

先查看 **运行经济**：每航次成本、机队利用、人工、维护与事故暴露。如果证据确认失败，回到“UTM 不作为机载最后安全防线”，保存触发输入、系统响应和人工处置，再把样本加入回归集。

本章的边界不是一句“视情况而定”，而是能写进测试、监测或人工审核条件的触发器。
