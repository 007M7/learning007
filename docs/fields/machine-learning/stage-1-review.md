## 八章其实只完成了一件事

回看续费项目，最初的需求只有一句“预测哪些用户会流失”。它没有说明谁在何时使用结果，也没有说明数据怎样出现。若团队从这句话直接开始调算法，后面得到的每个高分都可能建立在另一项任务上。

八章沿着同一份合同把问题逐步压实。

```text
一项真实决定
    │
    ▼
谁在何时处理什么对象                       第 1 章  问题定义
    │
    ▼
当时能看见什么，结果何时确认               第 2 章  样本契约
    │
    ▼
两类错误与后续动作分别付出什么             第 3 章  决策成本
    │
    ▼
怎样用独立数据检验下一批对象               第 4 章  泛化实验
    │
    ▼
一行记录经过哪些筛选与行动才会出现         第 5 章  数据生成
    │
    ▼
现实结果怎样变成标签，哪些答案不可确认     第 6 章  标签测量
    │
    ▼
测试准备模拟哪一种时间、对象与环境         第 7 章  切分协议
    │
    ▼
信息是否绕过边界进入训练与选择             第 8 章  泄漏审计
```

八张表之间存在明确依赖，后一项建立在前一项的边界上。

没有问题定义，样本不知道冻结在哪个时刻。没有样本时间，标签与未来字段无法区分。没有行动成本，指标改进无法转化为选择。没有目标未来，测试切分只是随机抽签。没有数据生成图，团队看不见是谁获得了曝光和标签。没有这些边界，泄漏审计也只能按字段名猜测。

因此，第一阶段最终学到的核心判断可以压缩成一句话。

> 机器学习实验在一套真实流程中，用受保护的历史证据模拟一个未来决定。算法只在这套边界清楚以后才开始比较。

## 可信实验包里应当留下什么

八章各自产出一份可以交接的材料。它们共同解释实验结论的来路。

| 产物 | 它固定的判断 | 缺少以后最常见的后果 |
|---|---|---|
| 问题定义卡 | 使用者、对象、决策时刻、动作、容量、基线与停止条件 | 模型有分数却没有可执行位置 |
| 样本与时间契约 | 样本单位、特征截止、可用时间、标签窗口与成熟日 | 未来信息和未成熟结果进入训练 |
| 成本与行动表 | 现实状态、可选动作、错判代价、容量与拒绝条件 | 准确率提高却让业务付出更多 |
| 泛化实验说明 | 训练、验证、测试职责，简单基线与测试打开历史 | 团队把开发反馈误写成未来能力 |
| 数据生成过程图 | 准入、曝光、处理、记录、结果确认与反馈 | 表格变化找不到真实流程原因 |
| 标签规范 | 目标构念、代理标签、来源、缺失、争议与版本 | 空白被填成零，测量偏差被当作事实 |
| 切分协议 | 时间、群组、环境隔离与预处理拟合边界 | 近亲样本让测试世界过于容易 |
| 泄漏审计与回归集 | 数据谱系、攻击测试、修复和永久门禁 | 同类漏洞换一条字段再次出现 |

一份产物不必很长。它的价值在于能让另一位不了解项目的人复述约定，找到证据，并知道什么变化会使它失效。

可信实验包会随流程变化而更新。产品改变提醒时点，要回到数据生成图和样本时间。支付渠道变化，要重审标签来源。公司进入新地区，要修改目标总体与环境切分。测试结果被用于改模型，要更新实验历史并准备新的独立留出。

## 三条边界贯穿了整个阶段

八章反复使用时间、实体和行动三条边界。

### 时间边界保护当时真实可见的世界

决策时刻把输入与未来分开，数据可用时间又把“已经发生”和“系统能够读取”分开。标签成熟日保证结果窗口已经结束，时间留出则保证测试发生在开发以后。

检查时间边界时，始终问三件事。

1. 模型具体在什么时刻作答。
2. 某条信息在那个时刻是否已经到达运行系统。
3. 用来核对的结果何时才完整成熟。

退款状态、结案原因和迟到工单是否泄漏，都由这三项事实决定，不能由字段名字决定。

### 实体边界保护测试对象的新颖性

一行是一份合同，不代表每行彼此独立。同一客户、家庭、设备、企业付款账户或复制文档会把近似信息带到集合另一边。

检查实体边界时，要先写清系统准备面对老对象的下一次事件，还是从未见过的新对象。前者可以允许某些历史重叠，仍要保护时间；后者需要把共享身份与来源的记录整体隔离。

### 行动边界保护预测与干预的区别

风险分数描述在当前流程下某个结果出现的可能性。运营是否提醒、发券或人工检查，是另一个决定。行动会改变结果，也会进入下一轮训练数据。

检查行动边界时，要分别保存预测、入选政策、人工决定、实际动作与最终结果。模型能找出高风险对象，不代表某个动作对这些对象有效。若要比较行动效果，需要实验或因果设计，第四阶段会专门处理。

时间、实体和行动三条边界能够解释第一阶段的大部分错误。遇到新的字段或实验结果时，先问它穿过了哪条边界，往往比先问该用什么算法更有效。

## 用一个新场景完成迁移

下面换一个没有在正文里出现的任务。

一家工厂希望预测设备是否会在未来七天故障。维修团队每天早上只有二十个巡检名额。数据库保存传感器读数、维修工单、更换零件记录和停机原因。同一台设备每小时生成一行数据，故障后维修人员会补写工单，部分老设备在夜班时经常离线。新工厂将在三个月后接入系统。

不要先选模型。请为它组装第一版可信实验包。

### 第一步把愿望放进一次决定

至少写清下面这些事实。

- 预测单位是一台设备、一个部件，还是一个小时窗口。
- 每天什么时刻生成巡检名单。
- 未来七天的故障怎样定义，计划停机是否算故障。
- 二十个名额怎样使用，漏检和白查分别带来什么代价。
- 当前维修团队依靠哪条规则安排巡检。

完成以后，应该得到一句可执行任务。“预测设备故障”还缺少上述约定。

### 第二步沿一台设备画出时间与生成过程

挑一台设备，把传感器事件发生、上传、特征快照、巡检、维修和故障确认放到同一条时间线。夜班离线设备为什么缺数据，接受巡检的设备为什么拥有更多维修记录，都要在图里出现。

特别检查故障后补写的停机原因。今天查询时它很完整，早上作答时却不存在。更换零件记录也要区分计划更换与预测触发的更换，后者会进入反馈回路。

### 第三步设计三种未来

为任务准备三套切分。

1. 时间外推，用较早月份训练，后移月份测试，输入与结果窗口之间保留必要间隔。
2. 设备外推，同一台设备的所有窗口整体移动，检验新设备冷启动。
3. 工厂外推，把一个完整工厂留出，检验新环境迁移。

近期部署若只在现有工厂运行，时间外推是主报告。公司要为新工厂采购系统，工厂外推就不能只作为附录。三套分数不需要平均，每一套都对应一个不同承诺。

### 第四步为最可疑的高分设计攻击

假设模型突然获得 95% 的故障识别率。至少运行下面四项攻击。

- 删除故障后才补写的工单与停机原因。
- 把全部特征还原到早上名单生成时的可用状态。
- 扩大设备群组，避免同一部件的相邻窗口跨集合。
- 打乱测试标签，确认训练产物和转换参数完全不变。

每项攻击都要写明预期。删除未来字段后成绩下降是正常修复，标签打乱后仍然高分则说明管道或评测有严重问题。

## 先找到最薄弱的一环

可信实验包不要求八份材料同样精美。项目推进取决于最薄弱又最关键的一环。

| 发现的缺口 | 此时最合理的动作 |
|---|---|
| 使用者和动作仍然不清楚 | 回到业务流程，不开始训练 |
| 历史可用状态无法重建 | 优先建设快照或事件时间，不把今天的表当过去 |
| 大量标签不可确认 | 补采与抽样核对，暂时缩小适用范围 |
| 新环境没有任何历史数据 | 使用简单规则或小规模试运行，不报告普遍能力 |
| 测试已经反复参与选择 | 把它降为开发数据，等待新的独立留出 |
| 新模型没有稳定超过简单基线 | 保留基线，调查数据与任务，不用复杂度掩盖缺口 |

这张表体现了一种重要能力。知道何时不应该继续训练，也属于机器学习判断。数据条件尚未成立时，增加算法复杂度只会更快适应错误证据。

## 阶段自检

先合上前八章，尝试用自己的话回答。

1. 为什么一条数据库记录不自动等于一条训练样本。
2. 为什么“没有标签”和“标签为零”需要不同处理。
3. 为什么随机切分分数高于时间切分，不能直接说明后者实现有误。
4. 为什么测试标签没有进入训练代码，测试集仍然可能被污染。
5. 为什么模型上线后，下一轮数据不再是原流程的被动记录。

若只能复述术语，回到一个具体对象，沿它经历的时间与系统重新讲一遍。能够指出对象、记录、动作和证据，才算真正理解。

## 什么时候可以进入第二阶段

达到基础掌握时，你应当能够独立完成下面四件事。

- 把一个模糊需求改写成有对象、时点、动作、容量和基线的任务。
- 为一条样本画出输入截止、标签成熟和数据生成过程。
- 根据部署场景设计至少一套主切分，并说明它不能代表什么。
- 找到一条可疑信息路径，设计攻击，并把修复写成回归门禁。

达到熟练掌握时，你还应当能把同一方法迁移到陌生领域，比较多种未来场景，并在证据不足时主动缩小结论与上线范围。

第一阶段尚未教会你线性模型、树模型、优化器和自动选型。它为这些内容建立了比赛场地。下一章从线性回归开始，研究一个模型怎样把目标投影到特征空间，以及残差如何暴露假设没有解释的结构。后续每一种算法都必须在本阶段保护好的数据、决策和评估边界里比较。
