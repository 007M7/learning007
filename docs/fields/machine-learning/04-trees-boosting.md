# 04 · 决策树、集成与梯度提升

> 树模型强在对表格数据的缺失、非线性和交互具有合适归纳偏置，但特征重要性、概率和分布外行为仍需单独验证。

## 先别问谁最好，先问你在优化什么

> 树模型为什么仍是表格数据的强基线，何时又会失败？

表格业务数据混合连续、类别、缺失和阈值规则。树能在不标准化的情况下表达非线性交互，boosting 又把许多弱树叠成强模型。但高基数 ID、未来代理变量和稳定的实体特征会让树更容易记忆；默认 feature importance 还会偏爱可分裂次数多的变量。

## 把选择拆成三条判断轴

| 知识节点 | 先用一句话说清 | 什么时候值得选择它 | 先排除的误解 |
|---|---|---|---|
| MLF10 · 决策树 | 以分裂规则递归划分特征空间并在叶子估计 | 规则交互是否适合轴对齐分区 | 树不需要任何数据治理 |
| MLF11 · Bagging | 对重采样模型平均以降低高方差 | 稳定性收益是否值得并行成本 | 随机森林一定不会过拟合 |
| MLF12 · Boosting | 逐步拟合梯度/残差以构造加法模型 | 偏差降低、过拟合与延迟如何平衡 | boosting 轮数越多越好 |

读表时不要横向背三行。任选一行，把“定义—决定—反例”连成一句因果解释；然后把本章案例中的一个输入替换掉，检查原判断是否仍成立。

## 判断树：递归分区、方差降低与函数梯度下降

单树选择使纯度或损失下降最大的切分，并在叶节点输出均值/概率。随机森林通过样本与特征随机性降低树间相关，从而降低方差。梯度提升维护加法模型 $F_m$，每轮用新树拟合当前损失对预测的负梯度；学习率、树深、叶样本和轮数共同控制容量。CatBoost 的有序目标统计用于降低类别目标编码泄漏。

  B -->|拟合梯度串行| GB[Boosting]
  RF --> E[平均/投票]
  GB --> E
  E --> C[校准/切片/延迟]
  C --> G[GBDT 与其他基线门禁]

## 不要让一个分数替你做决定

回归树分裂可写为

$$
\min_{j,s}\left[\sum_{x_i^j\le s}(y_i-c_1)^2+\sum_{x_i^j>s}(y_i-c_2)^2\right].
$$

梯度提升更新：

$$
F_m(x)=F_{m-1}(x)+\eta h_m(x),\quad
h_m\approx-\frac{\partial \ell(y,F)}{\partial F}\bigg|_{F_{m-1}}.
$$

把每个符号放回真实系统。下面任何一项说不清，计算正确也不能保证结论正确：

- 贪心分裂不是全局最优树
- bagging 只有在基学习器误差不完全相关时有效
- boosting 的迭代轮数与学习率不能分别孤立解释
- 类别统计必须严格保持时间/折内因果顺序

## 做到什么，才算结果可信

| 观察维度 | 要留下的记录 | 它防止你误判什么 |
|---|---|---|
| 任务 · 决策树 | 主指标、切片指标、无效/拒绝比例 | 避免平均分掩盖关键用户或条件；本章还要据此判断：规则交互是否适合轴对齐分区 |
| 可靠性 · Bagging | 校准、方差、置信区间、最坏切片 | 知道预测何时不可直接行动；本章还要据此判断：稳定性收益是否值得并行成本 |
| 资源 · Boosting | 训练/推理时间、内存、能耗或费用 | 确认提升不是无限预算换来的；本章还要据此判断：偏差降低、过拟合与延迟如何平衡 |
| 运维 · 决策树 | 漂移、缺失、延迟、人工接管和回滚 | 把离线模型放回真实系统；本章还要据此判断：规则交互是否适合轴对齐分区 |

## 不要只看宣传：两份可核验依据

公开结果可以帮助设置基线，却不能替代你自己的数据、预算和失败代价。

### XGBoost: A Scalable Tree Boosting System（2016-06-10）

**它追问什么：**怎样把正则化树提升做成能处理稀疏数据并高效扩展的系统？

**方法和结果：**XGBoost 使用二阶损失近似、结构正则、稀疏感知分裂、加权分位数草图和缓存友好实现。论文同时讨论算法目标与系统优化，而不是只给模型公式。 作者在多类公开任务展示准确性与规模优势，并报告系统层吞吐。

**它改变的判断：**贡献是把 boosting 的目标、缺失方向和工程并行结合成可复用系统。

> **不要越过这条边界：**原论文年代较早；现代 CatBoost、LightGBM 和表格基础模型需要在同一预算下重测。

### Beyond IID: How General Are Tabular Foundation Models, Really?（2026-06-29）

**它追问什么：**表格基础模型在非 IID、大样本和高维任务是否仍稳定领先树模型？

**方法和结果：**BeyondArena 汇集 IID、时间、群组、多特征类型与规模变化的 142 个数据集，比较 11 个模型，并配套 Data Foundry 统一元数据和运行协议。 作者报告基础模型在小到中型 IID 数据强，但传统树/深度模型在非 IID、大规模和高维场景仍占优。

**它改变的判断：**贡献是把基准从基础模型擅长的区域扩到真实困难区域。

> **不要越过这条边界：**预印本和统一框架可能无法包含每个模型的最优领域调参；排名不能替代本地任务对照。

## 一次有约束的选择：客户续费概率

数据包含套餐、使用量、工单、合同期限和地区。逻辑回归先提供可解释基线；CatBoost 处理高基数类别，XGBoost 使用显式编码。时间切分模拟下月续费，客户 ID 永不作为特征。比较不仅看 AUC，还看概率校准、前 5% 营销容量内增益、推理 P95、模型大小和重要性在不同时间窗的稳定性。

### 读案例时做三次停顿

1. 到 决策树 时停一次：规则交互是否适合轴对齐分区？
2. 到 Bagging 时再停一次：哪条数据流、状态变化或约束能证明机制真的发生？
3. 到 Boosting 时最后停一次：如果出现“把高基数 ID 当正常类别”，系统应继续、拒绝还是交给人？

## 做一次公平对照：解释排名为什么会翻转

### 第 1 步：固定训练/验证/测试与总调参次数

- **这一步在验证：**决策树能否支持“规则交互是否适合轴对齐分区”这项判断。
- **至少留下：**主指标、切片指标、无效/拒绝比例。
- **先停下来而不是继续调参的信号：**把高基数 ID 当正常类别。

### 第 2 步：比较单树、随机森林、XGBoost/CatBoost 和线性模型

- **这一步在验证：**Bagging能否支持“稳定性收益是否值得并行成本”这项判断。
- **至少留下：**校准、方差、置信区间、最坏切片。
- **先停下来而不是继续调参的信号：**验证集上无限早停/调参。

### 第 3 步：画随树数/深度变化的学习曲线与训练时间

- **这一步在验证：**Boosting能否支持“偏差降低、过拟合与延迟如何平衡”这项判断。
- **至少留下：**训练/推理时间、内存、能耗或费用。
- **先停下来而不是继续调参的信号：**用 impurity importance 声称因果重要。

### 第 4 步：比较 gain、permutation 和 SHAP 排名，并对相关特征构造反例

- **这一步在验证：**决策树能否支持“规则交互是否适合轴对齐分区”这项判断。
- **至少留下：**漂移、缺失、延迟、人工接管和回滚。
- **先停下来而不是继续调参的信号：**只比较默认线性模型与精调 boosting。

## 什么信号会推翻当前选择

先排除这些误解：树不需要任何数据治理；随机森林一定不会过拟合；boosting 轮数越多越好；SHAP 等于因果贡献；最新基础模型已经淘汰 GBDT。

### 把高基数 ID 当正常类别

- **先看什么：**主指标、切片指标、无效/拒绝比例
- **回到哪项控制：**表格任务默认保留 GBDT 强基线
- **怎样留下证据：**保存触发条件、原始输入、系统响应和人工处置；修复后把同一样本加入“解释排名为什么会翻转”的回归记录。

### 验证集上无限早停/调参

- **先看什么：**校准、方差、置信区间、最坏切片
- **回到哪项控制：**模型选择使用预算相同的嵌套验证而非各跑默认值
- **怎样留下证据：**保存触发条件、原始输入、系统响应和人工处置；修复后把同一样本加入“解释排名为什么会翻转”的回归记录。

### 用 impurity importance 声称因果重要

- **先看什么：**训练/推理时间、内存、能耗或费用
- **回到哪项控制：**类别编码、缺失方向和单调约束进入模型合同
- **怎样留下证据：**保存触发条件、原始输入、系统响应和人工处置；修复后把同一样本加入“解释排名为什么会翻转”的回归记录。

### 只比较默认线性模型与精调 boosting

- **先看什么：**漂移、缺失、延迟、人工接管和回滚
- **回到哪项控制：**解释性结论必须附相关特征和扰动稳定性
- **怎样留下证据：**保存触发条件、原始输入、系统响应和人工处置；修复后把同一样本加入“解释排名为什么会翻转”的回归记录。

### 忽略树模型概率同样可能失准

- **先看什么：**主指标、切片指标、无效/拒绝比例
- **回到哪项控制：**表格任务默认保留 GBDT 强基线
- **怎样留下证据：**保存触发条件、原始输入、系统响应和人工处置；修复后把同一样本加入“解释排名为什么会翻转”的回归记录。

## 证据改变时怎样重选

### 1. 表格任务默认保留 GBDT 强基线

验收时查看 **任务**，至少保存主指标、切片指标、无效/拒绝比例。如果观察到“把高基数 ID 当正常类别”，这项决定必须重新评审，不能因为已经实现就默认保留。

### 2. 模型选择使用预算相同的嵌套验证而非各跑默认值

验收时查看 **可靠性**，至少保存校准、方差、置信区间、最坏切片。如果观察到“验证集上无限早停/调参”，这项决定必须重新评审，不能因为已经实现就默认保留。

### 3. 类别编码、缺失方向和单调约束进入模型合同

验收时查看 **资源**，至少保存训练/推理时间、内存、能耗或费用。如果观察到“用 impurity importance 声称因果重要”，这项决定必须重新评审，不能因为已经实现就默认保留。

### 4. 解释性结论必须附相关特征和扰动稳定性

验收时查看 **运维**，至少保存漂移、缺失、延迟、人工接管和回滚。如果观察到“只比较默认线性模型与精调 boosting”，这项决定必须重新评审，不能因为已经实现就默认保留。

## 本章小结

- 单树、bagging 和 boosting解决不同误差来源
- 表格模型比较必须包含预算与非 IID 场景
- 重要性是模型行为描述而非因果结论
- 树模型仍需校准、切片和生产验证
