## 为什么现在要学“模型选型不是排行榜：画出 Pareto 前沿”

先别问“谁最好”。质量、延迟、成本、可解释和维护性冲突时怎样选？ 只有把约束、失败代价和退出条件放在同一张表里，选择才有意义。

**本章核心判断：** 模型选择是质量、校准、延迟、成本、可解释和维护性的多目标决策，不是排行榜取第一。

本章只追一个判断：**质量、延迟、成本、可解释和维护性冲突时怎样选？** 最后必须用“多目标选择记录与淘汰理由”来回答；如果产物不能暴露失败样本，就还不能算学会。

## 沿着一条完整推理链走到底

### 第一步：固定要解释或改变的对象

不要用“整体效果更好”代替对象。把“质量、延迟、成本、可解释和维护性冲突时怎样选？”改写为：在明确输入、时间点和约束下，观察什么量，比较什么基线，最后据此采取什么动作。

### 第二步：写出中间机制

上一主题“表格基础模型的先验从哪里来”提供前置条件，本章用 **AutoML** 解释关键机制，并把结果留在“多目标选择记录与淘汰理由”中。下一主题“预测问题与因果问题的分水岭”只在这些证据成立后继续。 只要中间任一环只能凭主观解释，结论就应降级为假设。

### 第三步：主动寻找反例

先尝试制造“给基础模型更多预训练知识却称数据相同”。如果当前方法仍给出看似正常的平均分，说明评价没有覆盖真正风险，需要补切片、过程指标或拒绝条件。

### 第四步：把结论写成可撤回决定

当前决定是“任何冠军必须通过非 IID、概率与资源门禁”。同时写下适用条件、责任人和重新评审信号；这样新证据出现时能更新，而不是把旧结论当永久规则。

这条推理链最终必须落到 **多目标选择记录与淘汰理由**。只有定义、机制、观察和决定互相对得上，文章内容才真正进入工作系统。

## 当 AutoML 失效，先查哪里

先排除这些看似合理的误解：基础模型等于任何数据都通用；不做梯度训练等于没有计算成本；AutoML 消除了实验设计；总体平均排名可直接采购；点预测最强就最可靠。

### 把一次前向称为零成本

先查看 **运维**：漂移、缺失、延迟、人工接管和回滚。如果证据确认失败，回到“任何冠军必须通过非 IID、概率与资源门禁”，保存触发输入、系统响应和人工处置，再把样本加入回归集。

### 给基础模型更多预训练知识却称数据相同

先查看 **任务**：主指标、切片指标、无效/拒绝比例。如果证据确认失败，回到“建立任务形态路由而非统一默认模型”，保存触发输入、系统响应和人工处置，再把样本加入回归集。

本章的边界不是一句“视情况而定”，而是能写进测试、监测或人工审核条件的触发器。
