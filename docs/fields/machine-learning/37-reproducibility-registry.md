## 一笔被投诉的预测为何重放不出来

某风险模型在三个月前把一笔订单送入人工审核。客服现在需要解释原因。团队找到了模型文件，也找到了订单编号，重新运行后的分数却从 0.74 变成 0.58。

差异可能来自很多位置。训练表每天覆盖，类别字典已经增加新值，特征代码读取了当前汇率，依赖库升级改变缺失处理，线上阈值也从 0.70 调到 0.60。模型文件相同，只能证明一小部分计算没有变。

需要重放的对象其实有三层。训练重放要从固定输入重新产生模型工件，评价重放要恢复当时的切分、指标和门槛，预测重放要恢复某次请求实际看见的特征、模型与政策。三层共享版本链，验收标准不同。

本章的交付物是一份可复现实验包和一张模型登记卡。它们要回答模型从哪里来、为什么获准使用、一次行动怎样产生、出现问题时回到哪个稳定状态。

## 先定义足够一致，不追求字节神话

某些训练能做到字节完全一致，例如固定代码、确定性算法、单线程 CPU 和相同依赖。分布式 GPU 训练可能受并行归约、内核和硬件影响，只能得到数值接近或指标等价的结果。

因此，团队需要为每类重放预先定义容差。

| 重放类型 | 必须固定的输入 | 可接受结果 |
|---|---|---|
| 数据构建 | 原始对象版本、查询、时间边界、过滤规则 | 行集合与统计摘要一致 |
| 训练运行 | 数据、代码、环境、配置、随机种子 | 工件摘要一致，或参数和评价在容差内 |
| 离线评价 | 模型、测试集、切片、阈值、指标实现 | 报告可重算且差异可解释 |
| 单次预测 | 原始请求、特征快照、模型、政策、依赖服务 | 分数、拒绝和动作一致 |

“足够一致”必须在运行前定义。事故后扩大容差，只会把不可解释差异改名为正常波动。

## 数据版本要保存内容和生成规则

一个文件路径不是数据版本。路径指向的内容可能被覆盖，数据库查询也会随迟到记录、删除和维表更新改变。可靠快照需要不可变对象标识、内容摘要、模式、查询或构建代码、有效时间和采集截止时间。

训练数据还要保存行级身份或可验证的分区摘要。若出于隐私不能长期保留完整样本，可以保存受控快照、加密引用、行数、键摘要、分布统计和删除记录。可复现要求不能取消数据主体的删除权，删除后的重放应明确降级范围。

标签成熟时间尤其重要。七天结果在第三天重建，得到的是尚未成熟的数据。快照清单需要区分事件时间、进入系统的时间和被用于训练的时间，才能判断当时是否读取了未来信息。

数据版本的验收不是“文件还在”。用同一清单重新构建时，系统应主动检查模式、主键、时间范围、缺失率、标签成熟度和关键切片，任何差异都进入报告。

## 特征版本需要语义，不只需要列名

训练和服务都出现 `order_amount_30d`，仍可能计算不同。训练端按自然日聚合，服务端按最近 720 小时聚合；训练端包含退款后金额，服务端使用下单金额；训练端事后补齐迟到事件，服务端只能看到预测时已到达记录。

特征契约应记录业务定义、数据源、事件时间、可见性截止、窗口、单位、缺失默认、类别字典、拟合状态和实现摘要。标准化器、编码器和特征选择器都属于模型输入语义，要随模型一起登记。

可以用事件回放验证契约。选择一批历史预测时点，只开放当时已经到达的数据，分别运行离线和在线实现，再比较每个特征。差异不能只看均值，单位错误和少数类别映射失败常被总体统计掩盖。

## 一次训练运行由清单串起来

训练运行清单是机器可读的事实记录。它至少引用以下内容。

- 任务和标签定义版本
- 数据快照与切分版本
- 特征契约和转换工件
- 代码提交与未提交差异
- 容器或环境锁文件
- 全部配置、随机种子和硬件类型
- 训练日志、评价报告和最终工件摘要
- 父模型、运行发起者和审批记录

代码提交不足以描述运行。配置可能来自命令行和环境变量，镜像标签可能被覆盖，外部预训练模型也可能静默更新。清单应引用不可变摘要，并对秘密只保存名称与版本，不记录明文。

训练结束后，从一个干净环境执行重放。若必须依赖开发者本机缓存才能成功，实验包尚未独立。若外部数据或服务不可冻结，要保存响应快照并声明只能近似重放。

## 模型登记卡记录为什么允许进入下一步

模型登记不是模型文件仓库。登记项把工件、血缘、评价、风险和生命周期放在一起，让团队知道一个版本能在哪里使用。

一张可执行的登记卡包含模型标识与摘要、父运行、任务和目标人群、训练时间范围、特征契约、评价集与切片、校准状态、拒绝策略、已知限制、负责人、审批状态、部署位置和退役时间。

状态也要有含义。候选表示训练完成，已验证表示通过固定离线门槛，影子表示接触真实输入但不影响动作，金丝雀表示只影响受控流量，生产表示已承担明确责任，归档表示禁止新调用但保留审计。

状态迁移由证据触发。上传文件不能自动变成已验证，离线得分也不能直接变成生产状态。每次迁移保存门槛结果和批准人，失败候选同样保留，避免团队反复重走已知死路。

## 阈值和政策必须成为一等版本

模型输出 0.74，最终是否审核还取决于阈值、容量、黑白名单、拒绝区和人工规则。这些内容改变行动，却经常藏在服务配置中。

应把模型版本与政策版本分开。模型更新时可以保持政策不变，阈值更新时也可以保持模型不变。这样评价才能判断变化来自排序、校准还是决策边界。

政策清单记录阈值、分组条件、资源上限、冲突优先级、人工接管、默认动作、生效时间和审批依据。回滚目标也由模型、特征和政策的兼容组合组成，只回滚权重可能继续使用新阈值和新特征，无法恢复旧行为。

## 预测日志保存引用，也尊重最小化原则

每次线上预测至少产生请求标识、事件时间、实体引用、特征契约版本、必要特征快照、模型版本、政策版本、原始输出、最终动作和追踪标识。外部服务响应或检索结果参与预测时，也需要可重建引用。

日志不能无期限复制全部敏感输入。团队应按重放目的选择字段，使用访问控制、加密、保留期和删除流程。对不能保存的内容，记录摘要、来源版本和无法完整重放的边界。

重放工具读取一条预测记录，在隔离环境加载对应工件，重新计算特征、分数和政策动作，再输出逐层差异。它不仅给出一致或失败，还要指出差异最先出现在哪一层。

```text
request 8f3a
  data snapshot     ds_2026_07_01@sha256
  feature contract  fc_18
  model             risk_42
  policy            review_7
  score             0.7421
  action            manual_review
```

## 用三次演练验收可复现实验包

第一次演练从训练运行开始。清空本地缓存，只提供运行清单和受控凭证，重建数据、训练模型并复算评价。记录时间、容差和所有不可冻结依赖。

第二次演练重放一个正常预测和一个拒绝预测。系统逐层比较原始请求、特征、分数与动作。若分数一致而动作不同，优先检查政策和时间生效规则。

第三次演练故意把金额单位从元改为分，再将模型和政策分别回滚。门禁应在模式或范围检查时阻断错误。完整回滚要恢复兼容的特征、模型和政策组合，并证明服务仍能接收当前请求。

演练结果写入登记卡。无法重放的原因要形成修复任务，例如缺少字典版本、镜像标签可变或日志不含政策标识。

## 可复现与性能、隐私和成本之间有取舍

保存每个输入快照能提高调查能力，也增加存储和隐私风险。固定所有执行细节能提高确定性，也可能阻碍安全补丁。长期保存旧环境可能暴露已知漏洞。

解决办法是分层保留。高风险决策保存更完整的受控证据，低风险批量预测保存摘要和抽样快照。旧环境放入隔离仓库，只用于重放，不重新暴露公网。模型退役后保留最小审计包，并按制度删除原始敏感数据。

可复现也不等于正确。一个有泄漏的实验可以被完美重放，一个带歧视政策的决策也可以被完整追踪。版本链提供追责和修复基础，评价、因果和公平判断仍来自前面阶段。

## 与 AI 协作检查版本缺口

AI 可以比较训练代码与运行清单，寻找未记录配置、可变依赖和离在线特征差异。给它一条预测追踪，它可以生成重放步骤和差异定位表。

AI 不应获得生产秘密或无边界读取用户日志。它也不能把日志可得误解为保存合法。涉及保留期限、访问权和删除义务时，由数据与安全责任人确认。

## 本章交付

完成一份可复现实验包。它包含不可变数据引用、特征契约、运行清单、环境锁定、评价报告、模型工件和重放命令。再完成一张模型登记卡，记录状态、证据、限制、负责人和兼容政策。

基础掌握要求你能重建一次离线运行，并解释确定性重放与指标等价重放的差别。熟练掌握要求你能从任意线上动作追到输入、特征、模型和政策，完成故障注入与组合回滚。

下一章会使用这套版本链，让候选模型先接触真实输入，再以有限影响逐步进入生产。
