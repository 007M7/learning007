# 14 · Bagging 与随机森林为什么降方差

## 把上一章的一棵树重跑三十次

客服超时任务中的单棵树在一次切分上表现不错。团队更换随机种子并略微调整训练样本后，根节点在复杂度、队列长度和进入时段之间来回变化。测试 AUC 有时是 0.76，有时只有 0.68。

这类变化来自树的高方差。它会认真追随训练数据中的局部差异。数据换一小部分，第一刀改变，后面的分区随之重建。

Bagging 的做法很直接。从原训练集有放回抽样，构造许多同样大小的 bootstrap 数据集。每份数据训练一棵较深的树，最后对预测平均或投票。一棵树可能偏向某些样本，其他树会看到不同组合。

这里有一个容易误解的地方。Bagging 不是把一棵好树复制很多遍。若每棵树训练数据、特征和算法完全相同，它们会给出相同预测，平均没有任何收益。集成需要成员之间有差异，也需要这些成员保留足够预测能力。

## 平均为什么可能降低方差

先想象 $B$ 个预测器在同一对象上的误差方差都是 $\sigma^2$，任意两者误差相关系数约为 $\rho$。平均预测的方差可以写成

$$
\operatorname{Var}(\bar f)\approx \rho\sigma^2+\frac{1-\rho}{B}\sigma^2
$$

第二项会随树的数量增加而下降，第一项不会。若树之间完全独立，$\rho=0$，方差接近缩小为原来的 $1/B$。若树完全同涨同跌，$\rho=1$，平均后方差几乎不变。

这个式子给随机森林的设计提供了方向。增加树数主要压低可平均掉的部分，降低树间相关性则压低无法被树数解决的部分。树数足够后继续增加，性能常趋于稳定，计算与存储成本仍会增加。

平均通常不显著降低所有偏差。若数据遗漏了关键变量，每棵树都看不见，森林也看不见。若训练标签系统性错误，所有树会共同学习错误关系。集成擅长处理采样造成的波动，不能修复共同的数据盲区。

## Bootstrap 怎样制造不同训练世界

原训练集有 $n$ 个样本，每次有放回抽取 $n$ 次。一些样本会重复出现，一些没有被抽中。随着 $n$ 增大，一棵树的 bootstrap 样本大约包含 63.2% 的不同原样本，其余约 36.8% 没有参与该树训练。

没被抽中的部分叫袋外样本。对训练集中的某个对象，只汇总那些没有见过它的树的预测，便得到袋外预测。所有对象的袋外预测可以估计泛化误差，无需额外拿走一整块训练数据。

OOB error 很有用，也有适用边界。它继承 bootstrap 的近似独立同分布假设。时间序列里从未来抽样训练、再预测较早对象，会破坏时间方向。多个样本属于同一客户或设备时，普通行级 bootstrap 也可能让关联对象跨越袋内外。此时需要分组 bootstrap、块 bootstrap，最终仍应保留符合部署条件的时间外测试。

袋外结果也会被调参使用。若团队反复根据 OOB error 选择特征、深度和随机种子，它已经承担验证集角色，不能再当未经接触的最终证据。

袋外覆盖还应逐样本检查。树数较少或抽样比例特殊时，不同对象获得的袋外预测数量可能差异明显。只有几棵树参与的对象，其 OOB 概率波动会很大。保存每个对象的袋外票数，设置最低覆盖门槛，再计算总体指标，能避免少量不稳定预测混入结论。

## 随机森林为什么还要限制每次可见特征

普通 Bagging 的每棵树在每个节点都能查看全部特征。若某个强特征总能带来最大纯度改善，大多数树会在根部选择它，树之间仍然高度相似。

随机森林在每个分裂节点随机抽取一部分特征作为候选。强特征有时不会出现，树被迫探索其他可用路径。这可能让单棵树稍弱，却降低树间相关性，平均后反而更稳。

候选特征数太大，森林接近普通 Bagging。候选数太小，成员差异增加，但单树可能经常看不到有用信息。这个参数应和叶节点大小、样本抽样比例一起通过正确的验证设计选择。

随机子空间也会改变解释结构。某棵树未使用关键特征，可能只是该节点没有抽到它。森林里的单条路径因此缺少单树规则的稳定含义。若业务必须阅读规则，可以另外训练一棵代理树概括森林预测，并明确它只是近似摘要，同时报告代理树与森林的一致率。

类别极不平衡时，还要观察每棵 bootstrap 样本包含多少正类。极少数事件可能在某些树中几乎消失。可以采用分层抽样或平衡随机森林，但任何改变训练类别比例的方案都要重新检查概率校准。

## 三种稳定性要分开测量

“随机森林更稳定”需要指出稳定在哪里。

第一种是训练随机性。固定同一训练集，更换 bootstrap 与特征抽样种子，记录测试预测和指标的变化。第二种是样本扰动。对训练时间窗口或客户集合做重采样，观察模型是否依赖少数对象。第三种是环境变化。把模型放到更晚月份或新渠道，检查数据生成过程变化后的表现。

森林通常能明显改善前两种波动，对第三种没有保证。若九月客服流程更改，所有树仍基于旧流程，成员数量再多也无法提供新规则。

只报告五个随机种子的平均 AUC 也不够。应同时展示标准差、最差值和对象级预测的分散程度。两个模型平均 AUC 相同，其中一个在关键客户上的风险分数随种子剧烈跳动，运营体验完全不同。

## 做一次树间相关、OOB 与方差对照

使用上一章相同的数据边界，训练四组模型。

| 模型 | 目的 | 需要固定的条件 |
|---|---|---|
| 剪枝单树 | 解释性基线 | 深度与剪枝规则 |
| 深单树 | 观察高方差 | 叶节点与特征处理 |
| Bagging | 测试重采样平均 | 树数、样本比例 |
| 随机森林 | 测试去相关收益 | 每节点候选特征数 |

每组至少运行三十个种子。记录测试指标分布、单个样本预测标准差、训练时间与推理时间。对 Bagging 和随机森林，从树预测矩阵中抽样计算成对相关性。再画树数从 1 增长到 500 时，OOB error 与测试误差怎样变化。

对象级方差图能补足总体指标。选择若干稳定预测、种子分歧和高代价错误的工单，画出三十次运行的概率分布。总体 AUC 波动很小，仍可能有一批临界对象在不同运行中反复跨越行动阈值。若这些对象进入自动决策，应使用概率平均、阈值缓冲或人工拒绝区处理。

为了看清机制，安排两次消融。第一次保持树数不变，只改变每个节点可见的特征数，观察单树强度与树间相关的交换。第二次保持特征策略不变，只增加树数，找出性能进入平台而成本继续增长的位置。

最后注入一个共同盲区。删除一项关键流程特征，或让测试集来自流程改变后的月份。若所有集成方法一起退化，报告应明确写出“降低方差不等于抵抗分布变化”。

资源比较也应随实验保留。树数增加会线性推高模型体积和推理工作量，具体增长受实现与并行方式影响。记录平台机型、线程数、批量大小和延迟分位数，才能判断平台以后那几十棵树是否值得。只看离线训练时间，容易漏掉线上内存与冷启动限制。

交付物不是一行最高分。它应包含种子分布图、树间相关性、OOB 与真实测试差距、树数成本曲线，以及单树可读性与森林稳定性的取舍说明。

还要保存一次可复现的成员抽样。随机选择五棵树，记录各自训练到的不同样本比例、根节点和对象级预测。这个小样本不能代表整座森林，却能帮助读者把“成员有差异”与最终平均联系起来。若五棵树结构几乎相同，再回到候选特征数和抽样策略检查相关性来源。

模型注册时保存训练种子与库版本。相同参数在实现更新后可能生成不同成员，稳定性报告需要能够重算和比较。

这也让后续回归测试拥有明确、可复算的参照。

## 袋外重要性也需要谨慎解释

随机森林可以打乱某个特征的袋外取值，观察性能下降，得到 permutation importance。它比基于节点纯度累计的特征重要性更贴近预测贡献，却仍会受相关特征影响。

两个特征携带相似信息时，打乱一个后另一个可以代替它，重要性看起来都不高。若无条件打乱破坏了原本合理的特征组合，性能下降又可能被夸大。这些问题将在第 16 章集中处理。

这一章只保留一条边界。森林通过许多树的共同预测降低波动，不会把特征排名变成因果结论，也不会自动生成可信概率。第 11 章的校准检查与第 12 章的决策规则仍然适用。

## 与 AI 协作读取重复实验

AI 可以生成多种子实验脚本，汇总每棵树对样本的预测，并画出相关性热图与性能平台。要求它固定数据切分，只改变明确列出的随机源，否则差异无法归因。

让 AI 解释结果时，要求它分别回答单树强度、树间相关和外部时间测试。若它只说“随机森林泛化更好”，应追问证据来自哪一种稳定性。
