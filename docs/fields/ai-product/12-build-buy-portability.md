## 为什么现在要学“Build、Buy 与可迁移性”

先别问“谁最好”。供应商变化时，数据、评测和工作流能否带走？ 只有把约束、失败代价和退出条件放在同一张表里，选择才有意义。

**本章核心判断：** Build/Buy 需要比较能力、总成本、数据权、可观测和退出路径，价格只是其中一项。

本章只追一个判断：**供应商变化时，数据、评测和工作流能否带走？** 最后必须用“选型记录、锁定风险与退出计划”来回答；如果产物不能暴露失败样本，就还不能算学会。

## “选型记录、锁定风险与退出计划”怎样进入真实系统

| 决定 | 验收依据 | 重新评审的信号 |
|---|---|---|

## 给“Build、Buy 与可迁移性”一个可操作定义

Build/Buy 需要比较能力、总成本、数据权、可观测和退出路径，价格只是其中一项。

可操作定义必须允许你回答三件事：输入或条件是什么，发生了哪条机制，最后观察什么才算支持结论。本章的观察出口是 **选型记录、锁定风险与退出计划**。

## “供应商变化时，数据、评测和工作流能否带走？”依赖哪些前提

本章暂时不展开整套推导，但必须把判断拆成可以检查的前提：

| 顺序 | 必须成立的前提 | 对应控制 |
|---|---|---|
| 1 | 任务是否真的需要环境反馈循环；在“Build、Buy 与可迁移性”中必须显式核对 | 政策/权限不用 prompt 保证 |
| 2 | 知识更新频率与模型截止差异；在“Build、Buy 与可迁移性”中必须显式核对 | 状态独立于上下文窗口持久化 |
| 3 | 工具写权限和幂等/撤销能力；在“Build、Buy 与可迁移性”中必须显式核对 | 供应商合同覆盖数据权、日志和退出 |
| 4 | 供应商数据留存、可观测和出口能力；在“Build、Buy 与可迁移性”中必须显式核对 | 多 Agent 需要证明优于单 Agent/工作流 |

这四项共同约束“供应商变化时，数据、评测和工作流能否带走？”。任何一项只能靠猜测回答时，都应降低结论强度或补实验。

## 沿着一条完整推理链走到底

### 第一步：固定要解释或改变的对象

不要用“整体效果更好”代替对象。把“供应商变化时，数据、评测和工作流能否带走？”改写为：在明确输入、时间点和约束下，观察什么量，比较什么基线，最后据此采取什么动作。

### 第二步：写出中间机制

上一主题“工具、状态与策略必须分层”提供前置条件，本章用 **能力阶梯** 解释关键机制，并把结果留在“选型记录、锁定风险与退出计划”中。下一主题“把‘回答好’改成任务单位与 Rubric”只在这些证据成立后继续。 只要中间任一环只能凭主观解释，结论就应降级为假设。

### 第三步：主动寻找反例

先尝试制造“把 Agent 当默认 UI”。如果当前方法仍给出看似正常的平均分，说明评价没有覆盖真正风险，需要补切片、过程指标或拒绝条件。

### 第四步：把结论写成可撤回决定

当前决定是“多 Agent 需要证明优于单 Agent/工作流”。同时写下适用条件、责任人和重新评审信号；这样新证据出现时能更新，而不是把旧结论当永久规则。

这条推理链最终必须落到 **选型记录、锁定风险与退出计划**。只有定义、机制、观察和决定互相对得上，文章内容才真正进入工作系统。

## 当 能力阶梯 失效，先查哪里

先排除这些看似合理的误解：Agent 比 workflow 更先进；模型卡等于独立验证；多模型投票必然可靠；Build 可避免锁定；Prompt 能执行权限。

### 只看 token 单价不看总拥有成本

先查看 **风险运维**：漂移、越权、事故、恢复时间和残余风险。如果证据确认失败，回到“多 Agent 需要证明优于单 Agent/工作流”，保存触发输入、系统响应和人工处置，再把样本加入回归集。

### 把 Agent 当默认 UI

先查看 **任务质量**：主指标、分层指标、置信区间和失败类型。如果证据确认失败，回到“政策/权限不用 prompt 保证”，保存触发输入、系统响应和人工处置，再把样本加入回归集。

本章的边界不是一句“视情况而定”，而是能写进测试、监测或人工审核条件的触发器。

## 把“Build、Buy 与可迁移性”迁移到新条件

围绕“Build、Buy 与可迁移性”完成如下变式：对同一任务实现或详细设计简单方案和 Agent 方案；用 30 条盲测比较质量、延迟、成本、恢复，写出是否允许晋级的 ADR。

提交“选型记录、锁定风险与退出计划”时同时附上：

1. 一个成功样本和一个失败样本；
2. 失败推翻了哪条假设，而不只是报错信息；
3. 哪项结论来自公开来源，哪项只来自你的本地实验；
4. 如果换数据、人群、环境或本体，最先需要重测什么；
5. 当前仍无法消除的残余风险。
