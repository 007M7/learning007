# 权威来源与内容治理

课程优先使用能够长期追溯的一手资料。

## 来源优先级

1. 正式标准、协议与规范；
2. 官方语言、框架和平台文档；
3. 原始论文、作者技术报告和官方工程博客；
4. 高质量开放教材；
5. 经过验证的二手解释，仅用于降低理解门槛。

## 每条来源记录

- 标题、作者或维护组织；
- 原始链接；
- 发布或最近更新日期；
- 本站访问和核验日期；
- 支持哪个知识节点；
- 证据类型与适用边界；
- 是否存在版本相关风险。

## 分领域目录

- [软件与系统工程来源](/sources/software)：语言、操作系统、网络、API、数据库与架构表达；
- [软件质量与生产交付来源](/sources/quality)：测试、容器、CI/CD、可观测性、安全与供应链；
- [AI 应用与 Agent 来源](/sources/ai)：模型接口、RAG、工具/MCP、评测与风险治理。

## 时效策略

| 来源类型 | 复核节奏 | 触发复核 |
|---|---|---|
| RFC/正式标准 | 每年 | 新版取代、勘误影响语义 |
| 活文档/API | 每季度 | 版本、弃用、定价/参数变化 |
| 安全清单 | 每季度 | OWASP/NIST 新版或高影响漏洞 |
| 原始论文 | 内容稳定 | 只补后续证据，不改写原论文结论 |
| 本站综合实践 | 每次项目验证 | 测试/事故证明边界变化 |

本站统一核验日为 **2026-08-31**。章节不复刻外部原文，只做面向项目的解释并链接原始资料。来源支持某个事实，不代表来源作者认可本站全部建议。

## 更新一条内容的门

提交应同时修改：知识节点、来源版本/访问日、受影响练习或评测、必要的迁移/弃用提示。版本相关结论尽量写“截至何时”，避免把今天的 SDK 参数当永久概念。
