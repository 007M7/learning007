# AI 测量科学阅读综述

AI 团队非常容易获得分数。模型在某基准上提高两点，新的评审模型给出 4.3 分，Agent 完成率达到 78%。真正困难的问题在分数出现以前：这套测试测到的是我们关心的能力吗，题目和真实任务是什么关系，样本变化后排名还稳定吗，模型是否针对公开基准过拟合，以及这个结果能否支持发布、采购或治理决定。

Sang T. Truong 与 Sanmi Koyejo 主持的 Stanford AIMSLab 在线教材《AI Measurement Science》从这些问题出发。它把 AI evaluation 从“运行 benchmark”提升为测量科学：先定义构念与效度，随后研究评测数据与概率模型，再处理估计、可靠性、效率、干预和外推；最后分析基准成为优化目标后的激励、设计机制与应用。教材还延伸到动态系统、Agent、可扩展监督和公平评测，并配有代码、数据与课程项目。

[阅读 Stanford AIMSLab 完整在线教材](https://aimslab.stanford.edu/textbook){target="_blank" rel="noopener noreferrer"}

这是一部方法密度很高的前沿教材。产品经理不必在第一次阅读掌握所有概率模型，却必须理解前三章，因为任何产品评测都依赖“测什么、用什么数据、怎样由回答推断能力”。后续可以按职责选择方法路线或治理路线。

教材处于快速发展的 2026 版本，部分章节和领域结论会继续更新。它的优势正是将经典心理测量、统计建模和当前 AI 评测连接；阅读时也应记录版本，不把当前 taxonomy 当作永恒分类。

## 全书从一个比指标更早的问题开始

评测常从“选哪个指标”开始，测量科学先问 construct：我们真正想知道、却不能直接观察的属性是什么。推理能力、事实可靠、代码能力、代理自主性和帮助程度都是构念。题目、交互轨迹和评分只是这些构念留下的可观察响应。

```text
目标决定需要了解的构念
        ↓
构念通过任务与情境产生可观察响应
        ↓
数据记录模型 × 题目 × 评审 × 条件的响应矩阵
        ↓
测量模型估计能力、难度、不确定性与差异
        ↓
可靠性、效度与外推证据共同限定结论
        ↓
分数才可能支持选择、发布、干预或治理
```

箭头中任何一段断开，数字仍然可以计算，却不再支持原来的解释。一个数学题集上的高分不能自然推出客服场景事实可靠；一组单轮问答不能测量多步骤 Agent 的恢复能力；用户点赞也不能直接当作答案正确。

这本书的核心态度可以概括为：评测不是给系统贴一个分数，而是建立从构念到决策的证据链。

## Validity：评测真的测到了所声称的东西吗

第一章采用统一效度观，把 validity 理解为对分数解释与使用的证据积累。教材将构念视为嵌入 nomological network 的潜变量：它与其他属性、任务和结果存在理论关系，并因果地产生可观察响应。只看回答数据，多个完全不同的结构可能产生相同分布，因此效度不能由数据自动识别。

教材组织五类效度证据。Content evidence 检查任务内容是否覆盖构念；criterion evidence 检查分数与外部标准关系；construct evidence 检查理论预期的内部与外部关系；external evidence 关注跨人群、任务和环境推广；consequential evidence 观察评测使用产生的后果。

以“企业研究 Agent 能力”为例，若测试只包含网页搜索与摘要，内容没有覆盖权限、工具失败、冲突证据和长任务中止。即使得分稳定，它也不能代表生产 Agent。若高分系统在真实研究中没有提高结论质量，criterion 关系不足。若基准公开后厂商专门优化题型，分数后果会改变系统行为，效度需要重新审查。

效度不是通过/失败标签，也不是某个统计量。它针对具体解释。相同分数可以用于同版本回归测试，却未必能用于比较不同架构，更不能直接支持高风险自动化。产品经理应在评测计划开头写“这个结果允许我们作出什么决定”，而不是最后才寻找用途。

## Data：响应矩阵让评测对象变得清楚

第二章用 response matrix 抽象评测数据。行可以是模型或系统，列可以是题目、任务或情境，单元格记录回答、分数、时间、成本、轨迹或其他反应。这个简单结构迫使团队区分四个对象：谁被测、用什么题测、谁或什么评分、在何种条件下运行。

教材梳理 70 余种 benchmark，覆盖知识、代码、Agent、多语言、文化和偏好等。taxonomy 的作用不是建立永久排行榜，而是显示不同基准针对不同构念与响应形式。选择 benchmark 应从产品任务出发，热门程度和模型排行榜不能替代覆盖分析。

真实评测数据有多种质量问题。题目可能重复或泄漏进训练；标签含糊；难度集中在狭窄区间；答案格式与能力混淆；评审者不同意；缺失响应不是随机；模型因预算、工具和采样设置不同而不可比。Agent 轨迹还会产生嵌套和时序依赖，一次最终成功掩盖中间危险行为。

数据集版本必须与结果绑定。修改题目、评分器、提示或执行环境，测量标尺可能已经变化。所谓“比上周提高”只有在关键条件可比时成立。若新题专门加入旧模型失败样本，平均分下降可能表示测试更难，而非模型退化。

## Models：从简单平均走向题目与系统的共同模型

直接平均默认每道题同等信息、难度相近、评分误差可忽略。第三章引入概率测量模型，包括 Item Response Theory 中的 Rasch、2PL、3PL，以及更广的分层与潜变量方法。它们共同试图解释系统能力与题目属性怎样产生响应。

Rasch/1PL 模型可以用直觉式关系理解：模型能力高于题目难度越多，答对概率越高。2PL 进一步允许题目拥有不同 discrimination，有些题更能区分能力。3PL 加入 guessing，在选择题等场景表示低能力者也可能猜对。参数不是为了让评测变复杂，而是回答“哪些题真正提供信息”“两个系统是否只是做对不同难度题”。

IRT 依赖假设，例如潜在能力维度、局部独立和模型形式。生成式系统的多维能力、提示敏感与开放评分可能违反简化假设。使用更复杂模型也不自动真实，需要 posterior predictive check、残差、替代模型和领域解释。

产品团队不一定要部署 IRT，却应吸收三个判断：题目不是等价计数单位；系统与题目的交互包含结构；评测结果应该带不确定性。20 道相似问题上的 19 分，不一定比覆盖关键失败的 200 道任务更有证据。

## Learning：我们怎样从有限评测估计未知表现

评测只观察有限样本，产品关心未来任务。Learning 章节讨论估计与泛化：怎样从观测响应学习系统、题目与群体的关系，怎样对未测试对象预测，并避免把拟合当作真实能力。

数据切分要尊重部署结构。随机拆分相似题目会让训练与测试共享模板，结果过于乐观；同一文档衍生问题应按来源分组；随时间变化的知识应使用时间外推；Agent 工具和网站变化需要环境切分。评测模型自身也需要独立检验。

元评测很重要。如果使用 LLM-as-a-judge，必须在目标任务上与人工标注比较，检查位置偏好、长度偏好、自我偏好和群体差异。裁判在旧样本上相关高，不保证遇到新模型、新攻击和新语言仍然可靠。

产品经理应把评测集分成开发、选择和最终确认用途。开发集用于频繁诊断，选择集用于比较提示与模型，保留集只在发布前使用。所有集合反复参与决策后，都会逐渐变成训练信号，需要更新或盲测。

## Reliability：同一个结论换个条件还站得住吗

可靠性关注测量在题目、采样、评分者、时间和运行条件变化下的稳定。生成模型具有随机性，同一输入多次采样可能不同；Agent 受工具延迟和环境状态影响；人工评分也存在分歧。只运行一次、只用一个裁判，会把偶然结果当作系统属性。

可靠性可以从多个层次检查：题目内部一致性、重复运行、评分者一致、不同题集的排名稳定、版本变化的可比性。总体分稳定也可能掩盖关键切片波动，高风险场景需要单独估计。

置信区间和方差分解比更多小数位有价值。两个模型相差 0.7 分，若不确定性为 ±2 分，不能宣称明确胜出。排名在不同提示模板、采样温度和裁判下翻转，说明决定依赖测试设置。

可靠不等于有效。一套只测格式遵循的题可以非常稳定，却不能代表研究能力。反过来，复杂真实任务可能天然波动，不能因为可靠性较低就改成容易但无关的测试。团队要在代表性与测量精度之间明确取舍。

## Efficiency：更少成本取得足以决策的信息

完整评测可能非常昂贵，尤其涉及专家、人类偏好、长轨迹和多次运行。Efficiency 章节不是追求最小题量，而是提高每单位成本的信息。不同题目对不同能力区间的区分度不同，固定向所有系统发相同题目会浪费预算。

可以使用分层抽样、主动选择、顺序测试、早停和自适应测验。明显失败的候选不必运行全部昂贵任务；分数接近门槛时增加最有区分力的题；关键风险切片即使比例小也固定保留。效率策略必须预先规定，不能看到不喜欢的结果就停止。

AI 产品评测还应同时计入被测系统成本与评分成本。多模型评审、重复采样和长 Agent 轨迹会快速增加费用。缓存、可重放环境和分级测试可以形成漏斗：便宜确定性检查先过滤，自动行为评测其次，高成本专家与真实环境最后确认。

降低成本不能破坏效度。删除昂贵但关键的真实任务，只保留可自动评分题，会让测量对象悄悄改变。效率优化应报告哪些信息被牺牲，以及当前决策为何仍然成立。

## Intervention 与因果推广：系统改变以后结果为什么会变

预测“哪个系统分高”与判断“采取某项改动会让产品更好”不同。教材的方法路线讨论干预与推广，要求区分观察关联、实验改变和跨环境迁移。

提示、检索、工具、模型与用户培训经常同时变化。上线结果提高，无法知道哪项造成。随机实验、分阶段发布或明确对照可以估计干预效果；高风险或低样本场景则需要准实验、机制分析和敏感性检查。

外部效度问结果能否从评测环境推广到目标使用。基准用户、任务、语言、设备、预算和后果与生产不同，平均处理效果可能失效。产品需要说明目标总体，并检查效果异质性。一个帮助新手的解释可能拖慢专家，不能只报告总体平均。

模型进入工作流后还会改变人的行为。用户可能学习怎样迎合系统，团队可能把人工难例留给模型，数据分布因此改变。干预对象是社会技术系统，不只是模型参数。

## Benchmark Ecosystem：当分数成为目标，测量会被改变

教材后段从单个评测扩展到生态。公开 benchmark 影响研究、投资、采购和媒体，参与者会针对指标优化。Goodhart 式问题由此出现：当测量成为目标，它与原构念的关系可能减弱。

模型训练吸收测试数据、提示针对题型优化、只报告有利结果、基准维护者选择易传播指标，都会改变生态。排行榜提高透明度，也会把复杂能力压成单一顺序。产品采购若直接使用公开排名，可能为与自身任务无关的能力付费。

机制设计需要考虑激励。盲测、动态题库、私有保留集、提交限制、完整报告、利益冲突披露和复现环境，都用于减少操纵。没有任何机制永久有效，评测会与被测系统共同演化。

评测治理还包括谁定义构念、谁受到结果影响、谁能质疑。文化与多语言测试不是把题目翻译，而要检查能力定义和评分标准是否适合目标社会环境。公平性也不能只比较平均分，要看测试本身是否对群体具有相同含义。

## Agent 评测为何需要过程而不只看最终成功

Agent 会规划、调用工具、读取环境、写入状态并在失败后恢复。最终任务完成率重要，却无法说明它是否越权、用了多少资源、偶然成功还是稳定完成。评测对象从一个回答扩展成轨迹与环境交互。

一套 Agent 评测至少包含：任务定义与初始状态、可用工具和权限、成功条件、禁止行为、时间与成本预算、环境变化、过程日志、恢复和中止。评分可以分为最终结果、步骤正确、工具选择、参数、权限、安全、效率和可恢复性。

环境必须可重放。真实网页和 API 会变化，某次失败可能来自外部服务。模拟环境稳定却可能失去现实复杂度，最好用分层方法：确定性沙箱完成回归，受控动态环境测适应，小流量真实任务作最终证据。

Agent 的自主性越高，评测越应覆盖干预和停止。系统在信息不足时会不会请求确认，发现工具结果冲突是否暂停，执行不可逆操作前是否获得授权。这些行为不能由最终“任务完成”抵消。

## 用客服 Agent 建立一份测量合同

团队希望 Agent 自动处理退款。第一步定义构念，不叫“智能程度”，而是“在标准订单政策内，正确识别资格、取得必要信息并安全完成退款的能力”。其 nomological network 包含政策理解、订单状态、工具权限、异常识别和人工升级。

内容效度要求任务覆盖正常、缺失、冲突、过期政策、高金额、不同地区和越权请求。响应矩阵记录不同 Agent 版本在任务上的最终结果、轨迹、调用、成本和人工评分。题目按难度和失败类型组织，而不是简单平均。

可靠性通过重复运行、不同订单模板和裁判比较检查；效率采用分级测试，先跑确定性规则和短任务，再进入专家审核的高后果场景。发布解释限定为“标准场景辅助处理”，不外推到全部退款。

小流量试验比较 Agent 建议与现有人工流程，观察正确处理、时长、客户结果、人工升级和错误成本。生产中新失败进入保留集，但更新后不能用同一数据既优化又最终确认。这样得到的 78% 不再是孤立数字，而是一份带构念、数据、条件和决策边界的证据。

## 产品经理应掌握的八个评测问题

1. 我们真正要了解的构念是什么，而不是手边能算什么指标？
2. 测试内容怎样覆盖目标任务、用户、环境与高后果失败？
3. 响应由模型能力、题目、评分者和运行条件分别贡献多少？
4. 结果换题、换裁判、换随机种子或换时间是否稳定？
5. 两个分数差异是否大于不确定性，并足以改变决定？
6. 公开基准是否已经成为训练和优化目标？
7. 评测结果允许推广到哪里，哪些人群与场景不能外推？
8. 这项评测的使用会激励团队或供应商做出什么行为？

## 本书没有替你完成什么

测量科学提供论证框架，不会自动给出产品构念。领域专家、用户和责任方仍要共同定义什么算成功与伤害。复杂模型也无法从有缺陷的数据中识别唯一真实结构，第一章已经提醒 nomological network 不可仅凭响应数据确定。

教材中的数学方法需要结合样本与假设。机械使用 IRT、置信区间或主动抽样，可能制造更高级的伪精确。产品团队应从决策风险选择必要复杂度，小型回归测试不一定需要完整潜变量模型，高风险采购与自动化则不能只靠几十道题。

前沿 Agent、可扩展监督与文化评测仍在快速发展。当前框架帮助发现问题，不表示领域已有最终答案。

## 建议阅读路径

产品与设计读者先读 Validity、Data、Models 三章的概念部分，再进入 Ecosystem、Design 和 Application；为一个真实产品写测量合同。评测工程师继续完成 Learning、Reliability、Efficiency 与 Intervention，并运行代码和 capstone project。

第一次实践不必复杂。选择一个发布决定，写出构念、代表性任务、关键切片、评分规则、重复条件、不确定性、门槛和不可外推范围。随后问：若结果提高两分，我们到底会做什么；如果没有明确行动，评测可能没有对准决定。

## 总体评价

《AI Measurement Science》是这组 AI 产品教材中方法论最强的一部。它不满足于告诉团队“建立 eval”，而是追问 eval 为什么能代表能力、分数何时稳定、怎样更高效，以及评测成为目标后会怎样失真。

对 AI 产品经理，它提供一种真正专业且结构化的判断：任何数字都要附带测量对象、数据、模型、不确定性、适用边界和使用后果。掌握这条证据链，才能在模型发布越来越频繁、Agent 行为越来越复杂的环境中，避免把排行榜或漂亮平均分直接写进产品承诺。
