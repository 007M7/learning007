# 人工智能与计算智能体基础第三版阅读综述

假设要做一个采购 Agent。员工提交需求后，它要核对库存、向几家供应商询价、比较交付时间、取得预算批准，最后创建订单。大语言模型可以读懂那段需求，也可以生成一份采购理由。到了真正执行时，系统还得知道哪些事实已经确认，哪些报价可能过期，哪一步需要人批准，接口失败以后能否重试，两家供应商会不会同时改价。一次流畅回答只覆盖了其中很小的一段。

David L. Poole 与 Alan K. Mackworth 合著的第三版教材为这类问题提供了一套完整语言。作者从计算智能体出发，把人工智能组织成一个持续发生的过程。智能体感知环境，维护对环境的信念，根据目标和偏好选择行动，再从行动结果中更新认知。搜索、逻辑、概率、机器学习、规划、强化学习和多智能体由此进入同一个闭环，各自处理闭环里的不同困难。

这本书很适合放在 AI 应用与 Agent 知识库的第一位。它不会教你调用某个流行框架，却能帮助你判断一个框架省略了什么假设。读完以后，读者应当能够拿到一个 Agent 方案，逐项检查环境、状态、时间、知识、偏好、不确定性、算力和其他参与者，随后决定应当使用规则、搜索、学习、规划或人工控制。

这是一部人工智能总教材。它讲授的 Agent 范围远大于当前常说的 LLM Agent，恒温器、机器人、辅导系统、诊断系统和交易程序都可以成为分析对象。作者关心的是一个计算系统怎样在环境中持续行动，语言模型只是其中可能使用的一种表示或推理能力。

第三版出版于 2023 年，书中深度学习、社会影响和部署讨论已经更新，主体结构仍沿用经典 AI 的问题划分。它适合承担稳定基础，不能单独替代 2024 年以后的长上下文、工具调用、RAG、提示注入、Agent 评测和推理模型研究。阅读责任因此很清楚。用它建立判断坐标，再用知识库里的近期论文更新具体能力边界。

## 三分钟抓住全书

全书的六个部分依次拿掉对环境的简化假设。

```text
第一部分  智能体怎样存在于环境中
              ↓
第二部分  世界已知且行动确定时怎样搜索、推理和规划
              ↓
第三部分  世界不能完全知道时怎样学习、表达概率并识别因果
              ↓
第四部分  行动结果也不确定时怎样决策、学习策略并处理其他智能体
              ↓
第五部分  状态过于庞大时怎样用实体、关系和知识图谱表达世界
              ↓
第六部分  系统进入社会以后怎样重新检查目标、责任与部署后果
```

这个顺序解释了全书为什么先讲搜索，后讲概率规划。若智能体知道当前状态，每个动作的效果又完全确定，达成目标可以化为寻找一条状态路径。感知开始遗漏信息以后，系统需要维护信念。行动可能产生多个结果以后，固定路径要改成能够根据观察继续选择的策略。其他主体也会根据你的行为调整时，环境本身带上了目的，博弈、协商和机制设计随之出现。

读者可以把六部分压缩成一个问题。智能体依据什么，在什么限制下，选择下一步行动。十九章不断为这句话补充条件。

## 全书从感知和行动的循环开始

第一章给出的定义很朴素。智能体把感知、推理和行动连接起来，并且始终处在环境之中。环境会产生刺激，控制器依据当前刺激和过去信息发出命令，执行器再把命令变成环境里的动作。命令和动作需要分开。采购程序发出“购买 12 件”的命令，库存变化、网络故障或价格更新都可能让实际结果偏离命令。

智能体为了跨时间工作，还要维护信念状态。它可以保存已经观察到的事实、对当前世界的估计、最近执行过的动作、仍待完成的计划，也可以保存各个动作可能带来的价值。信念状态不是聊天记录的别称。只有未来决策仍然需要的信息，才值得进入状态；状态还要随着新感知和行动结果更新。

```text
环境产生感知
      ↓
更新信念状态
      ↓
根据目标、偏好和资源选择命令
      ↓
执行器尝试改变环境
      ↓
观察真实结果并继续更新
```

这个循环能立刻校准今天的 Agent 架构。提示词描述行为规则，语言模型提出候选，工具执行外部操作，记忆保存跨步骤信息，运行时安排重试和中止，评测检查最终环境是否真的改变。模型很重要，完整系统还需要把其余环节接住。

## 十个维度先告诉你问题难在哪里

第一章最值得反复使用的内容，是智能体设计空间。作者没有给出一套适用于所有任务的架构，而是列出十个复杂度维度。每个维度都对应一种会改变算法和系统设计的条件。

| 维度 | 较简单的一端 | 复杂度增加以后要处理什么 |
| --- | --- | --- |
| 模块化 | 单层系统 | 模块、层级以及不同抽象层之间的信息传递 |
| 规划跨度 | 不考虑未来或只看有限步骤 | 步数不预先确定的任务与持续运行过程 |
| 世界表示 | 枚举状态 | 特征，以及数量庞大的实体和关系 |
| 计算限制 | 假定能求得最佳行动 | 时间、内存、费用和数值精度下的有限理性 |
| 学习 | 知识由设计者给定 | 从数据和交互经验中学习表示与行为 |
| 感知不确定性 | 完全可观察 | 多个真实状态产生相同或误导性的感知 |
| 行动效果 | 确定性结果 | 同一动作可能产生不同结果 |
| 偏好 | 单一达成目标 | 价值、风险、时间和成本之间的权衡 |
| 参与主体 | 只有一个智能体 | 对手、合作者以及拥有各自目标的多个主体 |
| 交互方式 | 主要离线计算 | 观察环境以后必须及时完成的在线推理 |

十个维度不能逐项孤立处理。层级不同，规划跨度可能不同。采购 Agent 的工具执行层要在几秒内处理超时，高层计划可能持续数天；创建订单在接口层看起来是确定动作，放到真实业务层还会受到库存和审批影响。感知也会改变表示，系统看不到供应商真实库存时，只能维护几种可能状态及其可信程度。

这张表还能阻止一种常见误判。任务效果不好时，团队很容易继续修改提示词。设计空间会迫使大家先定位复杂度来自哪里。缺少订单状态属于部分可观察，报价会变属于效果不确定，多项目争抢预算属于复杂偏好，多家供应商相互报价属于多主体互动。四个问题需要的改法完全不同。

## 分层控制把快反应和慢推理放到不同位置

第二章继续处理智能体内部结构。作者指出，先把所有传感信息整理成完整世界描述，再交给一个中央推理器，最后统一发出动作，这种结构很难同时处理快速反应和长期目标。层级控制给出另一种安排。较低层快速处理局部变化，对上层提供简化后的感知；较高层看更长时间和更抽象的任务，再把目标交给下层。

送货机器人的低层负责避障和电机控制，中层前往目标位置，高层按照地点列表执行计划。上层知道“会议室”和“实验室”，中层处理坐标，低层处理速度和方向。每一层都把下层看作一个可以接收感知、执行命令的虚拟身体。

采购 Agent 也可以这样分层。业务层确定采购目的、预算和审批规则，计划层安排询价、比较和下单步骤，工具层保证参数、幂等、重试和权限，接口层处理供应商 API 的具体响应。把这些责任全交给一次模型调用，任何局部失败都会迫使模型重新理解整件事。分层以后，快慢任务拥有不同超时，业务规则也无需淹没在接口细节中。

层级并不自动带来可靠性。层与层之间仍要约定传递什么感知、接受什么命令、保留哪些状态。高层说“选择最合适供应商”，低层没有价格、交期和风险的共同表示，抽象只会掩盖分歧。第二章的价值正在这里。架构图里的每条连接都应当对应可以解释的数据和控制关系。

## 搜索、约束、逻辑和规划共同处理确定性世界

第三至第六章暂时把世界简化。智能体知道当前状态，动作结果可以预测，外部事件不会突然改变环境。这样的条件距离生产系统很远，却能让四种推理任务分开显形。

搜索先把“怎样完成目标”表示为图中的路径。状态说明智能体可能处在哪里，边表示可执行动作，代价记录走这条边需要付出什么。宽度优先、深度优先和启发式搜索的差别，由候选路径怎样排队产生。启发式信息若能估计剩余代价，智能体就能少探索许多无望路径；估计过强或含义不清，也可能失去最优性保证。

约束把状态进一步拆成变量。会议时间、会议室和参与者各自有可选值，硬约束排除冲突组合，软约束为仍然合法的方案排序。搜索在这里不再盲目枚举完整状态，它可以先传播局部一致性，缩小各变量的候选范围，再对真正存在分歧的地方分支。工具调用中的参数校验、工作流里的前置条件和资源调度，都能看到约束问题的影子。

命题与推理负责另一项工作。系统需要区分已知事实、能够推出的结论、为了回答问题还应询问用户的信息，以及当前知识为何产生矛盾。逻辑表示的价值包含调试。某个结论无法推出时，团队可以检查缺少哪条规则；结论与事实冲突时，也能定位知识层的问题。语言模型生成一句听起来合理的话，没有自动提供这样的可追踪关系。

确定性规划把状态、动作、前置条件和效果接起来。计划是一串能够把初始状态带到目标状态的行动。这个定义依赖六类重要假设，包括单一智能体、动作效果确定、没有无法控制的外部事件、环境完全可观察、时间按离散步骤推进，目标能够写成状态条件。书在这里主动把假设写明，随后各章再逐项放宽。

四章合起来提供了一个很实用的分工。搜索负责在可能路径中选择，约束负责排除不合法组合，逻辑负责维护可解释知识，规划负责说明行动怎样改变状态。现代 Agent 可以让语言模型参与这四项工作，系统仍需知道当前任务究竟属于哪一种。

## 第七章以后开始处理不知道的世界

现实智能体很少拥有完整规则。第七章把学习定义为智能体根据经验改善行为，改善可以表现为会做更多事、做得更准或做得更快。监督学习使用输入与目标组成的样本，学习新输入到输出的关系。作者特别强调，目标是理解产生数据的世界。数据只记录了一部分世界，还会受到选择过程和历史决策影响。

这个位置安排得很重要。学习没有从全书第一页接管人工智能，它先接过一个已经有环境、目标和行动的智能体。贷款模型从历史违约中学习，是为了支持未来决策；历史数据里的不平等也可能被模型延续。手表预测健康状态，如果只给出运动建议，偶尔猜错的后果有限；若系统会自动呼叫急救，准确性和可靠性要求会发生变化。预测质量最终要回到行动后果。

第八章解释表示学习。传统方法先由人把像素、声音或字符变成特征，神经网络可以共同学习特征和预测函数。多层结构让低层表示被多个高层任务复用，也形成与树模型不同的归纳偏好。读者在这里得到的重点应当是表示怎样影响可学习关系，而非背下一串网络名称。

第九和第十章把概率推理与学习接起来。环境部分可观察时，信念状态可以是一组可能世界的概率分布。贝叶斯网络用条件依赖表达变量之间的关系，推断根据新证据更新信念；概率学习再用数据估计参数、结构和隐变量。智能体由此可以面对没有在训练集中原样出现的新情况，组合已有关系形成判断。

| 情况 | 智能体还缺什么 | 书中接入的方法 |
| --- | --- | --- |
| 有输入输出样本，希望预测新样本 | 从经验中概括规律 | 监督学习与表示学习 |
| 当前事实无法完全观察 | 对可能状态的信念 | 概率模型与推断 |
| 模型结构或参数也未知 | 从数据更新概率模型 | 贝叶斯学习与无监督学习 |
| 希望知道采取行动会造成什么 | 干预后的结果 | 因果模型 |

这四行构成一条连续关系。预测、推断、学习和因果回答不同问题，不能被一个总称为“智能”的模型输出混在一起。

## 因果一章守住预测与行动之间的边界

第十一章讨论因果。观察数据能够说明变量怎样共同变化，行动需要知道主动改变一个变量会发生什么。冰淇淋销量与溺水事件可能一起上升，禁止冰淇淋并不会自动减少溺水；共同的季节因素可以同时影响两者。一个概率分布本身不足以确定干预效果，因果结论还需要干预数据和建模假设。

这对 Agent 尤其关键。Agent 会采取行动，评测却经常停留在下一步预测是否准确。客户流失风险高，不等于发送优惠券一定能留住他；某类工单经常升级，也不等于自动提前升级就会改善满意度。系统从相关性跨到行动时，必须说明因果假设，并通过实验、准实验或合适的领域证据检查。

因果模型还让反事实问题有了位置。系统可以询问同一对象若采取另一种行动，结果可能怎样变化。这个问题无法从普通分类分数直接得到。采购 Agent 若想判断“现在下单比等一周是否更好”，需要价格变化、库存和交期之间的因果结构，单纯预测明天价格仍然不足。

## 不确定规划把计划改成依观察而行动的策略

第十二章放宽确定性规划的核心假设。智能体无法保证每个动作产生唯一结果，也无法提前知道以后会观察到什么。固定行动序列因此失去作用。合理的计划要写明观察到不同情况以后分别做什么，这样的计划更接近策略。

马尔可夫决策过程用状态、动作、转移概率、奖励和时间组织问题。状态完全可观察时，策略可以直接根据当前状态选动作。部分可观察时，智能体只能根据感知更新信念状态，再依据这份概率分布行动。检查一次检测可能暂时增加成本或不适，却能改善后续治疗决定，这类信息价值只有放进多阶段决策才能看见。

效用与奖励负责表达偏好。只最大化达成目标的概率容易产生荒唐策略。若唯一目标是降低交通事故受伤概率，最稳妥的做法可能是永远不出门；真实决策还要考虑生活收益、时间、费用和多种伤害。Agent 的“成功”同样不能只写成任务完成。它还要包含权限越界、错误成本、等待时间、资源消耗和可恢复性。

## 强化学习处理规则未知时怎样从行动中学习

第十三章继续拿掉一项条件。智能体知道可能的状态和动作，却不知道转移规律与奖励函数，只能边行动、边观察结果、边更新策略。这形成强化学习问题。

书中用小型网格环境解释两个难点。探索与利用要求智能体在尝试未知行动和使用当前最佳行动之间选择。信用分配要求它判断很久以前的哪些动作共同造成了最后奖励。一个游戏只在胜负时给分，学习者仍要找出中间哪些行动改变了胜率。

今天的 Agent 学习也会遇到同样问题。一条研究轨迹包含检索、阅读、改写查询、调用代码和整理证据，最后只得到“答案通过”或“答案失败”。把结果直接归给最后一步会丢掉大部分信息。训练数据需要保存状态、动作、观察、工具结果和最终回报，评测环境还要能够重复，信用分配才有可用依据。

强化学习也暴露了奖励设计的风险。能够被计算的奖励只是偏好的代理。若采购 Agent 只因低价得分，它可能选择交期不稳或售后很差的供应商；若只奖励速度，它可能绕过必要审批。奖励进入学习以前，先要回到第十二章的复杂偏好与第十八章的社会后果。

## 多智能体要求你承认其他参与者也会思考

第十四章把其他主体从环境噪声中分离出来。每个智能体拥有自己的信息和效用，最终结果由多方行动共同决定。供应商会根据需求和竞争者调整报价，审批人可能改变预算，另一个采购 Agent 也在争抢同一库存。把这些参与者当成固定环境，模型很快会失效。

多智能体互动很少只有完全合作或完全竞争。两家相邻商店都希望街区整洁，又会争夺顾客，店内经营则互不影响。Agent 之间也可能共享总目标，却在资源、信息和局部指标上发生冲突。增加角色数量不会自动增加能力，协调和通信本身会消耗资源，还可能出现误解、策略操纵和责任分散。

博弈表示帮助分析各方行动与结果，群体决策讨论怎样聚合不同偏好，机制设计则反过来安排可用动作和结果规则，使自利参与者更可能产生期望结果。当前多 Agent 系统常把“研究员、评审员、规划员”写进提示词，却没有明确每个角色掌握什么信息、追求什么效用、怎样解决冲突。第十四章提供了检查这些设计的理论入口。

## 实体和关系让世界表示继续扩大

前十四章经常用状态或特征表达世界。状态数量随着对象增加迅速膨胀。第三十个布尔特征已经能组合出十亿级状态，现实系统也无法为每个员工、订单和供应商单独编写同一条规则。第十五至十七章转向实体与关系。

关系表示允许系统说某个订单属于某位员工、某家供应商提供某种商品、某条政策适用于某个地区。规则可以对一类实体成立，无需提前枚举所有对象。谓词逻辑、Datalog、证明与替换提供了精确推理方法，知识图谱和本体继续处理命名、类别、属性、共享与维护。

知识图谱中的标识符指向实体，三元组表达实体之间的关系。本体说明不同系统怎样使用同一个类别和属性。它们对 Agent 的作用不限于检索更多文本。权限继承、订单归属、工具参数、组织关系和任务约束都需要稳定语义。检索出含有“红色”的文档，与知道某个包裹的颜色属性为红色，属于两种不同的表示能力。

第十七章再把关系表示与概率学习合并。系统可以预测实体的属性和实体之间的关系，也要面对对象身份不确定、关系相互依赖和新实体不断出现。现代 GraphRAG、知识记忆和神经符号方法使用了新的模型，根本问题仍然相通。系统用什么实体和关系描述世界，这种选择会决定它能够提出哪些问题。

## 社会影响从目标写入系统的那一刻就已经开始

全书几乎每个技术章都保留社会影响小节，第十八章再集中讨论大规模部署。这样的安排传递了一项很重要的判断。社会后果与目标、数据、表示和行动机制共同形成，无法等到系统完成以后再补一次伦理检查。

智能体的偏好通常来自设计者，却可能影响没有参与设计的人。诊断系统怎样权衡痛苦、寿命、费用和不确定性，涉及患者、医生、支付者与社会的不同偏好；社交平台优化参与度，会改变信息传播和群体关系；贷款、保险和招聘系统使用历史数据，也会把既有差异带进未来决定。

第十九章回到部署和智能体设计空间。一个方案进入真实环境以后，十个维度需要重新检查。用户、数据和外部系统会变化，原本离线完成的判断可能成为在线问题，原本单一主体的流程也可能出现策略互动。全书到这里闭合。技术方法没有离开环境、目的和后果独自存在。

## 用一个采购 Agent 走完整本书

带着同一个项目阅读，会比逐章背算法更容易看见六部分怎样接力。

| 阅读位置 | 在采购 Agent 中要回答的问题 | 应留下的产物 |
| --- | --- | --- |
| 第一、二章 | 它感知什么、记住什么、由哪些快慢层级组成 | 环境边界图与分层控制图 |
| 第三至六章 | 哪些步骤可搜索，哪些组合违法，哪些事实可推出 | 状态图、约束表、规则集与确定性计划 |
| 第七至十一章 | 哪些知识要从历史学习，哪些事实无法观察，哪些行动需要因果证据 | 数据定义、信念模型与因果假设 |
| 第十二、十三章 | 报价和库存变化时怎样选择，结果如何返回策略学习 | 效用表、条件策略与轨迹记录 |
| 第十四章 | 供应商、审批人和其他采购者怎样改变结果 | 参与者、信息、效用与协调机制 |
| 第十五至十七章 | 商品、供应商、合同和地区规则怎样共享语义 | 实体关系模型与知识图谱 |
| 第十八、十九章 | 谁承担错误，怎样监控部署后的行为变化 | 风险边界、审计事件与更新条件 |

项目的第一个版本无需同时实现所有方法。设计空间先帮助团队找到当前复杂度。若价格固定、库存可靠、流程短，约束和确定性工作流已经足够。报价会变、库存不可见时再加入信念和条件策略。多供应商谈判出现以后，才需要认真处理策略互动。复杂方法应当由环境条件引入。

## 对今天的大模型 Agent 最有用的七个判断

1. 模型只承担智能体闭环中的部分推理。环境、感知、状态、执行器和结果确认同样决定系统行为。
2. 记忆应当被设计为信念状态。每条信息都要说明何时写入、怎样更新、何时失效，以及未来哪项行动需要它。
3. 规划方法依赖环境假设。部分可观察、行动随机或外部事件频繁发生时，一次生成的固定步骤很快过期。
4. 自主程度要同时查看偏好冲突、信息缺口和行动可逆性。能调用工具只说明系统拥有动作通道。
5. 推理预算属于决策的一部分。等待更好答案有时间和费用成本，有限理性要求系统知道何时停止计算并采取可恢复行动。
6. 多 Agent 设计从信息和效用开始。角色名称、提示词差异和消息数量无法替代协调机制。
7. 最终评测要观察环境结果。文本答案正确、工具命令合法，还需确认动作是否生效以及后续状态是否满足目标。

七项判断可以直接用于架构评审。团队先画出感知、状态、命令和环境反馈，再为十个维度选择当前值。模型与框架的选择应当排在这些条件之后。

## 当前版本没有覆盖到哪里

第三版的最大限制来自时间与范围。它出版于 2023 年，大语言模型没有成为全书主线。Transformer 扩展规律、指令微调、偏好优化、长上下文、RAG、函数调用、MCP、浏览器操作、代码 Agent 和测试时搜索，需要另读近年的专著与论文。

书中也没有系统展开当前 Agent 安全的典型攻击面。间接提示注入、不可信工具返回、跨服务权限、凭证隔离和高后果动作审批，已经成为生产系统的独立主题。第十八章提供责任视角，具体威胁模型仍要结合近期安全研究和软件安全资料。

十九章覆盖面很广，每项方法的深度有限。希望真正实现概率图模型、强化学习或多智能体算法时，还要转向专项教材。它更擅长说明这些方法为什么在同一个智能体问题里出现，以及每种方法接过了哪一项被放宽的假设。

## 放进 Learning 007 的学习路线

这本书直接连接 [工作流、Agent Runtime 与记忆](/domains/ai/05-agent-runtime) 和 [Agent 系统边界与研究范式](/frontier/agents/01-paradigm)。前两章适合在学习运行时以前阅读，帮助你把感知、信念状态、控制器和环境反馈画清楚。

第三至第六章为 [推理、规划与测试时搜索](/frontier/agents/02-reasoning-planning) 提供经典基线。面对新的规划论文，可以先检查它放宽了哪项假设，又增加了多少在线计算。第十二至十四章连接 [Agent 学习与强化学习](/frontier/agents/08-agent-learning)，让轨迹、奖励、信用分配和多主体非平稳性拥有统一来源。

第十八、十九章应当与 [Agent 安全、权限与可控自治](/frontier/agents/10-safety-governance) 一起阅读。前者负责目标、社会影响和部署视角，后者补充当前高权限工具系统的威胁与控制方法。这样安排能够保留经典理论，同时避免用 2023 年教材替代最新证据。

## 怎样读才不会被十九章拖散

第一次阅读先看第一、二、十二、十四和十九章。五章能够建立环境闭环、设计空间、分层控制、不确定决策和多主体边界。读完后画一个自己熟悉系统的环境图，并填写十个复杂度维度。这个产物会告诉你接下来真正需要哪一部分。

第二次按问题选读。需要工作流和规划时读第三至六章；需要评价模型和处理不确定性时读第七至十一章。在线学习和多 Agent 对应第十二至十四章，知识表示与 GraphRAG 则对应第十五至十七章。每读一组，都把书中的假设写到自己的系统旁边。

第三次再做练习和实现。书后附有开源软件映射，可以把搜索、约束、概率推断和规划对应到可运行工具。练习的目标是比较表示与假设。拿同一个采购任务，先写确定性计划，再加入一次库存不可见和一次报价变化，观察固定路径为什么要变成条件策略。

读完以后，可以用五个问题检查自己是否真正获得了这本书的判断能力。

1. 当前 Agent 的环境边界在哪里，哪些变化来自系统外部。
2. 系统保存的是原始历史，还是能支持下一步行动的信念状态。
3. 当前规划依赖哪些可观察性和确定性假设。
4. 成功目标怎样表达时间、费用、风险和可恢复性的权衡。
5. 其他参与者会不会根据 Agent 的行动改变自己的策略。

## 总体评价

《人工智能与计算智能体基础》第三版最强的地方，是用一套设计空间连接人工智能的主要方法。读者不会只得到搜索、概率、学习和规划的并列目录，还能看见一种方法在什么条件下变得必要，条件改变以后为什么要换另一种表示或决策方式。

它对当前 LLM Agent 的价值也很明确。模型能力更新很快，环境、状态、偏好、不确定性、计算限制和多主体互动依旧存在。一个系统是否可靠，常常取决于团队有没有把这些问题写进架构和评测。作为 AI 应用与 Agent 的第一本总教材，它提供了足够稳定的坐标。近期模型、工具协议和安全证据应当继续从后面的书籍与论文补入。
