# 算法设计阅读综述

从一张空白纸到一个算法，关键任务包括认出问题结构、构造过程，并说明方案为何覆盖所有情况。Jeff Erickson 把建模、递归、正确性证明和复杂度分析放在一起。读者会看到，回溯、动态规划和贪心并非三种代码样式，它们对选择空间、重复子问题和局部决策有完全不同的假设。

读完以后，读者应能从“问题规格与规模参数”追到“图遍历与最短路”，说明中间的机制、代价和失败边界，并用“用一个真实系统复原《Algorithms》的判断过程”完成一次可复查的应用。

## 先确定问题与可用结构

### 问题规格与规模参数

全书先用“问题规格与规模参数”固定分析对象。先把输入、输出和合法条件写清，再选择能反映增长的规模参数。这一定义决定后文能够讨论哪些状态、操作和保证。

用反例检查规格是否遗漏情况，复杂度必须说明相对哪个参数增长。先写问题规格和成本模型，再讨论结构或算法。输入规模、操作比例、顺序要求与内存层次都会改变方案比较。

在“用一个真实系统复原《Algorithms》的判断过程”中验证这项知识时，应留下一份问题规格、一段正确性论证和一组对照基准。字符串长度、顶点数与边数可能同时影响成本，不能总用一个 n。带着这项限制进入“递归和分治”，后面的结论才有清楚前提。

### 递归和分治

“递归和分治”承接前面已经建立的对象关系。递归把问题归约为更小的同类问题，分治还要合并多个子问题结果。这里新增的规则会改变后续能够作出的判断。

先证明规模严格减小与合并步骤正确，再写递推式分析成本。正确性论证与性能测量承担不同任务。不变量说明结果为何成立，复杂度预测增长趋势，基准测试再补充常数与机器条件。

实践记录需要说明“递归和分治”在正常条件下产生什么结果，并主动加入一个边界条件。子问题大量重叠时，直接分治会重复计算，应考虑动态规划。若结果随之改变，就把差异带到“回溯搜索”继续处理。

### 回溯搜索

到了“回溯搜索”，原书开始处理上一环尚未解决的困难。回溯维护部分解，选择一个分支，失败后撤销并尝试下一个。理解它需要同时保留前一节的输入与限制。

用不变量保证部分解始终合法，用剪枝排除不可能产生答案的分支。最有价值的练习是改变一个假设，让两个合理方案的优劣互换。这样才能学会选择，也能发现结论依赖的工作负载。

这一节适合产出一份问题规格、一段正确性论证和一组对照基准，让另一位读者能够复查选择。剪枝改善实例表现，通常不会改变指数级最坏复杂度。尚未覆盖的输入、状态与环境，应在进入“动态规划依赖图”时继续保留。

### 动态规划依赖图

接下来要处理“动态规划依赖图”。重复子问题形成依赖图，记忆化自顶向下求值，表格法按拓扑顺序求值。这一步把先前的局部结论送进更完整的执行或验证过程。

状态必须包含决定未来所需的全部信息，又不能保留无关历史。先写问题规格和成本模型，再讨论结构或算法。输入规模、操作比例、顺序要求与内存层次都会改变方案比较。

把“动态规划依赖图”用于当前项目时，先写明成立条件，再保留能够推翻结论的反例。状态过多会造成时间与空间爆炸，状态定义比填表公式更关键。下一节“贪心交换论证”要接住这项未解决的问题。

## 再证明、测量并比较候选方案

### 贪心交换论证

原书随后把视线转向“贪心交换论证”。贪心每步作局部选择，正确性依赖最优子结构与可交换选择。它补上的关系，正是后一部分能够继续推理的前提。

用交换论证把任意最优解改造成包含当前选择的最优解。正确性论证与性能测量承担不同任务。不变量说明结果为何成立，复杂度预测增长趋势，基准测试再补充常数与机器条件。

在“用一个真实系统复原《Algorithms》的判断过程”中验证这项知识时，应留下一份问题规格、一段正确性论证和一组对照基准。看起来合理的局部收益不是证明，约束稍变就可能失效。带着这项限制进入“图遍历与最短路”，后面的结论才有清楚前提。

### 图遍历与最短路

“图遍历与最短路”承接前面已经建立的对象关系。BFS、DFS 和最短路在图上维护已发现集合、边界与距离估计。这里新增的规则会改变后续能够作出的判断。

选择算法前检查边权、方向、负权和可达性，明确维护的不变量。最有价值的练习是改变一个假设，让两个合理方案的优劣互换。这样才能学会选择，也能发现结论依赖的工作负载。

实践记录需要说明“图遍历与最短路”在正常条件下产生什么结果，并主动加入一个边界条件。Dijkstra 不能直接处理负权，稠密度也会改变合理表示。若结果随之改变，就把差异带到“最大流与对偶直觉”继续处理。

### 最大流与对偶直觉

到了“最大流与对偶直觉”，原书开始处理上一环尚未解决的困难。流量受容量和守恒约束，增广路逐步改进可行流，割给出上界。理解它需要同时保留前一节的输入与限制。

用最大流最小割关系判断结果不仅可行而且最优。先写问题规格和成本模型，再讨论结构或算法。输入规模、操作比例、顺序要求与内存层次都会改变方案比较。

这一节适合产出一份问题规格、一段正确性论证和一组对照基准，让另一位读者能够复查选择。多商品流、费用和整数约束会改变问题性质与算法。尚未覆盖的输入、状态与环境，应在进入“归约和 NP 困难”时继续保留。

### 归约和 NP 困难

接下来要处理“归约和 NP 困难”。归约把一个问题实例转换成另一个问题，并保持答案关系。这一步把先前的局部结论送进更完整的执行或验证过程。

用已知困难问题证明下界，再决定限制输入、近似或启发式。正确性论证与性能测量承担不同任务。不变量说明结果为何成立，复杂度预测增长趋势，基准测试再补充常数与机器条件。

把“归约和 NP 困难”用于当前项目时，先写明成立条件，再保留能够推翻结论的反例。NP 困难不等于所有实例都慢，也不等于启发式没有价值。下一节“整本书的最终判断”要接住这项未解决的问题。

复述这条主线时，应把一份问题规格、一段正确性论证和一组对照基准放在旁边。读者需要指出前一环产生了什么，后一环怎样使用，以及哪个条件变化会使传递中断。若“贪心交换论证”无法读取“问题规格与规模参数”留下的信息，说明中间还缺接口、状态或证据；若“归约和 NP 困难”没有接住“贪心交换论证”暴露的限制，阅读就停在了局部技巧。

## 用一组真实操作检验选择

选择一个确实运行过的服务，先写出用户任务、关键状态与不可接受的失败。随后沿“问题规格与规模参数、递归和分治、回溯搜索、动态规划依赖图、贪心交换论证、图遍历与最短路、最大流与对偶直觉、归约和 NP 困难”恢复原书的推理次序。进入每一层时，记录它接收什么输入、改变什么状态、向下一层交付什么证据。讨论问题规格与规模参数时先固定问题边界，进入贪心交换论证时检查机制怎样兑现承诺，最后用归约和 NP 困难处理故障、演进或责任。再主动改变一次负载、版本或故障条件，观察原判断从哪里开始失效。

这个案例需要同时写正常路径和失败路径。正常路径说明“问题规格与规模参数”怎样经过中间机制到达“归约和 NP 困难”。失败路径则改变一个前提，观察保证在哪里停止、哪个信号先出现、谁应采取动作。把两条路径放在一起，教材中的抽象才能进入工程判断。

速查表只用于定位。掌握“递归和分治”需要说清它的输入、内部状态和输出，还要指出“子问题大量重叠时，直接分治会重复计算，应考虑动态规划。”。如果回答停在定义，可以回到案例改动一个条件，再观察原有结论是否保留。

## 容易读错的地方

1. 只记住“问题规格与规模参数”的名称，没有画出它处理的对象和状态
2. 直接抄用“贪心交换论证”的结论，遗漏原书给出的前提
3. 只验证正常路径，没有用“归约和 NP 困难”检查失败后的状态
4. 把《Algorithms》中的教学规模、历史条件或组织背景直接当成当前项目条件

这些错误都能用本书自己的对象关系纠正。看到“只记住“问题规格与规模参数”的名称，没有画出它处理的对象和状态”时，返回“问题规格与规模参数”重建问题；出现“把《Algorithms》中的教学规模、历史条件或组织背景直接当成当前项目条件”时，沿案例检查被省略的运行或组织条件。误解被定位到具体章节后，补学范围会更小，也更容易验证。

## 怎样进入数据结构与算法学习

这本书在软件与系统工程路线中承担“把递归、动态规划、贪心、图算法和复杂性串成可证明的算法设计方法”这一学习任务。正式学习先建立概念和机制，产物可以是最小实现、证明、数据模型、协议轨迹或架构决定。进阶学习再改变规模、并发、故障、安全或团队条件，比较原方案是否仍然成立。

最值得保留的判断包括以下内容。

- 问题规格与规模参数负责先把输入、输出和合法条件写清，再选择能反映增长的规模参数。；实践中应当用反例检查规格是否遗漏情况，复杂度必须说明相对哪个参数增长。
- 递归和分治负责递归把问题归约为更小的同类问题，分治还要合并多个子问题结果。；实践中应当先证明规模严格减小与合并步骤正确，再写递推式分析成本。
- 回溯搜索负责回溯维护部分解，选择一个分支，失败后撤销并尝试下一个。；实践中应当用不变量保证部分解始终合法，用剪枝排除不可能产生答案的分支。
- 动态规划依赖图负责重复子问题形成依赖图，记忆化自顶向下求值，表格法按拓扑顺序求值。；实践中应当状态必须包含决定未来所需的全部信息，又不能保留无关历史。
- 贪心交换论证负责贪心每步作局部选择，正确性依赖最优子结构与可交换选择。；实践中应当用交换论证把任意最优解改造成包含当前选择的最优解。
- 图遍历与最短路负责BFS、DFS 和最短路在图上维护已发现集合、边界与距离估计。；实践中应当选择算法前检查边权、方向、负权和可达性，明确维护的不变量。

列表中的每项判断都应连接一份证据。以“问题规格与规模参数负责先把输入、输出和合法条件写清，再选择能反映增长的规模参数。；实践中应当用反例检查规格是否遗漏情况，复杂度必须说明相对哪个参数增长。”为例，证据可以来自原书章节、自己的最小实验和项目中的一次应用。三者各司其职。原文说明概念从哪里来，实验检查机制，本地应用确认条件是否匹配。

## 复杂度结论的适用边界

教材为了讲清“问题规格与规模参数”和“归约和 NP 困难”，会控制示例规模，也可能省略认证、治理、兼容、极端负载或长期运营。NP 困难不等于所有实例都慢，也不等于启发式没有价值。。采用书中方案以前，应核对当前版本、项目约束和依赖环境。

开放正文也会更新。笔记中应保存访问日期、章节标题和采用的具体结论。版本变化时先比较定义、接口与边界，随后重跑与“用一个真实系统复原《Algorithms》的判断过程”相关的练习。单看页面更新时间无法判断现有实现是否受影响。

## 三遍阅读怎样形成学习产物

第一遍沿“沿《Algorithms》的论证次序建立知识地图”建立问题地图，只记录每个节点解决的困难。第二遍带着“用一个真实系统复原《Algorithms》的判断过程”进入关键章节，把对象、状态和选择画出来。第三遍完成一个最小实现或评审，主动触发“NP 困难不等于所有实例都慢，也不等于启发式没有价值。”所描述的边界，再保存结果。

《Algorithms》的学习产物应当符合它处理的对象。围绕“问题规格与规模参数”建立的记录，需要一路支持到“归约和 NP 困难”。算法类结论要有证明和复杂度实验，系统类结论要有执行轨迹与资源测量，架构案例要保存驱动因素和备选方案，工程著作则要形成目标、规则和运行证据。摘抄只能保存信息，无法代替这些判断材料。

一周后重新完成案例，改动一个关键条件。读者若仍能选择方案、解释机制并提出验证办法，知识已经开始迁移。若只能回忆章节标题，就回到改动条件所在的小节补一次练习，无需继续扩大阅读清单。
