# 手搓解释器阅读综述

给一门语言增加函数，看起来只是多写一种语法。明确实现时，扫描器要认识新符号，解析器要建立语法树，求值器要保存环境，调用机制要管理参数与返回值，闭包还要让已经离开的局部作用域继续存活。Robert Nystrom 用 Lox 语言把这条因果链完整展开。全书最聪明的安排，是先写一个树遍历解释器，再用 C 写一个字节码虚拟机。同一种语言的表面行为不变，内部表示、执行成本和内存管理全部重做。

读完以后，读者应能从“树遍历解释器”追到“对象与垃圾回收”，说明中间的机制、代价和失败边界，并用“用一个报表表达式功能检验理解”完成一次可复查的应用。

## 全书怎样把代码送进运行时

语言表面 → 静态约束 → 中间表示 → 执行机制 → 资源生命周期 → 工程边界

原书路线可以压缩为下面这些节点。

| 学习节点 | 这一层处理什么 | 为什么在此时出现 |
| --- | --- | --- |
| 树遍历解释器 | 字符经过扫描和解析成为抽象语法树，解释器直接遍历节点求值 | 先获得清楚的语义和快速修改能力 |
| 静态作用域解析 | 解析器之后增加 resolver，提前确定变量指向哪一层环境 | 修复闭包中的绑定错误并把部分错误前移 |
| 字节码编译器 | 源码被压成常量表和紧凑指令，控制流变成跳转 | 把高层语义映射到可高效执行的表示 |
| 栈式虚拟机 | 指令通过值栈和调用帧运行，函数调用获得明确的运行时布局 | 理解解释开销、局部变量寻址和递归 |
| 对象与垃圾回收 | 字符串驻留、哈希表、闭包上值和标记清扫共同管理堆对象 | 把语言功能连接到资源生命周期 |

这条路线从“树遍历解释器”开始。作者先建立对象和问题，再逐步加入“字节码编译器”等约束，最后用“对象与垃圾回收”处理完整结果。顺序值得保留，因为后一层往往在修复前一层已经暴露的限制。

## 先把语言表面落到明确对象

### 扫描与 token

全书先用“扫描与 token”固定分析对象。扫描器只识别词法单元和位置，不负责决定表达式含义。这一定义决定后文能够讨论哪些状态、操作和保证。

错误位置必须从这一层保留到后续阶段。把源码、内部表示和运行状态并排画出，才能看见一项语言特性穿过了哪些层，也能定位错误最早在哪一层出现。

在“用一个报表表达式功能检验理解”中验证这项知识时，应留下一张源码到运行状态的映射图和一次最小执行记录。Unicode、缩进敏感语法和增量解析需要额外设计。带着这项限制进入“递归下降与优先级”，后面的结论才有清楚前提。

### 递归下降与优先级

“递归下降与优先级”承接前面已经建立的对象关系。不同优先级由分层语法函数表达，结合方向由递归位置决定。这里新增的规则会改变后续能够作出的判断。

加入运算符时要同时检查文法、AST 和错误恢复。实现时要追踪对象的创建、引用、转移和销毁。语法层看似局部的改动，常会改变环境、调用帧或堆对象的生命周期。

实践记录需要说明“递归下降与优先级”在正常条件下产生什么结果，并主动加入一个边界条件。复杂语法可能更适合生成器或 Pratt parser。若结果随之改变，就把差异带到“环境与闭包”继续处理。

### 环境与闭包

到了“环境与闭包”，原书开始处理上一环尚未解决的困难。函数捕获定义时可见的变量关系，调用时创建新的局部环境。理解它需要同时保留前一节的输入与限制。

闭包让函数成为带状态的值，也让生命周期跨越词法块。性能判断应落到执行次数、分配量和访问路径。只比较语言表面或单次运行，无法解释成本来自解析、调度还是内存管理。

这一节适合产出一张源码到运行状态的映射图和一次最小执行记录，让另一位读者能够复查选择。捕获语义、可变性和并发会进一步放大成本。尚未覆盖的输入、状态与环境，应在进入“字节码与值栈”时继续保留。

## 再沿执行路径进入资源与系统边界

### 字节码与值栈

接下来要处理“字节码与值栈”。编译器把表达式顺序变成压栈和弹栈指令。这一步把先前的局部结论送进更完整的执行或验证过程。

栈效果必须平衡，否则错误会跨指令扩散。把源码、内部表示和运行状态并排画出，才能看见一项语言特性穿过了哪些层，也能定位错误最早在哪一层出现。

把“字节码与值栈”用于当前项目时，先写明成立条件，再保留能够推翻结论的反例。真实虚拟机还要处理验证、调试和平台安全。下一节“调用帧与上值”要接住这项未解决的问题。

### 调用帧与上值

原书随后把视线转向“调用帧与上值”。每次调用保存返回位置和局部槽位，关闭的上值把变量搬到堆上。它补上的关系，正是后一部分能够继续推理的前提。

它解释递归、闭包和尾调用为何是运行时问题。实现时要追踪对象的创建、引用、转移和销毁。语法层看似局部的改动，常会改变环境、调用帧或堆对象的生命周期。

在“用一个报表表达式功能检验理解”中验证这项知识时，应留下一张源码到运行状态的映射图和一次最小执行记录。示例没有覆盖 JIT 与复杂 ABI。带着这项限制进入“垃圾回收”，后面的结论才有清楚前提。

### 垃圾回收

“垃圾回收”承接前面已经建立的对象关系。标记清扫从根对象追踪可达图，再回收未标记对象。这里新增的规则会改变后续能够作出的判断。

正确性取决于根集合和对象引用完整，性能取决于分配与暂停。性能判断应落到执行次数、分配量和访问路径。只比较语言表面或单次运行，无法解释成本来自解析、调度还是内存管理。

实践记录需要说明“垃圾回收”在正常条件下产生什么结果，并主动加入一个边界条件。生产运行时还需分代、并发或增量策略。若结果随之改变，就把差异带到“整本书的最终判断”继续处理。

## 沿一个程序追踪表示与执行

设想产品允许用户输入 `revenue - cost * rate`，随后又提出变量、条件、函数和自定义脚本。团队先定义语法和错误信息，再决定表达式能访问哪些数据。树遍历实现可以快速验证需求；当同一表达式被高频执行，才有理由编译成字节码。若函数能够长期保存局部变量，就必须实现闭包生命周期；若脚本由外部用户提供，还要增加执行步数、内存、权限和宿主 API 限制。这个案例说明，语言功能会穿过表示、执行、资源和安全边界，远不止编辑器里增加一个关键词。

这个案例需要同时写正常路径和失败路径。正常路径说明“扫描与 token”怎样经过中间机制到达“垃圾回收”。失败路径则改变一个前提，观察保证在哪里停止、哪个信号先出现、谁应采取动作。把两条路径放在一起，教材中的抽象才能进入工程判断。

## 做选择时怎样使用这些知识

| 情境 | 建议检查或采用的方向 | 选择依据 |
| --- | --- | --- |
| 需要快速验证 DSL | 树遍历解释器 | 实现直接，错误更容易定位 |
| 表达式被重复大量执行 | 字节码虚拟机 | 用编译成本换运行吞吐 |
| 只需少量可配置规则 | 受限表达式或配置 | 减少任意执行带来的安全面 |
| 要开放第三方扩展 | 沙箱、配额与能力接口 | 语言实现之外还需治理 |

表中每一行都要回到当前系统验证。以“需要快速验证 DSL”为例，团队可以先按“树遍历解释器”建立最小方案，再用“实现直接，错误更容易定位”检查选择理由。若规模、失败后果或维护方式变化，原来的推荐也要重新评估。

## 容易读错的地方

1. 只抄完代码，没有画出源码到运行时状态的数据流
2. 把 parser 的语法正确误当成程序行为正确
3. 看到虚拟机更快便跳过第一遍实现，结果无法解释语义
4. 把五百行教学运行时直接用于不可信输入

这些错误都能用本书自己的对象关系纠正。看到“只抄完代码，没有画出源码到运行时状态的数据流”时，返回“扫描与 token”重建问题；出现“把五百行教学运行时直接用于不可信输入”时，沿案例检查被省略的运行或组织条件。误解被定位到具体章节后，补学范围会更小，也更容易验证。

## 怎样进入编译与系统学习

这本书在软件与系统工程路线中承担“沿两次实现同一门语言的过程，理解语法、语义、运行时与性能如何互相约束”这一学习任务。正式学习先建立概念和机制，产物可以是最小实现、证明、数据模型、协议轨迹或架构决定。进阶学习再改变规模、并发、故障、安全或团队条件，比较原方案是否仍然成立。

最值得保留的判断包括以下内容。

- 语言表面特性必须在语法、表示、执行和错误中都有位置
- 静态分析可以在运行前补充解析器不知道的上下文
- 两种实现的对照比单独背编译器术语更有价值
- 性能优化要建立在可测的执行路径上
- 内存管理是语言语义的一部分
- 错误恢复和诊断直接决定开发体验

列表中的每项判断都应连接一份证据。以“语言表面特性必须在语法、表示、执行和错误中都有位置”为例，证据可以来自原书章节、自己的最小实验和项目中的一次应用。三者各司其职。原文说明概念从哪里来，实验检查机制，本地应用确认条件是否匹配。

## 三遍阅读怎样形成学习产物

第一遍沿“同一种语言为什么要实现两遍”建立问题地图，只记录每个节点解决的困难。第二遍带着“用一个报表表达式功能检验理解”进入关键章节，把对象、状态和选择画出来。第三遍完成一个最小实现或评审，主动触发“生产运行时还需分代、并发或增量策略”所描述的边界，再保存结果。

《Crafting Interpreters》的学习产物应当符合它处理的对象。围绕“扫描与 token”建立的记录，需要一路支持到“垃圾回收”。算法类结论要有证明和复杂度实验，系统类结论要有执行轨迹与资源测量，架构案例要保存驱动因素和备选方案，工程著作则要形成目标、规则和运行证据。摘抄只能保存信息，无法代替这些判断材料。

一周后重新完成案例，改动一个关键条件。读者若仍能选择方案、解释机制并提出验证办法，知识已经开始迁移。若只能回忆章节标题，就回到改动条件所在的小节补一次练习，无需继续扩大阅读清单。

答案要落到具体对象。回答里至少出现一个机制、一份证据和一项适用边界。能比较两个方案，并解释为何在当前条件下选择其中一个，说明阅读已经越过术语记忆。

## 总体评价

《Crafting Interpreters》最适合帮助读者完成“沿两次实现同一门语言的过程，理解语法、语义、运行时与性能如何互相约束”这项学习任务。它的核心跨度位于“扫描与 token”与“垃圾回收”之间。前者建立分析对象，后者把知识送到完整系统的边界。

后续论文和工具会更新实现与测量结果，本书保留稳定的问题结构。把原文当作知识坐标，用自己的代码、模型和运行结果校正边界，这份教材才能长期参与项目判断。
