# 《语音与语言处理》第三版阅读综述

用户在聊天框里输入一句话，系统返回一段通顺答案，这个界面很容易让人误以为自然语言处理只剩下“把文本送给大模型”。真正构建系统时，问题很快重新出现。文本怎样切成 token？模型输出的概率代表什么？检索结果怎样进入上下文？一个回答为何流畅却不真实？中文、英语和低资源语言能否用同一套评测？当任务从生成段落变成抽取实体、识别说话人或解析句法时，系统又应怎样改变？

Dan Jurafsky 与 James H. Martin 的《Speech and Language Processing》第三版草稿把这些问题放回一条完整的学科路线。2026 年版本以大语言模型开篇，却没有把 NLP 缩减成大模型使用说明。它先从词、token、概率、分类、向量和神经网络搭出语言模型，再进入后训练、检索、Agent、翻译和语音，最后回到词性、句法、事件、语义角色、指代与篇章结构。现代模型与传统语言结构在同一本书里相遇。

## 三分钟抓住全书

这部书最值得保留的是一条从语言材料到可评价系统的知识流。

```text
先决定什么算一个文本单位
        ↓
用概率和分类建立最小可计算任务
        ↓
用向量表示意义，用神经网络学习组合
        ↓
Transformer 预训练获得通用语言表示与生成能力
        ↓
后训练、检索和工具把基础模型变成任务系统
        ↓
翻译、语音、实体、句法、事件和篇章提出各自约束
        ↓
用任务指标、人工判断、群体切片和失败分析证明系统可用
```

读完整本书，应形成五个核心判断。

1. token、标签和语料边界由任务与处理方案共同确定，它们都会改变模型能学到什么。
2. 语言模型首先是对下一个 token 的概率分布；聊天、生成和 Agent 是建立在这个计算对象之上的系统形态。
3. 预训练学到广泛统计规律，但不自动保证事实、价值一致、任务成功或对所有语言公平。
4. NLP 不只有自由文本生成，检索、分类、序列标注、句法分析、信息抽取、翻译和语音各有明确对象与评测。
5. 一个指标只测量某个切面。数据来源、任务定义、错误后果与人工评价共同决定结论能否成立。

## 第一卷从 token 开始

第一章先澄清“语言模型”这个容易被产品界面改写的术语。技术上，语言模型接收前文，为下一个 token 分配概率。反复从分布中选择 token，并把已生成内容加入上下文，就形成从左到右的自回归生成。对话助手可以调用工具、保留状态和执行动作，但这些能力不应倒过来改变语言模型的基本定义。

这一区分很重要。若把模型说成“知道答案的智能体”，开发者容易把生成概率误当事实置信度；若知道它在产生条件续写，就会主动为知识来源、工具结果、验证与拒答设计外部机制。模型可以从大量文本预测中获得语言、概念和世界关联，也会同时吸收文本里的缺口、偏见和错误。

第二章追问模型处理的究竟是什么。人可以直觉地看见词，计算机得到的是字符编码和 token 序列。Unicode 规定字符如何表示，规范化处理会统一视觉相同而编码不同的字符串；形态学说明一个词可能包含词根、词缀和语法信息；BPE 等子词算法在词表大小、序列长度和未登录词之间折中。

tokenizer 属于模型系统的一部分。同一句话在不同语言中可能产生很不一样的 token 数量，直接改变上下文占用、推理成本和可学习单位。英语训练占比高的词表可能让某些语言被切得更碎。产品若按字符或“单词数”估算成本，而服务按 token 收费，就会产生系统性误差；模型若在 emoji、组合字符和特殊空格上表现异常，也应先检查编码与分词。

书中把正则表达式、Unix 文本工具、规则分词和最小编辑距离放在这一章，是为了让读者亲手接触文本边界。最小编辑距离随后会在拼写纠错、序列位置匹配和语音错误率中再次出现。这个基础的动态规划算法由此连接多个任务。

## 语料和标注先规定模型能学什么

第二章把 corpus 放在分词之后，顺序很有分量。语料是模型经验的来源，它包含哪些语言、体裁、时间、作者和采集条件，会限制模型能够估计的分布。新闻、社交媒体、客服记录和医学文本都由自然语言构成，它们的词汇、句式、事实更新速度和隐私要求却相差很大。一个在网页文本上表现良好的系统进入病历或方言对话以后，输入已经换了环境。

训练样本还要经过选择与清理。重复文本会让模型反复看见同一材料，也可能让测试内容混入训练；自动抓取会留下乱码、模板导航和机器生成文本；过滤规则可能删掉少数语言或特定社群的表达。数据量增大只能增加见过的材料，无法自动修复采集范围和过滤标准造成的偏斜。

监督任务还多了一层标签协议。情感分类中的“负面”可以表示说话者情绪、文本态度或产品评价，三种定义会产生不同标签。实体识别需要规定产品型号、机构缩写和嵌套实体怎样划分。指代消解也要决定泛指、缺省主语和跨段指代是否进入标注。标注者之间的分歧有时来自粗心，有时来自任务定义含糊；后者需要修改指南，不能简单用多数票盖过去。

语料说明应记录来源、用途许可、语言与体裁分布、采集时间、清理方法、重复处理和已知缺口。标注说明则要留下标签定义、正反例、争议处理与一致性结果。模型分数只有和这些条件放在一起，读者才能判断它能够迁移到哪里。

## n-gram 为什么仍值得学

第三章用 n-gram 模型建立语言建模的最小实验室。它根据有限历史中的计数估计下一个词的概率。假设很简单，读者却能在纸上算出训练集、测试集、似然、困惑度、采样、平滑和回退，直接观察语言模型怎样从数据分布得到行为。

未见过的 n-gram 若被赋予零概率，整句话的概率也会变成零。平滑把一部分概率质量留给未观察事件；插值同时参考不同长度的上下文；回退在长上下文证据不足时使用更短统计。这些技术不再是现代大模型的默认实现，但“有限数据无法覆盖未来输入”“概率质量如何分给未见事件”的问题从未消失。

困惑度衡量模型给真实序列分配概率的能力，只能在相同 tokenization、词表和测试数据上公平比较。一个模型因为把文本切得更细而得到不同困惑度，并不代表语言能力直接提高。更关键的是，较低困惑度通常有助于预测，却不能自动保证摘要忠实、对话安全或检索问答正确。指标必须与任务匹配。

n-gram 还把生成与评价接起来。采样按条件概率逐步形成输出路径。温度、top-k 与 top-p 等现代解码方法改变选择分布，进而改变重复、多样性与错误风险。这条直觉在 Transformer 时代仍然有效。

## 分类、向量和神经网络怎样汇入 Transformer

第四章选择逻辑回归，用它建立现代网络的基本组件。输入特征经过加权求和与 sigmoid 或 softmax，得到类别概率；交叉熵把正确标签的概率转成训练损失；梯度下降更新参数。多分类输出层、神经网络中的分类头以及语言模型的词表预测，都能从这里延伸。

分类章节把精确率、召回率、F 值、测试集、交叉验证和显著性检验与模型放在一起。因为预测只有进入评价合同才有意义。垃圾邮件、疾病筛查和有害内容检测的错误代价不同，不能只看准确率。群体样本量和标签定义也会让同一个总体分数掩盖不同伤害。

第五章从分布式假设进入向量语义。出现在相似上下文中的词，意义往往也相近。计数矩阵、余弦相似度和 word2vec 提供不同实现。向量把离散符号放进连续空间，使“相似”和“关系”可以参与计算，却也把训练语料中的社会关联编码进表示。词向量偏差从数据、目标和表示阶段就已开始形成。

第六章加入非线性和隐藏层。前馈网络把已有表示组合成任务需要的新表示；反向传播依据损失计算参数梯度。第七章最终把这些组件汇入 Transformer。token 与位置形成输入表示，自注意力让每个位置按内容选择其他位置的信息，多头机制允许不同关系并行，残差与归一化维持深层训练，语言模型头把隐藏状态映射回词表概率。

Transformer 由前面已经见过的向量、线性层、softmax、概率目标和梯度训练组成，新的关键在于信息交互结构。注意力权重表示当前计算怎样组合位置，却不能被轻率等同于人类解释。模型内部可视化需要与干预和因果证据区分。

## 预训练产生能力，后训练塑造可用行为

预训练让模型在大规模语料上反复预测 token。它不需要为每个下游任务单独标注，却能从上下文规律获得词义、句法、事实关联和任务模式。模型规模、数据规模和计算量共同影响结果，训练数据的语言、时间、质量与重复也决定知识边界。

会预测文本不等于会遵从用户。第八章把后训练分为指令微调、参数高效微调、偏好学习与基于偏好的对齐。指令数据展示任务与理想回答的关系；LoRA 等方法以较少可训练参数适配模型；偏好数据比较多个输出；奖励或直接偏好目标再推动模型更倾向被选中的行为。

这条流程会把“能力”和“行为”分开。基础模型可能已经拥有某种知识，却没有稳定地按指令表达；后训练可以改善格式、帮助性和拒答，也可能引入迎合、过度拒绝或特定风格。产品不能把后训练后的流畅度当成新知识证明，更不能把偏好标注者的选择当成全体用户价值。

第九章讨论 BERT 一类掩码语言模型。自回归模型只能利用左侧上下文预测下一个 token，掩码模型在训练中利用左右两侧恢复被遮盖内容，更适合分类和序列标注的编码器任务。编码器、解码器和编码器与解码器组合分别对应不同的信息可见性与输出方式。

## 解码过程也在决定最终答案

语言模型输出的是整个词表上的概率分布，系统还要从分布中决定下一个 token。贪心解码每一步选择最高概率项，速度快、结果稳定，却可能很早进入重复或局部不佳的路径。束搜索同时保留若干候选，适合机器翻译等需要比较完整序列的任务，候选数量增加也会提高计算开销，并可能偏好过短或过于常见的表达。

采样保留概率随机性。温度较低时，分布更集中，输出通常更稳定；温度升高以后，低概率候选获得更多机会，多样性和风险会一起增加。top-k 只在概率最高的固定数量候选中采样，top-p 则选取累计概率达到阈值的候选集合。两者都在截断长尾，但它们面对分布平坦或尖锐时的行为不同。

解码参数必须跟任务一起验证。法律条款抽取需要稳定和可核验，创意改写可以允许更多变化；工具参数生成往往还要加入语法约束，避免模型输出无法解析的结构。把一次随机生成的好结果当成模型能力，会忽略采样波动。可靠实验应固定提示、模型版本和解码配置，多次运行后报告成功率、失败类型与最坏后果。

解码也解释了为什么“模型置信度”需要谨慎使用。某个 token 概率高，只说明它在当前上下文与模型分布中占优。整段回答包含许多连续选择，事实正确性还依赖训练材料、提示、检索证据和生成路径。产品需要单独验证引用、实体、数字与行动结果，不能把输出概率直接翻译成答案可信度。

## 检索系统给模型什么，不能给什么

第十一章先讲倒排索引、词项权重、向量空间、精确率、召回率与排序指标，再进入稠密检索和 RAG。这一顺序很有价值。RAG 包含语料切分、索引、查询、召回、排序、上下文组装和生成，任何一步都可能改变答案。

检索可以让回答接触更新或私有材料，也能提供可引用证据。它不能自动保证材料被正确召回、上下文没有冲突、模型忠实使用证据，或者答案符合权限。没有召回时生成器可能依靠参数记忆继续作答；检索到错误文档时，流畅答案反而更危险。

评测因此至少分三层。检索层检查相关文档是否进入候选与前列；生成层检查答案是否由证据支持并覆盖问题；任务层检查用户是否真正完成工作。只用最终答案分数，很难知道失败来自查询、索引、排序、上下文还是生成。

书中紧邻 RAG 的问答评价说明，开放问题常有多种正确表达。精确匹配过于严格，模型裁判又可能偏好特定文风。可靠评价需要参考答案、证据、规则、人工复核和失败分类配合，不能把复杂判断藏进一个分数。

## 翻译与语音让“语言”重新变得具体

机器翻译章节从语言类型差异出发，再讲编码器与解码器、束搜索、低资源翻译、自动评价和伦理。不同语言的词序、形态与省略方式并不一致。模型必须在目标语言中重建意义与功能。束搜索扩大候选范围，却不能修复训练数据没有覆盖的文化和领域知识。

BLEU 等指标利用参考译文中的片段重合进行自动比较，适合规模化实验，不足以独立判断事实、语气、术语和可接受的多种译法。低资源语言尤其容易因测试集窄小而产生虚假的确定性。部署翻译系统时，需要按语言方向、领域和使用后果分开评测。

第十五至十七章从发音器官、音素、韵律和声学信号进入语音特征，再讲自动语音识别与语音合成。声音是连续信号，必须采样并转成可计算表示。Mel 频谱、MFCC、卷积、编码器与解码器、自监督语音模型和 CTC 分别处理声学表示、位置匹配与转录。

词错误率把替换、删除和插入与参考转录比较，是自动语音识别的核心指标，却会掩盖错误后果。把人名识别错一次，可能比十个虚词错误更严重；不同口音和环境噪声的总体平均也可能掩盖群体差异。语音合成的自然度同样不能只靠主观平均分，还要检查说话人相似、可懂度、滥用与身份风险。

## 第三卷说明 NLP 为什么不能丢掉语言结构

生成模型能够产生通顺文本，不代表词性、句法、事件和指代不再重要。第三卷把语言结构变成一组可标注、可预测和可评价的对象。

序列标注为每个 token 预测词性或实体标签。HMM 用状态转移和观察概率描述序列，CRF 对整条标签序列进行条件建模，神经模型则学习上下文表示。BIO 等标注方案决定实体边界怎样编码。评价实体识别时，token 层正确与完整实体跨度正确不是同一标准。

成分句法把句子组织成嵌套短语，依存句法直接表示词与词之间的中心和依赖关系。CKY 用动态规划搜索符合上下文无关文法的树，转换式和图式依存分析采用不同搜索空间。句法树记录某套标注规范下的结构；跨语言应用必须检查树库和关系定义。

信息抽取把关系、事件和时间从文本转成结构化记录。一个事件可以包含触发词、参与者、角色、地点和时间。模板填充要求系统先识别对象，再规范化并连接字段。对业务系统而言，这比生成一段摘要更容易接入数据库和规则，却也更依赖标签一致性与缺失处理。

语义角色标注追问“谁对谁做了什么”。PropBank 围绕谓词定义参数，FrameNet 以语义框架组织角色。不同谓词和表达方式可能描述相近事件，表层句法位置却不同。角色系统提供了从句法到意义的桥梁，也提醒读者，关系标签来自理论和标注协议，模型还可能学到其他划分。

指代消解与实体链接负责判断多个提及是否指向同一对象，并把对象连接到知识库。代词、省略、同名和篇章显著性都会制造歧义。篇章连贯与对话结构继续处理句子之间的关系、话轮、言语行为和共同背景。长文本系统若只增加上下文窗口，却没有处理实体延续、时间变化和对话状态，仍可能在局部流畅中失去整体一致。

## 用一条客服问答链检查全书知识

假设要建设一个支持中英文的售后助手。用户会描述故障、上传订单号、查询政策，也可能要求系统退款。

数据层先确定文本单位和权限。历史工单是否包含个人信息，中文与英文怎样规范化，订单号和产品型号是否需要保护为整体 token，人工标签中的“已解决”究竟表示用户确认还是客服关闭，都要写清。若把关闭状态当满意标签，模型会学到错误目标。

模型层不能只选一个聊天模型。政策问答需要检索和证据，故障描述可能需要分类或实体抽取，退款动作需要工具与授权。检索语料要版本化，文档分块不能切断条件与例外；生成回答必须引用有效片段；工具调用要使用结构化参数，并在金额或权限边界前请求确认。

评测层按链路拆开。分词和语言识别错误影响后续路由；检索检查召回与排序；回答检查事实支持、完整性和拒答；实体抽取检查订单号与产品型号；工具调用检查参数、权限和幂等；任务层观察用户是否解决问题、是否转人工以及错误成本。中英文、不同产品线和高风险操作需要单独切片。

运行层还要观察语料更新、模型版本和用户行为变化。新政策上线而索引未更新，会让模型稳定引用旧规则；模型升级可能改变格式和拒答；用户发现某种表达更容易获得退款，输入分布也会变化。数据、模型、检索、工具和人共同组成 NLP 系统，并在反馈中持续变化。

## 容易读错的七个地方

1. **语言模型不等于聊天产品。** 前者预测 token 分布，后者还包含提示、检索、工具、状态、权限和界面。
2. **token 不等于词。** 切分方式影响长度、成本、多语言公平和模型行为。
3. **困惑度低不等于任务成功。** 它评价序列概率，不能替代事实性、安全性和用户结果。
4. **预训练知识不等于可靠数据库。** 生成来自统计条件分布，仍需来源、检索和核验。
5. **RAG 不等于事实保证。** 召回、排序、上下文和生成各自可能失败。
6. **大模型没有取消结构化 NLP。** 实体、关系、时间、句法和指代仍是很多系统的可验证中间结果。
7. **总体平均不能说明所有语言都可用。** 语言、方言、领域和群体必须分别检查。

## 怎样使用这本书学习 40 个节点

第一遍建议按依赖关系读。先读第 1 至 7 章，完成 token、n-gram、分类、向量、神经网络和 Transformer 的主线；再读第 8、9、11 章，理解后训练、编码器模型与检索；随后根据方向选择翻译和语音，或进入第 18 至 26 章的语言结构。

每个主题都应留下一个最小实验和一张错误表。分词主题可以比较两种 tokenizer 对中英文、数字和特殊符号的切分；语言模型主题比较训练内外文本的困惑度；分类主题报告精确率、召回率与关键切片；检索主题分离召回和回答错误；结构化任务则检查跨度、关系和标注分歧。

阅读笔记不宜只抄术语定义。更有效的记录包含五项，分别是处理对象、输入输出、模型假设、评价证据和失败位置。例如“RAG”笔记若没有语料、切分、索引、召回、排序、生成与权限，就还只是一个名词。

## 全书没有替你解决的事情

这部草稿覆盖面极广，但宽度也意味着许多主题需要专门资料继续深入。它不会提供完整的大模型分布式训练手册，也不足以单独指导生产 Agent、提示注入防御、模型路由、缓存和成本治理。跨语言公平、数据许可、隐私与高风险行业责任，也必须结合地区法规和真实用户研究。

它最重要的价值，是把近年的大模型重新接回 NLP 学科。token 来自文本表示，预训练建立在概率建模上，Transformer 负责信息交互，检索与工具构成外部系统，翻译和语音暴露语言差异，句法语义提供可验证结构，评价则把所有能力送回具体任务与人群。

继续深入时可以按缺口选择资料。要研究检索，应补充索引、学习排序和查询评价；要训练大模型，应补充数据治理、分布式优化和缩放规律；要做多语言系统，应阅读目标语言的形态句法、语料资源和本地用户研究；要部署 Agent，还要学习工具协议、权限、状态、停止条件与攻击面。这样扩展仍然围绕一个明确任务，不会把所有新论文混成同一条时间线。

## 读完以后应能回答

- 为什么语言模型首先被定义为下一个 token 的概率模型？聊天产品还增加了哪些系统组件？
- tokenizer 会怎样影响上下文、成本、未登录词和多语言表现？
- n-gram、逻辑回归、向量语义与神经网络怎样一步步汇入 Transformer？
- 预训练、指令微调和偏好学习分别改变了什么？
- RAG 的失败应怎样定位到检索、上下文、生成或任务层？
- 为什么实体、句法、事件、指代和篇章分析在大模型时代仍然有用？
- 一个 NLP 指标能够证明什么，又不能证明什么？

把这些问题带回一个真实语言系统，并为每一层写出数据、模型、评价和失败边界，读者便能形成一套可以持续更新的 NLP 判断框架。
