# CSDIY 写作视角与认知框架

## 它怎样判断一个内容值得写

CSDIY 很少从“这个领域有哪些知识”开始。它先寻找学习者的能力缺口，再判断哪门课能通过真实练习改变理解方式。工具、调试、版本管理和代码质量会被优先收录，因为正规课程常忽略它们，缺失以后又会持续拖慢学习。

候选内容进入路线前，要通过下面的判断。

1. 它是否解决一个可观察的能力缺口。
2. 学习者是否会通过作业或项目真正使用这项能力。
3. 资料、环境与反馈是否允许外部学习者完成。
4. 成本是否与收益匹配，困难是否能够被诚实说明。
5. 不适合主路线的人是否有补桥或替代方案。

热点只有能进入成熟学习路径时才值得加入。仅仅新、流行或来自名校，不构成教学价值。

这不是从目录词频反推的作者心理。31 篇完整页分别记录了可见的判断链：`Algo.md` 用“为什么—如何实现—实际应用”回答学了就忘，`N2T.md` 用最终可运行系统支撑成果想象，`15445.md` 把开放评测与版本失效都算入课程质量，两个 roadmap 先限定受众再拆方向。证据链见 [_meta/review-evidence.json](./_meta/review-evidence.json)；“作者意图”超出页面可见内容时保持未知。

## 它怎样使用来源

原站提出“源代码、官方文档、英文书籍、英文博客、中文博客”的信息损失次序。这套次序用来分配来源责任。一手材料负责校准事实和机制，二手材料负责压缩、类比、排障和交流。

一个可执行的来源包包含五层。

| 层次 | 在学习中的责任 |
|---|---|
| 官方定义 | 确认范围、版本与要求 |
| 系统讲解 | 帮助建立概念关系 |
| 掌握证据 | 用作业、测试或 Autograder 验证能力 |
| 执行补丁 | 解决失效链接、环境和版本差异 |
| 经验支持 | 提供真实成本、踩坑和讨论入口 |

正文必须区分来源事实、个人体验、社区经验和编辑推断。来源记录除了 URL，还要写用途、版本、访问状态、最后核验日和不可推出的结论。

语料元数据也采用同一纪律。136 页都记录 `title/date/author/column/article_type/topic_tags/hook_type/structure_pattern/source_types/word_count/notable`，但“记录”不等于“已知”：正文只明确支持 2 页作者和 1 页日期，其余写 `unknown`；Git 的最后变更时间另列，不能替代发布日期。

## 七条认知命题

1. 教学质量由学习者能否掌握来判断，不由学校名气来判断。
2. 实践承担认识机制、发现隐藏假设的主要任务。
3. 脚手架与自由度没有绝对优劣。新手需要快速反馈，进阶者需要设计空间。
4. 难度是学习合同。数学、编码、环境、语言和时间成本都应提前说清。
5. 学习路线应按目标和基础分叉，学习者无需把整张清单逐项完成。
6. 自学依赖资料、环境、测试、社区和复习系统，不能只诉诸意志力。
7. 开放性、版本可复现和反馈机制本身就是内容质量的一部分。

## 对 Learning 007 的直接约束

每个阶段启动前新增一份学习决策卡，至少说明读者、结果、前置、投入、产物、验证、风险和替代路线。每篇文章仍然只围绕一个关键判断展开，但开头要告诉读者它在整条路线中的位置，结尾要把本章产物交给下一步。

“推荐”必须回答为什么选它、放弃了什么、谁不该选和什么信号会触发重选。“很难”必须拆成困难维度和可见阻塞。“完成练习”必须写成可提交的产物和验收证据。

最重要的迁移，是把资料综述写成一份带证据、成本、风险、替代与验收的学习决策。

七条命题是跨页归纳，不是七个固定正文区块。一次工具教程可以主要靠问题演化和流程图推进，一张课程卡可以在三段内结束，一篇机制讲义则仍需较长案例。只要读者获得的决策功能完整，就不要求表面结构相同。
