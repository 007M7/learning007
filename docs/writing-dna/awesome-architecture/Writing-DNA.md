# Awesome Architecture Writing DNA

这是一份用于 Learning 007 课程重写的执行规则。它来自对参考仓库 40 篇中文教程的全量统计与结构复盘，以及至少 20 篇完整文章的逐字深读。借鉴教学方法与信息结构，不复制原文案例和句子。

机器学习第一章多轮改写形成的执行步骤与放行条件，见[学习文章改写 SOP](./学习文章改写SOP.md)。SOP 统一学习入口与审稿标准，正文仍然根据时间、决策、实验、故障或比较关系单独设计。

从领域来源库到四十章课程、阶段总结和整板块验收的完整建设流程，见[领域知识库与学习内容建设 SOP](./领域知识库与学习内容建设SOP.md)。

## 1. 先设计课程，不先生成文章

一个领域约 40 章，分成六段：入门心智 → 核心工具 → 机制深水区 → 连续实战 → 工程决策 → 前沿与治理。每章只解决一个会导致错误判断的问题；上一章的产物要成为下一章的输入。每组末尾安排整合章或决策树。

## 2. 一章只有一条主线

开头用真实任务、常见误解、事故或两难说明为什么值得学。先让读者发现旧直觉不够，再给大白话心智模型和精确定义。正文围绕一条因果链逐层推进，不能把“概念、论文、代码、案例、治理”拆成互不相干的固定栏目。

## 3. 按知识类型选文体

- 概念启蒙：误解 → A/B 故事 → 定义 → 迁移。
- 原理深挖：现象 → 变量 → 最小例子 → 公式 → 反例 → 证据。
- 跟做实战：明确单一技能 → 分步跟做 → 指标/停止条件 → 变式 → 独立迁移。
- 决策选型：约束 → 比较尺子 → 候选与代价 → 触发信号 → 退出路线。
- 案例复盘：事件链 → 首个失真假设 → 直接/系统/组织原因 → 防复发。
- 前沿综合：旧范式瓶颈 → 新证据 → 稳定机制/近期结果/未知问题分层。

## 4. 语言像教练，不像报告

先说人话再说术语；用“为什么”“如果失败会怎样”“真正要区分的是”推动推理。长解释后用一句短判断收束。粗体只标记决策变量和结论。禁止批量出现“核心机制、证据审计、产品影响”等报告标题，禁止把论文写成重复摘要卡。

## 5. 证据进入推理链

书籍负责稳定知识骨架；经典论文解释范式从何而来；近三年论文修正能力边界；标准和事故限定部署条件。每份来源回答：它研究什么、怎么得到结果、改变了哪个判断、不能外推什么。引用数只是筛选信号，不替代阅读。

## 6. 视觉承担关系

参考站 40 篇没有 Markdown 栅格图片，却有 37 篇文本关系图和 31 篇表格。只在因果、时序、层级、分叉或多对象比较难以用短文说明时画图/表。图后解释关键箭头；表只放同字段比较；代码块必须能运行或能表达流程。

## 7. 学习闭环必须可验收

每章至少交付一个可审阅产物，并覆盖跟做、变式、迁移中的两个层次。练习必须暴露失败边界，不以“运行成功”作为掌握证据。结尾小结能脱离正文复述，最后一句自然说明下一章为什么接在这里。

## 8. 密度标准

参考站单篇平均 8,602 字符、范围 3,494—18,135。Learning 007 的核心机制与实战章目标 6,000—12,000 字符，选型/组织章目标 4,000—8,000 字符；长度只是结果，重复和堆链接不计入密度。每 800—1,500 字符至少出现一次真正承载信息的算例、关系图、表、代码、案例或决策产物。

## 9. 复杂度与责任

默认保留简单基线；只有真实瓶颈才购买复杂度。每个方案写明收益、代价、失败模式、复审触发与退出路径。AI、机器人与低空等高影响主题还必须写权限、观测、降级、接管和人类责任边界。

## 10. 交稿自检

去掉标题后，正文是否仍只能属于本章？读者是否能复述一个因果模型？来源是否改变了判断？练习是否产出可检查的东西？是否知道何时不用这套方法？如果任一答案是否定的，文章还不是课程。
