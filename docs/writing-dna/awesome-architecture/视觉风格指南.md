# Awesome Architecture 视觉风格指南

## 真实统计

- 40 篇中文教程中，Markdown 栅格图片为 **0**。
- 37 篇有 ASCII/文本关系图，占 **92.5%**。
- 31 篇有 Markdown 表格，占 **77.5%**。
- 每篇平均 6.05 个代码或文本图块、13.85 行表格。
- 每篇平均 69.38 处粗体强调。

因此它的“可视化”不是装饰插画，而是让关系变得可扫描。

## 图的功能

只在以下关系难以用两三句话说清时使用：

- 因果链：输入如何经过机制变成输出；
- 状态变化：系统在一次事件前后如何迁移；
- 决策分叉：满足什么条件走 A 或 B；
- 层级结构：哪些层向下约束哪些层；
- 演进路线：MVP 到规模化之间发生了什么变化。

文本图之后必须跟解释：图里最重要的箭头是什么、失败会从哪里传播。不能放完图就结束。

## 表格的功能

表格只承载“多个对象按完全相同字段比较”。典型列是：候选、适合、代价、触发信号、退出条件。不要把长段落硬塞成表格，也不要用表格重复正文。

## 排版节奏

- H1 后是一句灰底引用式点题，读者在首屏知道冲突与承诺。
- H2 是推理步骤，平均约 10 个；H3 只在局部需要拆解时出现。
- 正文平均每段不到两句，长机制拆成短段，但不把每句话都单独成段。
- 代码块既承载代码，也承载文本图、流程和模板。
- 横线用于大段阶段切换；粗体用于判断，不依赖彩色高亮。
- 品牌色是低饱和绿色（`#2f8a6b` / `#3c8772`），其余保持 VitePress 的黑白灰层级。

## 图片抽样结论

按 skill 要求检查了 5—10 篇视觉内容；源码中没有需要逐张解读的外部图片。截图里看到的灰色结构块，实际主要由 Markdown 表格、引用和代码块渲染。Learning 007 不应为了“像参考站”盲目增加配图，而应优先复制它的图文分工：文字讲因果，文本图讲关系，表格讲比较，代码讲可执行过程。
