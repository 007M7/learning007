# Learning 007 领域知识库与学习内容建设 SOP

这份 SOP 来自机器学习板块从资料检索、教材综述、四十章改写、五次阶段复盘到整板块总结的完整实践。它解决三个连续问题。

2026 年 9 月又完成了对 [CSDIY](https://csdiy.wiki/) 136 个中文页面的全量分析。这次校准补入了学习者分流、先修就绪检查、作业价值、真实投入、资源可执行性和替代路线。详细依据见 [CSDIY Writing DNA](../csdiy-wiki/Writing-DNA.md)。

1. 怎样建立一个能持续维护的领域知识库。
2. 怎样把知识库整理成由浅入深的领域课程。
3. 怎样把每个主题写成读者真正能学会的文章。

三件事必须分开管理。知识库保存来源和知识关系，课程安排学习顺序与产物，文章负责一次具体教学。来源数量很多，不代表课程已经成立。路线图画完，也不代表文章已经写好。

整套建设遵守一个更靠前的顺序：**先对齐意图，再审目录，再审一篇完整样稿，最后才允许补全。** 这四步是人工验收门，不是可以由生成器连续执行的四个任务。上一阶段没有得到用户明确确认，下一阶段不得开始。

## 一、先明确最终要交付什么

一个完整领域至少交付六类成果。

| 成果 | 解决的问题 | 主要读者 |
|---|---|---|
| 领域来源库 | 哪些书籍和论文值得长期使用 | 作者与维护者 |
| 证据账本 | 当前结论由什么支持，边界在哪里 | 作者、审阅者与读者 |
| 领域知识图谱 | 概念之间有什么前置、组成、比较和应用关系 | 课程设计者与读者 |
| 分阶段学习路线 | 读者应当按照什么依赖顺序学习 | 读者 |
| 正式学习文章 | 一个主题怎样被理解、应用和检验 | 读者 |
| 阶段与板块总结 | 多章知识怎样组合、迁移并形成完整能力 | 读者与审阅者 |

学习者的目标、进度、练习成绩和复习计划属于另一类数据。它们可以引用课程节点，不能写回公共知识节点。知识事实、课程安排和个人掌握状态混在一起，后续很难维护，也容易把一次答题结果误写成知识结论。

## 二、领域启动前先对齐意图并写建设合同

检索开始以前，先与用户完成一次意图对齐，再把确认结果写成一页领域建设合同。它约束后面的来源、章节和验收，不能由作者根据相邻领域自行补齐。

### 意图对齐卡

第一次汇报只回答下面这些问题，不检索、不写目录、不生成正文。

| 对齐项 | 需要确认的内容 |
|---|---|
| 建设对象 | 这次建设知识库、教材综述、正式课程，还是其中一部分 |
| 领域边界 | 必须覆盖什么，明确不包含什么，与哪些模块复用或分开 |
| 目标读者 | 起点、使用目的、阅读负担和预期产物 |
| 内容标准 | 文章承担系统教学、快速综述、证据索引还是前沿跟踪任务 |
| 来源标准 | 教材与论文的数量、权威性、开放全文、新鲜度和语言要求 |
| 样稿对象 | 用哪一本教材或哪一章作为第一篇完整样稿 |
| 验收基准 | 用户主要审阅选材、结构、密度、语言、格式和可读性的哪些方面 |
| 本轮边界 | 当前只做到哪一道门，是否包含构建、提交或推送 |

存在低风险未知项时可以提出默认建议，但必须把建议标为待确认，不能把模型推断写成用户要求。用户明确确认以后，把结果写入建设合同并标记核验日期。只有修改意见、局部讨论或“先看看”不等于整阶段通过。

### 领域边界

写清领域名称、主要对象、希望解决的问题、与相邻领域的边界。机器学习可以覆盖统计学习、经典模型、泛化、因果、可信与生产系统；深度学习里的大规模多模态训练可以作为相邻领域，不必全部塞进同一条主线。

### 目标读者

说明读者已有基础、学习目的、能投入的时间和希望完成的作品。默认读者聪明、有兴趣、缺少系统前置。文章要把专业关系讲清，不能假定读者已经理解论文里的所有符号。

先修要分成硬门槛、有帮助和可边学边补三类，并附一个就绪检查。学习成本分别记录概念、数学、编码、环境、英文和时间，不能合并成一个星级。目标读者也要知道自己何时应当补桥、选择最小完成路线或暂时停止。

### 板块出口

用一项可观察成果描述学习完成后的能力。机器学习板块的出口是一套能解释任务、数据切分、基线、校准、因果边界、偏移与上线监控的预测系统。

“系统了解机器学习”无法验收。“能为一个真实任务建立可重放实验，比较候选并说明何时拒绝上线”可以验收。

### 内容规模

大型技术领域默认规划约四十个独立主题。四十是知识密度的起步参照，不是必须锁死的篇数。必要前置无法在现有章节讲清时可以新增，两个主题共享同一认知难点和同一产物时可以合并。

一个主题对应一个学习节点和一篇文章。禁止先定十个大主题，再把每个大主题平均切成四篇。那种拆法按数量生产页面，很容易让四篇共享同一内容，只剩标题不同。

### 来源规模

大型技术领域的初始公开目录至少准备十本权威教材或开放专著、一百篇能够覆盖主线的核心论文。数量只是一项覆盖门槛。每个主要模块仍要检查是否有稳定教材、奠基论文、近期修正材料和部署边界来源。

### 证据截止

为板块记录证据核验日期。稳定定理和经典机制不因年份淘汰；模型能力、基准结果、软件、标准、法规和产业状态使用近期一手来源，并写清日期与适用范围。

### 第一道人工作业门：意图确认

向用户汇报建设合同的摘要、仍待决定的项目和下一阶段将产出的目录格式。收到明确确认后才开始系统检索。若后续发现来源不足以支撑已确认范围，应退回本门重新缩放边界，不能暗中更换主题或降低标准。

## 三、知识库建设 SOP

### 第一步先画来源地图

检索以前先列出领域模块。模块应当覆盖学科主线，不能根据搜索结果临时拼接。

机器学习来源库采用六个模块。

1. 入门与统计学习。
2. 数学、优化与泛化。
3. 经典模型与表格学习。
4. 数据、评测与分布偏移。
5. 因果、公平、安全与不确定性。
6. 生产机器学习。

其他领域需要重新设计模块。可以参考这个粒度，不能复制这些名字。

每个模块先写三个问题。

- 哪些稳定知识需要教材系统解释。
- 哪些方法必须回到原始论文理解。
- 哪些近期结果会改变能力边界或部署判断。

这一步完成后，检索才有明确缺口。否则搜索工具会不断返回热门内容，来源数量快速增加，学科结构仍然残缺。

### 第二步先确定权威候选，再用搜索补全

书籍候选优先来自大学课程书目、作者主页、正式出版社的开放版本、学术组织和领域内反复引用的教学材料。课程可以帮助发现教材，公开知识库当前只收录书籍和论文，不把需要登录、无法完整访问的课程页面混入教材目录。

论文候选先沿教材参考文献、综述、经典方法脉络和主要会议期刊展开，再用 Tavily、OpenAlex、arXiv 和学术搜索补全。搜索负责发现和定位，不能替代学术判断。

推荐顺序如下。

```text
学科模块
  → 权威教材与课程书目
  → 教材引用的奠基论文
  → 高质量综述中的代表论文
  → 近三年一手研究与独立评测
  → 标准、官方工程资料与事故研究
  → 搜索补齐遗漏主题
```

先查清哪些材料值得找，再让搜索工具执行查询。直接要求搜索工具给出“一百篇核心论文”，结果通常会混入重复条目、低相关论文和只有标题的页面。

### 第三步核验全文入口

公开目录只保存能够直接阅读的保真 URL 和结构化元数据，不下载、不镜像原文。书籍链接应直接打开作者维护的在线正文或 PDF。购买页、登录页、只有简介的页面不能标记为可读教材。

论文优先使用 arXiv PDF、PMLR、JMLR、正式会议论文集、期刊全文或作者主页 PDF。DOI 落地页可以作为身份信息，读者入口仍应尽量指向全文。

每个 URL 至少核对以下内容。

- 标题、作者和版本与记录一致。
- 页面无需登录或购买即可阅读全文。
- 链接打开的是正文，不是搜索结果或商品页。
- 来源域名属于作者、学校、会议、期刊或可信档案。
- 核验日期已经记录。

URL 可访问只说明材料能被读到。它不说明作者已经读过，也不说明文章可以引用该材料。

### 第四步建立结构化来源记录

书籍记录至少包含下面这些字段。

```json
{
  "id": "book-islr",
  "field": "machine-learning",
  "type": "book",
  "title": "An Introduction to Statistical Learning",
  "creator": "作者",
  "year": "版本年份",
  "modules": ["foundations", "classical"],
  "level": "starter",
  "role": "它在本领域承担的教学作用",
  "content_url": "https://直接正文地址",
  "review_url": "/knowledge-base/reviews/...",
  "access": "open",
  "verification": {
    "status": "fulltext-url-verified",
    "checked_at": "YYYY-MM-DD"
  }
}
```

论文记录除标题、作者、年份和全文地址外，还应保存主题、发表位置、DOI 或稳定 ID、来源查询、权威等级、入选理由、开放状态和检索日期。引用量可以帮助排序，不能单独决定是否权威。

所有记录使用稳定 ID。标题修订、链接迁移和版本更新不能产生新的重复来源。入库前先检查 ID、标题、DOI 和规范化 URL。

### 第五步提交教材与论文目录审阅

这一轮只交付**教材与论文目录**，不批量写教材综述，也不开始正式学习文章。目录需要让用户能够判断“选了什么、为什么选、覆盖了什么、还缺什么”。

目录审阅包至少包含下面四部分。

1. 教材清单：作者、版本、承担的教学任务、覆盖模块、直接全文 URL 和核验状态。
2. 论文清单：稳定 ID、年份、发表位置、主题、入选理由、全文 URL 和新鲜度分层。
3. 覆盖矩阵：每个领域模块分别由哪些教材、经典论文和近三年研究支持。
4. 排除与缺口：被排除的购买页、登录页、非系统性材料、重复来源，以及仍未覆盖的问题。

目录达到数量门槛但模块分布失衡，仍然不能通过。用户可以要求删除漂移材料、替换版本、增加某一模块或调整新鲜度。修改后的目录重新提交，得到明确确认后才进入阅读和样稿阶段。

### 第六步把目录状态与阅读状态分开

目录中的来源使用可访问状态。

```text
candidate
  → fulltext-url-verified
  → unavailable 或 retired
```

正式写作使用阅读证据状态。

```text
catalogued
  → retrieved 或 opened
  → read
  → cited
```

两套状态不能混用。看到书籍介绍页只能记为候选，打开正文也只说明已取得阅读入口。只有记录了具体阅读范围、采用观点和边界以后，才能标记为已读。文章参考资料真正引用该来源以后，才能标记为 cited。

若项目政策要求只保存 URL，阅读证据可以记录章节、页码、访问日期和采用观点，不保存原文文件。若来源允许本地保存且用户明确授权，可以额外记录工件摘要和哈希。两种方式都不能伪造已经阅读的范围。

### 第七步为每章建立阅读证据

一条章节阅读记录至少说明以下内容。

| 字段 | 内容 |
|---|---|
| lesson | 文章稳定 ID |
| learning_job | 本章要让读者学会的判断 |
| source_ids | 实际阅读并使用的来源 |
| read_scopes | 阅读的章节、页码或论文部分 |
| claims_used | 从来源采用的机制、边界与反例 |
| claims_rejected | 来源没有证明、正文不应外推的结论 |
| updated_at | 最近核验日期 |

每篇正式文章至少有两份真正相关的来源。稳定机制优先由教材或经典论文支持，近期能力结论尽量加入近三年一手研究或独立评测。高风险主题还需要标准、监管或领域责任材料。

阅读笔记不直接进入正文。作者需要把来源消化成教学关系。正文连续出现“某书第几章说了什么”“某论文采用了什么方法”，说明阅读报告泄漏进了学习文章。

### 第八步建立证据账本

证据账本面向读者，条目只保留会改变判断的来源。每条记录包含日期、来源、课程采用的证据、不允许外推的范围。

来源冲突时保留双方。先比较任务、数据、人群、预算、指标和时间，再把冲突转成适用范围或本地实验。不能按发布日期、新旧排名或作者声望直接裁决。

证据账本还要写更新触发器，例如出现跨环境独立复现、标准变更、许可证变化、基准发现泄漏、公开链接失效。触发器比固定更新时间更有价值。

### 第九步只为一本教材撰写完整样稿

目录确认后，先选择对该领域有代表性、能够暴露结构问题的一本教材，完成一篇达到最终发布标准的阅读综述。它不是缩短版提纲，也不是批量模板预览。读者点击教材时先进入综述，再决定是否打开原文。综述不能是目录翻译，也不能只有几段推荐理由。

每本教材综述至少完成下面几项工作。

- 说明作者要解决的中心问题和全书组织方式。
- 按知识推进解释各部分承担的工作。
- 选择几个关键概念深入讲清，给出例子或公式直觉。
- 指出全书强项、默认前提、过时部分和适用读者。
- 说明它与领域课程哪些章节相连。
- 保留可直接阅读全文的原文 URL。

综述的信息密度以读者能否快速说清全书结构衡量，不能用统一字数复制十三次。理论教材、实践手册和社会技术著作需要不同结构。

样稿提交时同时说明：实际阅读范围、正文采用的判断、没有采用的内容、原文入口和本篇选择这种结构的原因。来源审计保留在内部记录，正式综述不能出现“本章怎样使用原稿”一类制作说明。

用户审阅样稿时，重点确认内容选择、知识推进、可读性、专业判断、篇幅密度、标题层级和页面格式。每轮反馈只修改这篇样稿，直到用户明确确认。不得一边等待审阅，一边生成其余综述。

### 第十步冻结原则并补全其余内容

样稿确认后，将通过审阅的判断沉淀为本领域写作约束，包括读者起点、内容密度、引用方式、版式、禁用写法和验收示例。沉淀的是原则与质量基线，不是固定小标题模板。

随后才能补全剩余教材综述。每本书根据自己的论证顺序、知识类型和读者用途重新设计结构。批量阶段按可审阅的小批次推进；发现结构复制、内容漂移或密度下降时，停止扩写并回到已确认样稿比较。

### 第十一步运行知识库验收

至少检查以下项目。

- 教材数量达到领域合同要求。
- 核心论文数量和模块覆盖达到要求。
- 每个资源 ID 唯一，模块引用有效。
- 教材综述页面存在，原文 URL 可访问。
- 购买页、登录页和只有摘要的论文入口被排除。
- 公开目录没有混入本地路径、下载工件或敏感字段。
- 阅读状态与 URL 核验状态没有混淆。
- 证据账本记录支持范围、冲突和更新触发器。

机器学习库当前使用 `npm run kb:validate` 验证数量、字段、模块、直接全文 URL 和综述页面。

## 四、从知识库到领域课程的 SOP

### 第一步把来源目录转成知识节点

教材目录适合发现概念，不能直接变成课程目录。课程需要把概念重新组织成读者能够完成的判断。

每个知识节点记录稳定名称、必要前置、组成部分、比较对象、适用任务、主要来源、失败边界和验证项目。常用关系包括下面这些。

- prerequisite-of 表示必要前置。
- part-of 表示组成关系。
- applies-to 表示应用场景。
- compares-with 表示有意义的比较。
- supports 表示来源支持某项主张。
- challenges 表示来源质疑或限制某项主张。
- demonstrated-by 表示项目能够验证该技能。

同义概念归入一个主节点，别名保留。相同词在不同领域含义不同，需要增加限定词。来源的结论不能合并成无条件事实。

### 第二步先设计阶段出口

一条领域路线通常可以划分成四至六个阶段。阶段名称和数量由领域能力发展决定。机器学习使用五个阶段，只能作为一个经过验证的例子。

每个阶段先写五件事。

| 项目 | 必须回答的问题 |
|---|---|
| 阶段出口 | 读者最后能够独立完成什么工作 |
| 阻塞前置 | 缺少哪些判断时无法完成出口 |
| 章节产物 | 每章留下什么，后续怎样继续使用 |
| 掌握证据 | 读者需要解释、应用和迁移到什么程度 |
| 后续边界 | 哪些问题留给下一阶段 |

阶段还要提供路线分流。主路线服务默认读者，最小完成路线服务时间有限者，补桥路线服务先修不足者，进阶出口服务已经具备相关能力者。分流依据必须来自可观察条件。

阶段章节数可以不同。机制复杂的阶段可以增加章节，生产收束阶段可以较短。为了视觉整齐给每阶段安排相同篇数，会扭曲知识依赖。

### 第三步把约四十个主题排成依赖序列

每个主题只解决一个会导致错误判断的问题。标题写出读者要处理的对象，问题句暴露真实矛盾，产物说明学完后留下什么。

一个课程节点至少包含这些字段。

```text
stable id
stage
slug
title
lesson lens
guiding question
observable outcome
prerequisites
core sources
insight
```

lesson lens 用来提示合适文体，可以是概念、机制、推导、跟做、案例、决策、前沿或综合。它不负责生成固定目录。

排顺序时从阶段出口倒推。先找完成任务必须作出的判断，再找每项判断需要的前置。来源章节顺序、算法流行度和搜索热度都不能替代这一步。

### 第四步为相邻章节写交接合同

每章动笔前补完三句话。

1. 本章从上一章接过哪份已经完成的产物。
2. 本章只新增哪个判断，哪些相关问题暂不处理。
3. 本章把什么结果交给下一章。

相邻章节都谈数据或评价时，这份合同尤其重要。删掉标题以后，如果两篇大部分正文可以互换，章节边界尚未成立。

共同案例可以跨章复用，帮助读者减少背景负担。每章必须有新的矛盾、调查动作和产物，不能让一个案例变成多次释义。

### 第五步明确掌握标准

课程完成度由证据决定，不由阅读页数决定。

基础掌握至少需要一次不看答案的准确解释、一次基础应用成功，最近相关练习平均达到 7 分。熟练掌握还需要解决变式、说明常见错误或失败边界，最近证据平均达到 8.5 分，并在不同日期出现两次。

每章练习只能使用正文已经教过的概念。单次选择题用于发现误解，不能单独证明掌握。综合项目、迁移任务和实际作品承担主要验收。

### 第六步每个阶段增加阶段总结

阶段总结不能把各章摘要重新排列。它要把多章产物接成一次完整工作，再换一个陌生场景迁移。

阶段总结完成五项工作。

1. 解释各章之间的依赖关系。
2. 提炼少量反复出现的判断边界。
3. 使用新场景完成整阶段迁移。
4. 给出基础掌握与熟练掌握标准。
5. 说明进入下一阶段还缺什么。

阶段总结完成后，还要逐章审阅。审阅需要检查每章是否完成自己的职责，相邻内容是否重复，产物能否接上，专业术语是否在正确位置出现。

### 第七步完成板块总结

全部阶段完成以后撰写板块总结。它放在证据账本下方，帮助读者从来源进入完整课程复盘。

板块总结不复述四十篇内容。它应当回答下面的问题。

- 整个领域反复处理的核心问题是什么。
- 各阶段怎样改变读者能够支持的结论。
- 四十章可以压缩成哪些可迁移判断。
- 用什么综合项目验收整条路线。
- 遇到新问题时应该返回哪一阶段。

## 五、单篇学习文章撰写 SOP

详细写作规则继续使用[学习文章改写 SOP](./学习文章改写SOP.md)。下面是从来源到发布的执行顺序。

### 第一步建立本章教学合同

动笔前写清一项可观察目标、必要前置、正文范围、要教的术语、一个例子、一个应用产物、常见错误和完成标准。再补上就绪检查、预计投入、反馈入口和替代路线。这些内容是设计约束，可以分散呈现在阶段页、学习图和正文中，不得机械生成相同的开头卡片。

本章目标应当描述读者能作出的判断。例如读者能够判断一组特征是否越过预测时点。避免使用“了解”“熟悉”“掌握”这类无法验收的词。

### 第二步准备本章来源包

从知识库选出真正需要的少量来源。来源包至少包含一份稳定机制材料、一份边界或反例材料。近期主题再加入新研究、标准或官方资料。

作者先记录四项内容。

| 项目 | 要回答的问题 |
|---|---|
| 稳定机制 | 哪条关系得到教材或经典研究支持 |
| 关键边界 | 哪些条件失效时结论不能使用 |
| 可教学材料 | 哪个数字、实验、流程或反例最容易让读者理解 |
| 不可推出 | 来源没有证明什么 |

来源负责校准文章，不能代替作者组织教学。正文不写内部来源审计、下载状态和阅读账本路径。

### 第三步设计轻量学习图

文章开头保留一张简单的学习图，回答四件事。

1. 本章是什么。
2. 为什么值得学。
3. 学完以后怎样做。
4. 正文会真正使用哪些专业术语。

框中写核心知识点，不写大段正文，也不把术语逐项解释。学习图提供阅读方向，正文脱离它以后仍应是一篇完整文章。

### 第四步选择正文推进方式

文章结构根据知识关系选择。常见推进方式包括下面这些。

| 知识关系 | 合适的推进方式 |
|---|---|
| 信息随时间产生 | 跟随一个对象走完时间线 |
| 多个动作承担不同后果 | 从一次具体选择开始计算 |
| 结论依赖实验边界 | 跟随实验从设计走到评价 |
| 系统在压力下失效 | 沿事故时间线调查 |
| 多个方案需要取舍 | 在同一组约束下比较 |
| 能力逐步增加 | 让同一项目连续遇到新问题 |
| 规则由多个条件组成 | 从一个反例逐步补齐条件 |

一篇文章通常选择一到两种推进方式。小标题在正文关系写顺以后再取，只标记真正的认知转折。不同部分允许长短不一。

禁止让每篇文章重复“定义、三种方法、核心公式、两个论文、案例、边界、AI 协作、总结”的固定目录。栏目齐全会制造报告感，也会让知识被平均切碎。

### 第五步让术语在需要时出现

先让读者看见现象，再给这个现象命名。术语首次出现时，用当前案例中的对象解释它。后文要让读者用这个术语完成一次判断。

每个术语都要通过三项检查。

- 它解决了前文哪个表达困难。
- 读者能否在案例里找到对应对象。
- 后文是否用它改变了决定。

只负责显示专业程度的术语应当删除。术语密度来自关系清楚，不来自括号里的英文数量。

### 第六步安排公式、图、表和代码

公式只在能够压缩读者已经走过的推理时出现。公式前先给数值、流程或几何直觉，随后解释变量、变化方向和失效条件。

图用于因果、时序、层级、分叉和多对象关系。表用于同字段比较。代码用于可执行步骤或精确流程。视觉内容必须增加关系，不能把正文再复制一次。

每 800 至 1500 字符应当出现一次真正承载信息的材料，例如算例、关系图、比较表、代码、案例或决策产物。这个范围用于发现水文，不要求机械插入组件。

### 第七步让段落沿读者问题推进

一段完成一件事。下一段接住读者刚产生的问题，或接住上一段刚出现的对象。每个新段至少增加新事实、新动作、新区别、新后果或一项会改变决定的边界。

以下内容通常需要删除。

- 把上一段换一种说法再写一次。
- 连续解释名词，却不让读者使用。
- 大段搬运论文措辞，再由作者解释一遍。
- 为了显得全面，罗列与当前决定无关的知识。
- 每个小标题都重复案例、公式、边界和总结。
- 在章节末尾解释这篇文章怎样使用原稿。

技术文章仍然要像一个懂行的人在给聪明新手讲事。句子先交代谁做了什么，再补条件。专业性来自结构化判断、边界和可执行建议，不依赖复杂公式。

### 第八步完成学习检验

每章至少交付一个可审阅产物。产物可以是问题卡、时间图、实验协议、比较记录、压力矩阵或事故复盘。

随堂检验只检查一个关键误区。应用练习要求读者使用本章概念完成产物。熟练练习更换场景或条件，检查读者能否迁移和指出边界。

章节结尾只处理交接。说明本章产物暴露了什么新问题，下一章为什么从那里开始。不要重新摘要全文，也不要提前讲完下一章。

### 第九步满足正式章技术合同

Learning 007 当前正式章至少满足这些机器可检查条件。

- 正文不少于 4800 字符，机制与实战章通常以 6000 至 12000 字符为目标。
- 二级标题保持在 4 至 15 个之间，标题签名不能与其他文章重复。
- 包含 `KnowledgeFlow`、随堂检验、`Quiz`、参考资料和 `EvidenceTracker`。
- 没有 `draft-status`。
- 参考资料至少包含两份真正相关来源，正式章通常保留四份关键来源。
- 没有重复长段落、固定报告栏目和来源审计话术。
- 内部链接有效，页面能够完成生产构建。

最低字数防止明显过薄，不能保证质量。删去三分之一后判断和产物没有变化，原稿仍有重复解释。

## 六、逐级 review 与放行 SOP

整条流程使用下面的状态机。状态只由交付物和用户确认改变，不能因为搜索完成、脚本运行成功或作者自评通过而自动前进。

```text
意图待确认
  → 意图已确认
  → 目录待审
  → 目录已确认
  → 样稿待审
  → 样稿已确认
  → 小批次补全
  → 阶段通过
  → 全领域通过
```

### 第一关意图与范围

提交意图对齐卡和建设合同。用户确认建设对象、领域边界、来源标准、内容标准、样稿对象与本轮边界以后，才能检索目录。

### 第二关教材与论文目录

提交教材清单、论文清单、覆盖矩阵与缺口说明。用户确认选材没有漂移、来源可读、数量与模块覆盖达标以后，才能正式阅读并写样稿。

### 第三关一篇完整样稿

先选一本教材综述或一篇正式学习文章完成试写，直到读者确认故事、结构、专业密度、格式和可读性都合适。样稿必须达到最终交付密度，不能用半成品要求用户批准未来质量。第一篇只能证明当前内容类型的质量基线成立，不能直接复制到其他内容。

### 第四关小批次与连续章节

样稿明确通过以后，教材综述按小批次补全并检查是否忠于各书结构；正式课程继续写三至四篇相邻文章，检查共同案例、相邻边界、产物接力和结构差异。小批次通过人工审阅，才允许扩大范围。

### 第五关一个阶段

完成阶段剩余文章和阶段总结。逐章检查章节职责、来源、术语、产物和交接，再用陌生场景验证整阶段迁移。

### 第六关整个领域

五个阶段完成后做交叉复核。检查前置是否闭合、术语是否前后一致、章节是否重复、阶段出口是否覆盖板块出口。最后撰写板块总结。

### 每篇文章的五轮审稿

第一轮只看主线。用五句话复述全文，五句话应当组成一条连续推理。

第二轮只看分工。说明本章从上一章接过什么，又给下一章留下什么。

第三轮只看读者负担。检查术语首次出现、代词、长句主语、公式前的直觉和图表解释。

第四轮只看知识价值。读者能否提炼结构化判断，能否完成新情境应用，是否知道何时不用。

第五轮检查来源、组件、链接、构建、侧栏、移动端和页面是否 404。自动检查只能发现形式问题，不能替代前四轮。

### 阶段 review 的逐章记录

每完成一个阶段，维护一张简短记录。

| 检查项 | 通过标准 |
|---|---|
| 章节职责 | 每章解决独立问题 |
| 相邻衔接 | 上一章产物成为下一章输入 |
| 结构差异 | 小标题和推进方式由主题决定 |
| 知识密度 | 每个关键概念都参与判断 |
| 可读性 | 新手无需先读论文即可跟随 |
| 证据边界 | 来源支持范围与正文结论一致 |
| 学习产物 | 读者能提交可检查成果 |
| 阶段迁移 | 新场景能够复用整套方法 |

发现问题后先修当前阶段，不带着已知缺陷批量生成后续页面。

## 七、工程实现与维护 SOP

### 内容与生成器的边界

生成器可以创建路线、索引、草稿和重复性元数据。人工通过的正式文章必须优先保留。生成流程发现现有页面包含正式章组件且没有草稿标识时，不得用模板重新覆盖。

手写内容和生成数据需要单一事实源。课程元数据放在领域 curriculum 文件，公开资源目录放在结构化 JSON，正式文章放在文档目录，原稿阅读账本单独保存。不要在多个脚本中复制同一章节标题和链接。

### 每次提交前的检查

```bash
npm run check:content
npm run check:links
npm run check:sources
npm run kb:validate
npm run build
```

构建后在浏览器至少检查领域总览、证据账本、板块总结、最新阶段总结和该阶段首尾两章。确认标题、学习图、侧栏层级、证据组件和内部跳转正常。

### 发布顺序

```text
来源或课程变更
  → 结构化校验
  → 内容与语言检查
  → 生产构建
  → 本地浏览器验收
  → 查看差异与临时文件
  → 提交
  → 获取远端状态
  → 推送
  → 核对本地与远端提交 SHA
```

临时截图、抓取缓存和 PDF 渲染文件不进入正式提交。删除它们也需要先确认是否属于用户材料。

### 更新触发器

遇到下面情况时启动增量维护。

- 权威教材出现新版并改变章节结构或结论。
- 近三年独立研究改变模型能力边界。
- 标准、法规、软件默认值或许可证改变。
- 正文引用的全文 URL 失效或转为登录访问。
- 学习者反复在同一前置卡住。
- 阶段项目暴露当前路线缺少必要主题。
- 生产事故或新案例改变已有边界。

更新时保留旧结论、变更日期和修改原因。新来源只影响一两个节点时做局部更新，不重写整个领域。

## 八、这次工作确认的常见失败模式

### 先搜一百篇，再想学科结构

结果会有很多链接，模块覆盖仍然随机。正确顺序是先定来源地图，再按缺口搜索。

### 只有书名和链接，就声称参考了原稿

元数据只能证明来源存在。正式引用需要具体阅读范围、采用观点和不可外推边界。

### 每篇套同一套完整栏目

页面看起来很齐，知识被切成报告。正文应当沿时间、实验、选择、故障或比较关系推进。

### 直接搬论文和公式

作者已经知道上下文，读者没有。论文负责校准结论，文章要重新建立问题、例子和解释顺序。

### 用更多术语补专业性

读者只能得到一排名词。真正的专业性表现为知道要检查什么、为什么、怎样做、代价是什么、哪种情况会失败。

### 把阶段总结写成章节摘要

读者仍然看不到多章怎样协作。阶段总结需要整合产物并换场景迁移。

### 一篇通过后立即批量改写

单篇无法暴露相邻重复和阶段断裂。至少经过单篇、连续章节和阶段总结三道人工放行。

### 未对齐意图就开始检索

作者会用自己熟悉的学科边界替代用户真正想建的模块。先提交意图对齐卡；边界、来源标准和交付类型没有确认，不进入检索。

### 目录未确认就开始写综述

一旦选材漂移，后续阅读和长文都会成为高成本返工。教材与论文目录必须先独立验收，目录通过前不写批量正文。

### 把样稿当成批量模板

样稿确认的是质量、语言和判断原则，不是所有文章的小标题。每本教材和每个学习主题仍需按照自身知识关系组织。

### 把构建成功当成内容完成

构建只证明页面语法和依赖能够运行。文章逻辑、读者负担、知识价值和迁移能力仍需人工 review。

### 自动生成再次覆盖正式文章

生成器必须识别正式状态并保留内容。维护脚本本身也要进入验收范围。

## 九、最终验收清单

### 知识库

- [ ] 意图对齐卡已经由用户明确确认。
- [ ] 领域边界和模块已经定义。
- [ ] 至少十本权威教材拥有可直接阅读的正文 URL。
- [ ] 至少一百篇核心论文覆盖所有主要模块。
- [ ] 来源记录具有稳定 ID、版本、入选理由和核验日期。
- [ ] URL 可用状态与实际阅读状态分开。
- [ ] 每本教材拥有足够密度且结构不同的综述。
- [ ] 证据账本记录支持、限制、冲突和更新触发器。
- [ ] 教材与论文目录已经独立提交并通过人工审阅。
- [ ] 一篇完整教材综述样稿已经达到最终标准并通过人工审阅。
- [ ] 其余综述只在样稿确认后分批补全。

### 领域课程

- [ ] 约四十个独立主题来自能力依赖，没有使用十乘四拆分。
- [ ] 每个阶段拥有出口、前置、产物、掌握证据和后续边界。
- [ ] 每章只解决一个关键判断。
- [ ] 相邻章节拥有明确交接合同。
- [ ] 每个阶段都有阶段总结和新场景迁移。
- [ ] 全部阶段完成后有板块总结，并位于证据账本下方。

### 单篇文章

- [ ] 开头能够回答是什么、为什么、怎么做和本章术语。
- [ ] 正文主线由主题自己的知识关系决定。
- [ ] 术语在读者需要时出现，并参与后续判断。
- [ ] 公式、图、表和代码确实承担关系。
- [ ] 来源已经读过，正文没有变成论文摘要。
- [ ] 读者能完成一个可审阅产物。
- [ ] 文章写清适用条件、失败边界和下一章交接。
- [ ] 正文、语言、来源、链接和构建检查通过。

### 全领域放行

- [ ] 四十篇正文逐章 review 无遗漏。
- [ ] 五个阶段分别完成 review。
- [ ] 章节标题、结构和长段落没有批量重复。
- [ ] 综合项目能够贯穿问题、数据、模型、可信和生产。
- [ ] 生成器不会覆盖正式内容。
- [ ] 本地浏览器完成首尾章节、阶段总结和板块总结验收。
- [ ] 远端提交与本地验收版本一致。

## 十、下一领域的推荐执行节奏

第一轮只做意图对齐。提交建设对象、领域边界、读者、内容标准、来源标准、样稿对象、验收基准和本轮边界；用户确认以前不开始检索。

第二轮完成来源地图，检索并核验教材与论文，提交教材目录、论文目录、覆盖矩阵和缺口说明；用户确认以前不写综述。

第三轮只完成一篇有代表性的教材综述或学习文章样稿。样稿直接按最终密度和格式撰写，反复修改到用户明确确认。

第四轮把已确认样稿沉淀为内容原则和验收基线，再小批次补全同类内容。原则可以复用，正文结构不得刻板复制。

第五轮设计阶段出口和独立学习主题，只激活最前面三至五个节点。完成第一篇正式学习文章并再次经过样稿审阅，再继续相邻三篇。

后续每次只推进一个阶段。阶段通过后再扩大范围。全部阶段完成，撰写板块总结，运行全量检查，并在用户明确要求的范围内完成浏览器验收、提交或远端同步。

这套节奏看起来比批量生成慢，却能减少返工。机器学习板块的大量时间用在纠正来源没读、章节同构、术语堆叠、文章不连贯和阶段没有出口。把这些问题提前列入放行条件，下一个领域可以复用判断过程，同时保留该领域自己的知识结构与叙述方式。
