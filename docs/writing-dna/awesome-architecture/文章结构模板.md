# Awesome Architecture 文章结构模板

## 稳定的是学习闭环，不是固定目录

40 篇全部有本章小结与随堂检验，37 篇使用文本关系图，31 篇使用表格；但正文标题会随主题改变。共同骨架是：

```text
一句话点题（指出冲突和本章承诺）
→ 说明它处在整套课程的哪一段
→ 用误解、事故、任务或两难进入问题
→ 建立一条核心机制/决策主线
→ 用图、表、代码、算例或案例让关系可见
→ 给出失败代价、反例和触发条件
→ 让读者做迁移判断
→ 小结并自然引出下一章
```

这条链可以调序、合并，不能被复制成八个统一标题。

## 模板 A：概念启蒙型

适合领域开篇和容易被术语吓退的章节。

```text
常见误解/时代冲突
→ A 与 B 的具体对照故事
→ 用三条以内特征给出精确定义
→ 画出成长路径或因果图
→ 真实案例证明误判的代价
→ 让读者判断一个新情境
```

关键是“先让读者发现原来的理解不够”，而不是先铺百科定义。

## 模板 B：原理深挖型

适合损失函数、优化、注意力、控制、概率与动力学。

```text
表面现象
→ 真正控制现象的变量
→ 最小数值例子或文本图
→ 公式与变量逐项解释
→ 改变一个变量观察结果
→ 反例/失效条件
→ 论文或实验校准边界
```

公式必须回答“为什么需要它、各项在控制什么、假设破裂会怎样”，不能独立陈列。

## 模板 C：连续案例实战型

参考 18—22 的做法：同一个 AI 客服连续经历读图、从零设计、规模演进、迁移拆分和 Agent 化。

```text
明确本章只练一件事
→ 继承上一章系统状态
→ 分步做出决策/产物
→ 每一步写退路、指标和停止条件
→ 下一章让同一系统遇到更难的问题
```

六个新领域都应拥有一条贯穿 4—6 章的主案例，避免每章换一个没有上下文的玩具例子。

## 模板 D：决策与选型型

参考 27—34，不做工具排行榜。

```text
指出“先问工具名”是错误根节点
→ 定义 4—6 把判断尺子
→ 候选方案按同一维度比较
→ 给出阶段/瓶颈触发信号
→ 写一条带代价、复审条件、退出路线的决策记录
→ 用总决策树收束整组章节
```

必须保留“不引入新技术”和“沿用简单基线”两个候选。

## 模板 E：组织与演进型

参考 35—40。

```text
局部效率为何没有变成系统能力
→ 给出可操作定义/公式
→ 拆成角色、上下文、流程、治理等层次
→ 按风险或成熟度分级
→ 用瓶颈作为升级触发信号
→ 给出从小试点到平台化的路线
```

## 章节组的组织方法

每个约 40 章的领域至少分成六段：入门心智、核心工具、机制深水区、连续实战、决策与工程、前沿与治理。章节之间必须存在“上一章交付什么，下一章在它上面增加什么困难”的关系。目录不是 40 个并列关键词。
