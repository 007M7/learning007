## 先澄清第一阶段交来的模型边界

贯穿案例仍是同一个可引用政策知识助手。第一阶段验收的 `E-small` 是检索与支持验证编码器：它帮助找候选段落，并判断段落对问题是支持、矛盾还是信息不足。它不是自回归生成器，不能因为本章谈“后训练”就把编码器悄悄写成会逐 Token 回答的模型。

为了生成“答案、引用、动作”三字段，系统另有一个待审的小型 decoder `G-base`。本章保持 `E-small`、政策索引和支持阈值冻结，只审理 `G-base` 是否需要行为适配。输入是用户问题与允许引用的证据，输出合同如下：

```json
{
  "answer": "无法从当前证据确认，请转人工复核。",
  "citations": [],
  "action": "abstain"
}
```

`answer` 必须被 `citations` 中的生效条款支持；证据不足、版本冲突或涉及未授权个案时，`action` 必须是 `abstain`。最新政策仍留在版本化检索层，而不是被“记进”权重。若 `E-small` 没召回正确条款，本章的生成器训练也无权假装修好了上游。

这项边界带来第一条拒绝分支：**若主要错误来自旧索引、错误版本、召回缺失或证据本身不完整，停止微调，退回数据与 RAG。**只有在正确证据已经进入上下文，而模型仍反复破坏稳定输出合同、忽略明确的拒答规则或生成固定类型的无依据补充时，参数适配才成为候选。

## 在第一次训练前冻结审理规则

任务不能写成“回答得更好”。我们先把一次成功定义为四个同时成立的条件：引用来自允许的当前版本；回答中的可核事实都能定位到引用；JSON schema 可解析；该拒答时确实拒答。另设切片门禁，至少覆盖否定条款、同主题异版本、表格转写、证据不足和越权个案。

数据分成四个角色，不能训练完再解释。

| 数据角色 | 谁可以看 | 用途 | 禁止事项 |
|---|---|---|---|
| `train` | 训练人员 | SFT、LoRA 或偏好对 | 不得含测试答案、未来版本和无许可对话 |
| `dev` | 训练人员 | Prompt、rank、学习率、早停 | 不得反复选择后冒充独立结果 |
| `test_sealed` | 独立评测脚本/评审者 | 候选配置锁定后一次主评测 | 不回流 Prompt、检索规则或训练 |
| `shadow_future` | 发布负责人 | 新日期、新模板与漂移检查 | 不用于当前版本门槛调参 |

切分单位是用户、政策文档族和版本，而不是随机句子。2024 与 2025 同一制度的近重复段落若分到训练和测试，会让模型靠模板记忆得分。每条样本至少记录 `sample_id`、原始来源、许可/隐私状态、文档族、有效日期、标注人、标注指南版本、生成或人工来源、去重簇和目标 split；每次导出保存哈希。

“测试题能从政策库检索到答案”不必然是泄漏，因为检索现行政策正是产品能力。真正越界的是：把测试专用参考答案或评分解释放进索引；用测试错误改 Prompt 后仍称它为独立测试；让未来版本元数据暗示标签；把模型生成的测试回答回灌训练。独立性保护的是决策过程，不是禁止系统读取其本来就有权读取的知识。

在封存前还要写门禁与统计方法。本章示例门禁为：任务成功率不低于 0.90、无依据回答接受率不高于 0.04、schema 通过率不低于 0.98，且每个高风险切片都有最低要求。真实项目应按错误代价和样本量给出置信区间；600 条上的 1 个错误与 20 条上的 1 个错误意义不同。门禁在看结果后改变，就产生了新的开发集，必须另留测试。

## 四名候选在同一记分牌上竞争

比较不是为了证明最复杂方案赢，而是寻找满足门禁的最小可维护系统。

1. **Base：**`G-base` 只接任务输入与最小指令，显示未经工程处理的能力边界。
2. **Prompt：**增加明确 schema、正反例、引用和拒答规则，不改权重。
3. **RAG：**在同一 Prompt 前加入由冻结 `E-small` 找到、带版本的证据；事实更新可撤销。
4. **PEFT：**保持同一 RAG 输入，只给 `G-base` 加小型可训练 adapter，目标是剩余的稳定行为错误。

四者共享 tokenizer revision、解码参数、最大输入、测试集与评分器。RAG 天然拥有外部证据，这不是“不公平”，因为产品决策本来就在比较完整方案。若要归因 adapter 增益，则用嵌套消融：`RAG + 同一 Prompt + base` 对 `RAG + 同一 Prompt + adapter`，一次只改变 adapter。不要给偏爱的候选更多上下文或专属人工修正。

下面是**教学用假设结果**，只示范判决逻辑，不是仓库模型的实测数据，也不得被引用成性能承诺。

| 候选 | 任务成功 | 无依据接受 | schema 通过 | 决定 |
|---|---:|---:|---:|---|
| Base | 0.61 | 0.21 | 0.87 | 失败；缺证据且合同不稳 |
| Prompt | 0.76 | 0.13 | 0.96 | 失败；规则改善但事实仍缺 |
| Prompt + RAG | 0.887 | 0.058 | 0.973 | 接近但未越过三项门禁 |
| Prompt + RAG + LoRA | 0.917 | 0.032 | 0.992 | 候选进入 canary，仍需区间与回归 |

如果 RAG 已经满足门禁，就保留 RAG，拒绝 LoRA；0.917 也不自动证明第四行值得上线。评审还要看配对样本中改对了什么、哪些原本正确的样本被改错、子组下界、标注分歧、训练与长期维护成本。若增益只来自更严格 schema，优先尝试约束解码；若增益只出现在训练模板的近重复上，按泄漏处理。

## LoRA 变小的是可训练增量，不是全部风险

设冻结线性层为 $W_0\in\mathbb{R}^{d_{out}\times d_{in}}$。LoRA 不直接更新 $W_0$，而是学习

$$
W'=W_0+\Delta W,
\qquad
\Delta W=\frac{\alpha}{r}BA,
$$

其中 $A\in\mathbb{R}^{r\times d_{in}}$、$B\in\mathbb{R}^{d_{out}\times r}$，所以 $\operatorname{rank}(BA)\le r$。当一个方阵层的输入、输出维度都是 768，`r=8` 时，低秩两矩阵有 `8×768 + 768×8 = 12,288` 个参数，而原矩阵有 `589,824` 个，比例约 2.08%。这只是**一个目标层**的参数比，不是整个训练作业的显存比；前向 activation、反向传播、被选模块、精度、优化器与量化方式仍要实测。

下面的 NumPy 代码不训练语言模型，只验证低秩路径、形状和合并前后一致性。它没有证明 `r=2` 足够政策任务。

```python
import numpy as np

rng = np.random.default_rng(7)
d_in, d_out, rank, alpha = 5, 4, 2, 4.0
W0 = rng.normal(size=(d_out, d_in))       # 冻结
A = rng.normal(size=(rank, d_in))         # 可训练因子
B = rng.normal(size=(d_out, rank))        # 可训练因子
x = rng.normal(size=d_in)

delta = (alpha / rank) * (B @ A)
y_adapter = W0 @ x + (alpha / rank) * B @ (A @ x)
y_merged = (W0 + delta) @ x

assert delta.shape == W0.shape
assert np.linalg.matrix_rank(delta) <= rank
assert np.allclose(y_adapter, y_merged, atol=1e-12)

dense = 768 * 768
lora = 8 * (768 + 768)
print("rank(delta) =", np.linalg.matrix_rank(delta))
print("one-layer trainable ratio =", f"{lora / dense:.2%}")
print("merge max error =", np.max(np.abs(y_adapter - y_merged)))
```

LoRA 原论文在特定模型与任务中报告了参数和资源优势；这些数字不能外推到 `G-base`、中文政策数据或任意 PEFT 实现。目标模块可能是 attention 的 `q/v`，也可能扩到其他线性层；rank、缩放、dropout 和初始化都是要在 `dev` 上审理的配置。adapter 还必须绑定基础模型 commit、tokenizer 和注入模块名。基础模型升级后，即使张量形状仍能载入，也要视为新候选重跑评测。

## SFT 与偏好优化回答不同问题

监督微调（SFT）给定 `输入 → 合格目标输出`，适合学习稳定 schema、引用格式、拒答措辞和任务映射。它模仿示例，不保证示例中的事实正确；若把旧政策答案写入目标，模型会更稳定地复述旧事实。因此本案例的 SFT 目标只编码行为：如何依据当前上下文作答、怎样标引用、何时拒绝。动态政策来自 RAG。

偏好数据则为同一输入提供 `chosen` 与 `rejected`。DPO 使用冻结参考策略 $\pi_{ref}$，提升 chosen 相对 rejected 的对数概率差；其核心损失可写成

$$
-\log\sigma\!\left(\beta\left[
\log\frac{\pi_\theta(y_w|x)}{\pi_{ref}(y_w|x)}-
\log\frac{\pi_\theta(y_l|x)}{\pi_{ref}(y_l|x)}
\right]\right).
$$

这里的 $y_w$ 是 chosen，$y_l$ 是 rejected。优化的是标注政策下的**相对偏好**，不是一个事实真值探测器。DPO 论文在情感控制、摘要与单轮对话等设置中验证方法，不能由此推出它能修复政策引用、消除幻觉或天然安全。

本案例只有在下列条件同时成立时才让偏好优化进入试验：SFT 后仍存在难以写成唯一标准答案的稳定行为差异；标注者能依据同一 rubric 比较两份完整输出；chosen/rejected 不只是在长度、礼貌或模板上形成捷径；参考模型与 pair 生成版本被保存；事实正确性和拒答仍有独立硬门禁。若标注者经常把“语气更像人”选在“引用正确”之前，或 pair 来自同一个模型的未经复核自举，**拒绝 DPO，先修 rubric 与数据**。

InstructGPT 展示了示范数据、排序数据与反馈优化组成的一条具体流程，但其结果来自特定模型、标注过程和提示分布。它能帮助我们区分 SFT 与偏好信号，不能成为“后训练一定对任意用户更好”的证明。

## 把泄漏、回归和撤销写进训练计划

微调作业开始前创建 `adaptation-manifest`。至少包含：任务合同版本、train/dev/test 哈希、数据来源与删除请求映射、基础模型和 tokenizer revision、adapter 配置、随机种子、代码与环境、评测器版本、候选门禁、负责人和过期日期。原始逐样本输出要保留，不能只有汇总均值。

训练中监控 loss、梯度范数与 dev 指标是为了发现数值异常和过拟合，不是最终放行。每个 checkpoint 都跑小型哨兵集：正确证据、矛盾证据、空证据、恶意要求伪造引用、超长表格。训练 loss 下降但无依据接受率上升时立刻停止。若某条样本的来源许可撤回，应能从谱系找到受影响训练导出和 adapter；“参数里删不出来”正是减少不必要微调的理由之一。

评测时先锁定候选，再由独立脚本打开 `test_sealed`。除主任务外，必须比较 base 与 adapter 的回归：语言切片、长短输入、常见通用指令、拒答过度、引用 ID 原样保留、提示注入和空上下文。对随机生成至少固定可重放设置并重复采样；不要用一次漂亮输出代替分布。

发布不是覆盖 `G-base`。保留可切换路由：`base`、`adapter-canary`、`reject-to-human`。canary 先接低风险小流量，线上只记录获准的最小数据。以下任何一项触发回退：schema/支持/拒答门禁下降，adapter 与 base digest 不匹配，政策版本无法追踪，异常率或人工升级率越界，或服务端不再能稳定加载同一配置。回退要在演练中真的执行一次，并验证请求不再进入 adapter；文档里的“可回滚”不算证据。

## 完成一次可复核的适配审理

练习沿用政策助手，但可以用任意可本地运行的小 decoder 或用固定输出的模拟候选。目标是证明决策，不要求昂贵训练。

1. **最小复现：**运行上面的 LoRA 代码，保存标准输出；手算 768 维单层参数比例。再选 60—200 条按文档族切分的小样本，冻结任务合同与 `test_sealed` 哈希，依次运行 Base、Prompt、RAG。只有三者都没有越过预先门禁时才允许启动小 LoRA。
2. **变式：**第一次把错误集中在“缺少最新事实”，预测 RAG 应改善而 LoRA 不应成为事实库；第二次保持证据正确，把错误改成稳定 schema/拒答规则，观察 PEFT 是否产生配对增益。再把一个测试近重复偷偷放入训练，确认去重/谱系检查能报警。
3. **验证：**检查四候选共享相同评测输入和解码设置；从逐样本结果重算三项门禁与至少一个高风险切片；对 LoRA 验证 base digest、目标模块、可训练参数量和合并前后数值；让未参与训练的人在候选锁定后运行独立测试。
4. **反馈：**把错误归为召回、证据支持、事实生成、schema、拒答或评测器问题。召回错退回 RAG；动态事实错移出权重；只有稳定行为错才改 adapter。若区间重叠、样本不足或回归抵消收益，结论写“证据不足，保留简单基线”，而不是继续调到测试集变好。

提交六件可审阅产物：任务与门禁卡、数据谱系/切分清单、四候选逐样本结果、LoRA 配置与数值日志、adapter/release card、一次回退演练记录。评审者应能从这些材料回答“为何要改权重、改了什么、在哪些输入上成立、怎样撤销”。

## 本章小结：微调只有在简单基线失败且增益可归因时才值得采用

微调的前提是错误确实位于稳定行为层，且 Prompt、RAG 等较简单候选在同一门禁下仍未解决。本章用四候选记分牌区分动态事实与稳定行为，核对 LoRA 增量、SFT 与偏好信号，固定密封测试和回归切片，并把数据谱系、发布候选与真实回退演练绑在一起。点估计的小优势若缺少区间、回归和维护成本，不能为额外复杂度提供充分理由。

本章交出一份不可拆开的 release candidate，不以散落的 adapter 文件充数。它包含 `E-small` 与索引 revision、`G-base` digest、可选 adapter digest、tokenizer、Prompt 与 schema、sealed-eval 哈希、逐切片结果、允许动作、拒答路径和回退开关。若最终判决是不微调，`Prompt + RAG + G-base` 同样是合法候选。

下一章只接收通过独立评测并能回退的候选。它不会用更高 tokens/s 重新解释本章的正确性门禁，而要观察请求怎样经历排队、prefill 与 decode，KV cache 怎样限制并发，batching 和量化怎样改变尾延迟与输出。任何引擎、精度或批处理改变都视为新的系统版本，必须重放本章的支持、引用、schema 与拒答回归。

- Edward J. Hu 等，[LoRA: Low-Rank Adaptation of Large Language Models](https://arxiv.org/abs/2106.09685)，2021 年。用于冻结基础权重、训练低秩增量的原始方法；论文中的参数与显存收益属于其模型、任务和实现，不能直接外推到本案例。
- Hugging Face，[PEFT 官方文档](https://huggingface.co/docs/peft/index)，本课程核验于 2026-09-04。用于核对当前 adapter 配置、注入、量化集成与 checkpoint 机制；API 和支持的方法会变化，实践时锁定包版本。
