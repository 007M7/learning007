# 可选进阶

进阶内容保留在完整知识地图中，但默认不进入近期学习队列。

## 软件与系统工程进阶

| 方向 | 先修 | 什么时候值得学 | 产出证据 |
|---|---|---|---|
| 高级算法/数据结构 | SW04 | 搜索、调度、图关系或大规模数据成为瓶颈 | 基准＋复杂度/内存比较 |
| OS/编译器/高性能网络 | SW05—07 | 性能、运行时、安全隔离是产品核心 | profiler、系统调用/内存分析 |
| 分布式系统/共识 | SW06、11、13、Q13 | 多节点复制、一致性与故障域成为真实约束 | 故障模型、线性化/一致性测试 |
| 分布式存储/流处理 | 同上 | 数据量、吞吐、重放需求超过单库/普通队列 | 分区、重放、背压与恢复演练 |
| 微服务/Service Mesh | SW12—15、Q10—14 | 团队所有权、独立伸缩/合规需要物理隔离 | 服务边界 ADR、SLO、契约与故障隔离 |
| Event Sourcing/CQRS | SW10—13 | 审计、时态查询、重建状态价值大于复杂度 | 事件版本、投影重建/迁移测试 |

## AI应用与Agent进阶

| 方向 | 解锁信号 | 不应替代的基础 |
|---|---|---|
| 线性代数/概率/深度学习 | 要理解训练、优化、论文或模型评估 | 数据质量、任务定义与基线 |
| PyTorch/微调 | Prompt/RAG 不足且有稳定数据/指标 | 训练/验证隔离、版权隐私、回滚 |
| CUDA/量化/推理优化 | 自托管吞吐、显存、延迟决定成本 | 正确性评测、容量与可观测性 |
| GraphRAG | 问题真正依赖多跳实体关系 | 普通混合检索基线与分层评测 |
| 多 Agent | 角色并行/独立权限带来可测收益 | 单 Agent/工作流基线、预算、死锁/循环治理 |
| 自建推理集群 | 数据、成本或延迟明确排除托管服务 | 模型服务 SLO、安全更新、容量/故障恢复 |

## 明确暂不优先

为了“跟上趋势”而同时学多个前端框架、云厂商全家桶、所有数据库、Kubernetes 内核、大模型训练和多 Agent。先让一个真实系统具备契约、状态、测试、交付、观测和恢复，再用瓶颈选择进阶深度。

## 解锁条件

只有满足至少一个条件才进入近期队列：

1. 当前项目被该知识直接阻塞；
2. 目标岗位明确要求；
3. 必修核心已经有基本掌握证据；
4. 你明确接受延后主线交付的机会成本。

解锁后仍只把一个进阶节点放入近期队列，并先写可测问题：例如“p95 在 200 并发超过 2 秒，profile 显示 JSON 序列化占 40%”，而不是“我想学高性能”。
