# 六个端到端案例

案例不是复制代码，而是观察**需求怎样变成约束，约束怎样改变架构，架构怎样产生测试与运行证据**。

| 案例 | 难度 | 重点领域 | 最重要的取舍 |
|---|---|---|---|
| [01 · 个人任务板](/cases/01-task-board) | 入门 | 前后端、API、SQL | 简单 CRUD 与明确状态 |
| [02 · 多租户任务运行器](/cases/02-task-runner) | 核心 | 并发、队列、交付 | 同步请求与耐久任务 |
| [03 · 可引用知识助手](/cases/03-rag-assistant) | 核心 | RAG、权限、评测 | 召回质量与证据/成本 |
| [04 · 有审批的工具 Agent](/cases/04-tool-agent) | 进阶 | 工具、MCP、Runtime | 自主性与可控副作用 |
| [05 · AI 代码审查流水线](/cases/05-code-review) | 进阶 | Git、测试、AI Eval | 建议速度与误报/安全 |
| [06 · 学习证据系统](/cases/06-learning-system) | 综合 | 学习、数据、隐私 | 进度记录与真实掌握 |

## 每个案例都回答八个问题

用户与核心旅程、业务不变量、系统边界、数据模型、接口契约、失败与恢复、质量证据、演进触发器。技术栈可替换，决策证据不可省略。

::: info 使用方式
先只看需求和约束，自己画图；再展开方案对照。最后改变一个约束（流量、团队、隐私、延迟或成本），写一份新的 ADR。
:::
