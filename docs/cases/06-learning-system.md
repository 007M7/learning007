# 案例 06 · 学习证据系统

<div class="lesson-meta"><span>综合反思案例</span><span>三大领域</span><span>structured-learning</span></div>

## 需求与学习契约

学习者浏览知识地图，只保持 3—5 个近期节点；记录解释、练习、应用和跨日期复习。系统绝不能因为点了“已读”就宣称掌握，也不能伪造评估历史。基础掌握需要解释＋应用＋近期平均至少 7/10；熟练还需变化/边界、跨日期证据和 8.5/10。

## 数据分层

```text
Knowledge：节点、前置、来源、版本
Course：路径、任务、练习、rubric
Learner：活动队列、证据、作答、复习
Views：地图、章节、项目、复盘（只读取前三层）
```

本站静态第一版把知识和课程放在 Git；浏览器 localStorage 只保存设备本地自我记录，不同步、不自动判定掌握。若升级为服务端产品，证据追加写入，评估保留 rubric/版本/评分来源；学习者可导出和删除。

## 架构决策

课程侧栏从单一 `curriculum.ts` 生成，避免数量漂移。来源目录记录组织、版本/发布日期、访问日、适用节点和时效策略。可视化地图是导航，不是能力证明；项目案例跨域整合。

## 质量与隐私

构建检查所有内部链接；每个节点必须有目标、前置、练习、误区、完成标准和来源。学习数据最小化，不从停留时长推断能力；AI 教师提出建议但要区分观察、推断和用户确认。

## 你的变化任务

把本站升级为多设备学习系统：设计账号、离线合并、证据附件、评估版本、删除/导出、提醒同意与隐私；写 ADR 说明为何不自动宣称掌握。
