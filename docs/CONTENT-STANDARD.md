# Learning 007 章节完整度标准

本标准用于防止课程退化为术语表。完成关键词覆盖以后，章节还要让非科班学习者从问题进入机制，再把判断带回真实项目。

## 每章必须形成一条学习链

1. **进入问题。** 说明本章解决什么真实问题，以及不理解它会付出什么代价。
2. **纠正直觉。** 指出最容易犯的错误，用大白话建立新的理解框架。
3. **机制展开。** 每个知识节点至少包含因果解释、数据或控制流和失败边界。
4. **看见证据。** 案例、实验、论文或标准必须支撑一个具体判断。
5. **亲手应用。** 从跟做、变式到迁移，产出可以检查的作品。
6. **认识边界。** 说明何时失败、如何观测以及何时不该使用。
7. **检验与小结。** 至少一个迁移题，小结要能脱离正文独立复述。

这七步描述教学功能。正文目录仍要根据 [教学文章写作指南](./TEACHING-WRITING-GUIDE) 选择概念启蒙、原理深挖、跟做实战、决策选型、案例复盘或前沿综合文体。

## 每章还要承担一份学习合同

读者在进入正文前，应能判断这章是否适合自己。作者需要明确目标读者、可验证学习结果、硬先修、就绪检查、预计投入、反馈方式和替代路线。这些信息可以融入学习图、阶段页或正文，不要求使用固定卡片。

- “需要一定基础”必须改成可观察的先修能力。
- “难度较高”必须拆成概念、数学、编码、环境、英文与时间成本。
- “完成练习”必须说明产物、验证方法和反馈入口。
- 外部资源必须记录用途、版本、访问状态和最后核验日。
- 一条主路线必须允许补桥、最小完成路径或停止条件，不能默认所有读者全量完成。

## 内容密度底线

- 核心章节建议 4,500～10,000 个字符；进阶章节建议 5,000～14,000 个字符；
- 长度只作预警。重复定义、堆链接、堆代码不能换算成完整度；
- 一章可以标注“深水区，初读可跳过”，但主线不能依赖被跳过的内容；
- 一个章节可覆盖 2～4 个紧密相关节点；跨度过大必须拆章；
- 所有数字案例必须说明它是示例、实测还是外部来源，不能把假设写成行业事实。

领域深研与 Agent 前沿采用更高的自动预警线，但不再以二级标题数量衡量深度。领域文章至少 4,200 字符，并必须出现主题特有的概念解释、真实证据、应用任务、失败边界和掌握证据。自动检查还会拦截重复长段落、批量复用的标题签名和旧研究报告模板。

## 写作语气

先用大白话建立直觉，再给精确定义；先讲为什么，再讲怎么做。每节至少回答以下问题中的三个。它解决什么，怎样运行，代价是什么，何时失败，怎样验证，何时不该用。

本标准参考了 [Awesome Architecture](https://github.com/study8677/awesome-architecture) 的教程、地图与案例组织方式，也参考了 [CSDIY](https://github.com/PKUFlyingPig/cs-self-learning) 对先修、作业价值、真实成本、替代路线和资源可执行性的处理。所有课程拆分、学习证据、案例和文字仍按 Learning 007 的各领域目标独立编写。逐篇复盘结论见 [教学文章写作指南](./TEACHING-WRITING-GUIDE)。
