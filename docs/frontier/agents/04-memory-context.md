# 04 · 记忆先保留来源，再决定能不能想起

这章继续使用订单 1042，但时间跨度从一次运行拉到数周。硬先修是 [第 3 章](/frontier/agents/03-tools-protocols) 的工具合同，你需要能解释为什么 `refunds.commit` 即使收到完整参数也要重新检查批准。本章共 7 个标准回合：记忆机制、数据结构与环境准备 2 回合，跟做 1 回合，冲突/删除变式 1 回合，跨日任务迁移与交接 3 回合。可以使用 JSON 文件、SQLite 或内存表，向量数据库并非必需。反馈来自写入审批记录、召回清单、冲突 trace、删除证明和动作门的最终拒绝。没有真实删除能力时，不要保存敏感生产数据。

## 十二天把一条事实磨成了一张通行证

先还原时间线。第零天，客服主管查看订单 1042 的冲突证据，批准退回 399 元，批准记录绑定订单、金额、原支付方式和当天有效期。支付执行器验证记录后只提交一次。当天夜里，一个总结器读到完整 trace，写下一条长期记忆。

```text
客户 C77 的退款在主管批准后完成，金额 399 元。
```

这仍是一条有来源的历史事件。第二次压缩把它改成“客户 C77 有过小额退款批准”。第三次为了便于检索，又变成“客户 C77 五百元以下退款已获批准”。订单号、批准人、有效期和“有过”全消失了。

第十二天，客户为订单 1088 申请退款。检索器发现新金额 459 元，与旧摘要高度相似，于是把后一句放进 context。Agent 据此生成 `refunds.propose`，并把旧批准编号写进参数。若工具只检查“上下文里是否出现批准”，这笔新退款就会通过。攻击者没有注入提示，也没有偷 token；权限是在系统自己的记忆更新中被制造出来的。

这类现象在 2026-09-01 的预印本中被命名为 endogenous authorization laundering。作者用 EAL-Bench 测量记忆写入者是否虚构授权，以及错误记忆是否诱发下游执行者越权。在其五种写入模型、两种执行模型和采购、安全、金融任务设置里，增量更新对未经授权请求产生虚假权力的比例最高达到 50.2%，一旦错误权力存在，执行者在 98.6% 的试验中采取行动。数字来自特定实验组合，不能当作本项目事故率，也没有经过长期生产验证。它直接支持一个边界判断，持久记忆已经参与系统的有效授权面。

订单 1088 的正确结果是一条拒绝 trace。Agent 可以引用订单 1042 的历史，不能用它批准新订单。工具门从批准服务查询后发现主体和订单不匹配，拒绝提交，系统请求新的复核。记忆帮助解释客户经历，却没有获得创造权力的资格。

## 四个位置承担不同时间尺度

很多团队把聊天历史、向量库、摘要和模型上下文都叫 memory，随后用同一个 `top-k` 管理它们。先按系统作用拆开，存储产品放到后面选。

| 位置 | 订单案例里的内容 | 生命周期 | 主要风险 |
|---|---|---|---|
| working state | 当前订单、计划节点、已用预算、未决查询、工具回执 | 一次运行，可检查点恢复 | 旧版本继续驱动动作 |
| context | 本轮真正送入模型的状态、证据、规则引用和候选记忆 | 一次模型调用 | 关键约束被长文本挤掉 |
| episodic memory | 第零天发生过的读取、批准、提交与结果 | 跨运行的事件记录 | 事件被脱离当时范围解释 |
| semantic memory | 从多次事件提炼的稳定事实或偏好 | 跨运行，可修订和过期 | 推断被写成事实，偏好被写成权限 |

working state 是当前控制循环的工作台。它要带状态版本、动作结果和剩余预算，可以在崩溃后从检查点恢复。恢复时必须重新验证外部状态，不能假设检查点以后的世界没有变化。任务结束后，临时思路通常不值得永久保存，最终状态与必要证据才进入后续候选。

context 不是另一座仓库。它是某一时刻给模型看的投影。相同记忆库面对“解释上次退款”和“执行本次退款”应产生不同 context。前者可以展示历史经过，后者只应加入当前订单、现行政策和可验证批准引用。把全部历史塞进长上下文，只是绕过了选择责任。

episodic memory 保存发生过什么。适合的形式是追加事件或不可变对象，包括任务、时间、参与主体、输入证据、动作、结果和来源。它可以支持复盘与相似案例检索，却不自动形成一般规律。一次主管批准是一段 episode，不是客户属性。

semantic memory 保存经过提炼、预计跨任务仍成立的事实，例如用户明确选择中文沟通，或客户自己确认的收货偏好。它需要可撤销，也要记录由哪些事件支持。业务政策和授权最好仍由权威服务管理；semantic memory 可以保存一个带版本的引用，不能复制一段失去更新通道的规则文字充当现行政策。

这四个位置会互相传递内容，但传递不是复制。episode 进入语义层前要通过写入门，semantic 候选进入 context 前要通过召回门，context 生成动作前还要通过第三章的 action-commit boundary。每个边界都留下可检查决定。

## 写入门先问这条内容值不值得留下

退款运行结束后，系统会生成几十种内容。原始用户话语、物流响应、模型推理、复核决定、支付结果和客服回复不能全部永久保存。写入策略逐条判断用途、依据、敏感性、有效期与可更正性。

一条最小记忆记录可以这样表达。

```yaml
memory_id: mem-842
type: episodic
subject: customer/C77
claim: "order 1042 was refunded after one-time approval"
source_event_ids: [approval/ap-91, payment/tx-55]
writer: refund-memory-worker/v3
observed_at: 2026-08-20T11:42:00+08:00
valid_from: 2026-08-20T11:42:00+08:00
expires_at: 2026-11-18T00:00:00+08:00
scope: [support_history]
authority_class: informational
privacy: customer_restricted
confidence: 1.0
status: active
supersedes: []
```

`source_event_ids` 让评审者回到批准和支付记录，`scope` 限制用途，`authority_class` 明确它只能提供信息。`expires_at` 到达后，这条内容退出普通 context；历史事件是否继续为审计保留，由另一个明确用途和权限通道决定。

模型生成的摘要默认是派生内容，不能把自己的措辞当来源。若它写“客户有长期退款特权”，写入门沿来源链检查不到支持这个范围的事件，就拒绝 semantic 写入，保留失败审计。对用户偏好，写入门也要区分明确表达与系统推断。“请这次用短信通知”不能扩成永久偏好，“以后都发短信”才可能成为候选，还要有用户可查看和更改的入口。

来源充分仍不保证值得保存。身份证号可能出现在复核附件里，却不一定是后续退款所需属性。数据最小化要求系统只保存完成明确目的所必需的个人信息，并控制保留时间。NIST 800-63-4 的隐私说明把最小化、可管理性、修改、删除和选择性披露作为风险控制背景。它针对数字身份场景，不替代具体地区法律意见；本项目借用的是设计原则，并由组织的数据负责人确定法律与保留要求。

写入门的输出包含 `accept`、`reject`、`quarantine` 和 `needs_confirmation`。来源缺失进入隔离区，敏感且无用途直接拒绝，可能成为长期偏好的内容请求用户确认。只返回一段新摘要会丢掉为什么写、为什么没写的证据。

## 召回先找相关，再审查能否进入 context

订单 1088 到来时，检索器以客户、问题和当前状态寻找候选。关键词、BM25、dense embedding、图关系或时间索引都可以完成候选生成。候选排序回答“它可能有用吗”，没有回答“当前任务可以看吗”或“它能支持这个动作吗”。

把第一个问题记为 relevance，把后两个问题合并成 admissibility。记忆 $m$ 能进入本轮 context，至少满足

$$
E(m,q)=R(m,q) \land P_{read}(m,q) \land T(m) \land S(m,q) \land C(m)
$$

$R$ 表示与查询相关，$P_{read}$ 表示当前主体有读取权限，$T$ 表示仍在有效时间，$S$ 表示用途和主体范围匹配，$C$ 表示冲突状态允许使用。授权用途还要额外检查权威来源；普通相似度不参与放宽这个硬条件。

context composer 随后决定排列与预算。当前状态、未决约束和现行政策引用优先，历史 episode 只给必要片段，来源与时间跟随内容一起出现。若候选太多，系统宁可返回“历史记录过多，需缩小范围”，也不让一百条相似案例把当前订单版本挤出注意力。

组合完成后，再生成一份 context manifest。它记录本轮采用了哪些状态字段和记忆片段、各自为何进入、哪些候选被排除、使用了多少 token，以及哪一个事实允许哪一项判断。manifest 不要求保存隐藏推理，只保存输入选择和可公开的依赖关系。模型若回答“旧订单说明客户经常遇到物流问题”，评审者可以查到它引用了哪几个 episode；若没有足够事件支持“经常”，verifier 就把措辞降为一次历史，不让概括反过来成为新 semantic memory。

无答案也要在 context 政策里占一个位置。记忆库没找到培训记录时，系统只能说“在当前获准来源中未找到”，并附上查询范围与完整性。它不能补出“客户应该已经培训过”，也不能把空检索写成“培训未通过”。第一种是未知，第二种是明确否定，二者会触发不同工具路径。将未知结构化，可以减少后续摘要把缺失信息固化成错误事实。

context 还需要隔离用途。客服解释可以读取过去对话中的较多细节，退款资格判断只需要状态与证据，模型改写用户回复则不该看支付 token 或内部风险标签。同一个 Agent host 也要按当前子任务裁剪读取范围。权限过滤发生在数据进入 prompt 以前，不能把敏感字段交给模型以后再要求它忘掉。

Harness the Memory 在三个 backbone、四组 benchmark 和二十六项性能效率指标下比较多种记忆介质。其结果没有单一赢家，广召回能帮助长上下文事实问答，过量检索却可能让序列决策偏离行动关键状态；历史增长还会改变成本与脆弱性排序。它是 2026 年的新预印本，代码在论文页面声明待接收后开放，完整独立复现仍受限。这里采用其直接支持的结论，记忆介质需要按任务形态路由，不能用一次 QA 排名决定动作系统。

为了看清差别，可以向同一记忆库提出两个问题。用户问“我上次退款后来怎样了”，召回订单 1042 的 episode 合理。系统问“订单 1088 现在能否提交退款”，旧 episode 只能作为背景；当前批准服务的否定结果必须排在 context 前部，并在工具门再次校验。相关性相同，用途改变了可采纳程度。

## 冲突不靠最后写入者获胜

客户曾说“退款请回原银行卡”，后来又说“这一次退到平台余额”。若系统用后一条覆盖前一条，会把单次选择误当长期偏好；若永远保留前一条，又忽略当前明确意图。解决冲突需要比较主体、范围、时间和来源权威，不能只比较 `updated_at`。

先把每条 claim 写成带有效区间的断言。长期偏好可能作用于该客户以后所有订单，当前指令只作用于订单 1088。两者看似文本冲突，范围交集里当前订单指令更具体。执行后，单次指令随任务结束；长期偏好仍保持，除非用户明确修改。

同一范围内出现两个同权来源时，系统不应自行选最新。例如客户在网页资料中把通知方式改为邮件，同时在客服对话里说以后只发短信，而两个事件时间接近。记忆层把两条都标成 `conflicted`，context 告诉 Agent 需要澄清。澄清结果生成新事件，并用 `supersedes` 指向被替代记录。原记录保留必要审计，但不再用于普通决策。

不同权威来源发生冲突时，优先级也不能写成“公司总是高于用户”这种宽泛句子。用户能决定沟通偏好，公司政策能限制敏感附件发送，主管批准能授权某个退款提案。每类权力只在自己的字段和范围内比较。语义记忆没有资格覆盖当前政策服务，即使它更新时间更晚。

Mem0 把新信息与旧记忆比较后选择添加、更新、删除或不操作，并探索图结构来表达关系。在 LOCOMO 的论文设置里，它报告了相对 LLM judge、延迟和 token 成本的改进。贡献在于把抽取与整合做成显式操作；其数字依赖该数据集、模型、实现和 judge，不能证明这些操作已经解决授权、隐私或所有时间冲突。我们的写入门借用操作分类，同时增加来源、范围和权威检查。

## 遗忘是一条可验证的数据流

三个月后，客户撤回长期短信偏好并要求删除可选的客服个性化记忆。系统把主表一行标成删除，却忘了向量索引、滚动摘要和 prompt 缓存。下一次检索仍返回旧偏好，表面删除没有改变 Agent 行为。

遗忘至少有三种语义。过期让内容退出普通召回，但可按合法审计用途保留；撤销让一项偏好或授权引用立即失效；删除要求在确定范围内清理原始记录、派生摘要、embedding、图边、缓存和备份策略所覆盖的副本。不同语义要由不同事件触发，不能都实现成 `active=false`。

删除流程先建立影响清单。记录 `memory_id` 派生出的索引键、摘要版本和缓存标签，发出 tombstone，再让各存储返回完成回执。验收器用正常检索和越权检索各查一次，确认内容不可见；对必须保留的最小审计，只保存删除动作、时间和不可逆标识，不继续复制原敏感内容。备份的最终清理周期和法定义务由正式政策决定，并在用户界面说明，不能凭本章给出统一承诺。

遗忘也服务于正确性。临时物流故障、过期优惠和一次性批准若永久活跃，会持续污染决策。`expires_at` 到达后，召回门自动排除；若确需使用历史，调用方明确申请审计用途。时间过滤属于检索前的确定逻辑，不交给模型读完以后自行忽略。

## 一个评测要同时观察记得准与做得对

MemGPT 在 2023 年用虚拟上下文管理类比，让模型通过函数调用在有限 context 与外部存储间搬运内容，并在长文档和多会话聊天中验证设计。它把上下文管理提升为可观察动作，是本章的机制基础。操作系统类比不保证精确寻址、缓存一致性或正确替换，模型主动写入也可能漏记和误写，因此生产写入门仍需外部规则。

只测“上次金额是多少”会奖励高召回，却看不到旧批准是否诱发新动作。退款记忆实验要分两条任务线。事实线询问过去发生了什么，行动线要求根据当前状态选择读取、提案、拒绝或提交。两条线共享相同历史，分别报告有依据回答、正确未知、敏感泄露、冲突识别、安全成功和越权副作用。

构造六周事件流，其中包含四十条订单事件、十次后续更正、八条不应保存的敏感信息、六项到期偏好、四个一次性批准和十个没有答案的问题。比较完整历史、滚动摘要、稀疏或稠密 `top-k`、结构化事实表四种方案。固定模型、任务、context token 上限和随机种子，逐步增加历史长度。

故障注入放在生命周期各处。写入时删掉一个来源，把一次性批准改写成长效规则；召回时混入别的客户记录和已过期记忆；组合时把现行政策挤到窗口末尾；删除时让一个索引消费者不响应。每个故障都要有程序可见的期望结果，来源不足的授权记忆被隔离，跨主体候选被过滤，政策保持可见，删除未完成就展示部分失败并停止宣称完成。

最终产物包括记忆 schema、写入决策日志、召回候选与过滤原因、context 清单、冲突图、删除传播回执、行动状态差分和对照报告。做两项消融，一次移除 provenance 检查，一次把 admissibility 过滤改成纯相似度。若事实问答上升而越权动作也增加，报告必须保留这项交换，不能只公布最高 QA 分数。

再做一次恢复演练。运行层在生成 context 后崩溃，十分钟后从 working-state 检查点启动；这期间人工已经撤销批准。恢复程序先读取当前订单和批准版本，把旧 context 标成 stale，再重新召回。若它直接重放崩溃前的模型动作，说明系统把 context 当成了权威快照。产物中应保留旧 manifest、撤销事件和重新组合后的差异，评审者据此判断哪条信息让计划改变。

评测退出条件提前写好。任何跨主体泄露、过期授权通过或删除后正常召回都会让长期记忆退回只读沙箱。事实回答略有下降可以继续调检索，越权副作用不能用平均准确率抵消。若结构化事实表在行动任务上更稳，而 dense 检索只在历史问答上占优，可以按用途路由两种方案，无需选一个全局赢家。

## 三层练习

### 跟做

把订单 1042 的一次性批准写成一条 episode，再尝试生成“客户 C77 五百元以下可直接退款”的 semantic 候选。产物是一份记忆记录、一条写入门拒绝日志和订单 1088 的召回清单。验证候选因为来源不支持长期范围而被拒绝，旧 episode 可以回答历史问题，却不能通过新订单的批准检查。本段使用 1 个标准回合，反馈来自同伴沿 `source_event_ids` 反向复述授权范围。

### 变式

加入三条互相冲突的通知偏好，一条长期偏好、一条订单级选择和一条已过期客服推断。实现范围、来源与时间过滤，再执行一次用户删除请求。产物包括冲突关系图、最终 context、删除影响清单与检索前后截图或日志。验证当前订单采用更具体的明确选择，过期推断不进入 context，删除后主表和派生索引都无法正常召回。本段使用 1 个标准回合。

### 迁移

选择自己的跨日 Agent 任务，建立至少五十条事件和十二条行动测试。明确 working state、context、episodic 与 semantic 四个位置，为每条长期记录加入来源、用途、权限和有效期。注入错误摘要、跨主体召回、旧政策、未知答案和删除消费者超时。产物是一份 memory policy、可重放数据集、失败 trace、指标表和采用 ADR，必须出现一次因记忆不能提供权力而触发的正确拒绝。本段连同采用交接使用 3 个标准回合，评审者同时检查回答质量和最终环境状态。

## 本章小结

- working state 支撑当前控制循环，context 是每次调用的有限视图，episode 保存发生过的事件，semantic memory 保存可修订的跨任务事实。
- 写入先检查用途、来源、范围、敏感性和有效期，模型摘要只能是派生候选。
- 检索相关性只生成候选，读取权限、时效、主体、用途与冲突共同决定 admissibility。
- 一次性事件在反复压缩中可能被洗成长效权限，行动门必须回到权威系统核验。
- 冲突依靠范围、时间与来源处理，遗忘需要传播到索引、摘要和缓存并留下可验证回执。
- 记忆评测同时观察事实回答和后续行动，不能用 QA 提升掩盖越权副作用。
